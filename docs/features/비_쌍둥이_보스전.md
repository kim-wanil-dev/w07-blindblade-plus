### 비 내리는 쌍둥이 보스전

- 2026-10-22 목표·스폰 분리: `RainyStageController.Required Kills`는 보스 등장 처치 목표만 설정한다. 고정 시간표를 제거하고 `DefenseDirector`의 `DefenseEnemySpawner`에서 총 생성 수·시작 스폰율·증가량을 설정한다. 정식 씬의 목표와 총 생성 상한은 각각 독립된 100이며 시작 스폰율은 40회/분, 분당 증가량은 10이다. 상세는 [비 내리는 스테이지 2](비_스테이지2.md)의 최신 설정을 따른다. 아래 50명 연동 설명은 이전 기록이다.

- 2026-10-19 최종 사망 연출: 두 보스의 체력이 모두 0이 되면 5m 넘게 떨어진 늑대를 인간 옆으로 옮긴 뒤 두 외형을 독립 잔상으로 복제해 3초 동안 가루로 소멸시킨다. 원본 연기의 윤곽선을 잔상에도 적용하고 몸체를 불규칙하게 침식시키며, 사각 평면 대신 직전 설정보다 지름을 약 1/3로 줄인 불규칙한 다각형 재 조각을 흩뿌린다. 작은 재는 3초에 걸쳐 꾸준히 나오고 중간에 더 빽빽해진다. 개별 입자는 직전보다 천천히 흩어지고 중간에 가장 빠르며 끝에 감속한다. 카메라는 인간 보스를 중심으로 부드럽게 회전하고, 소멸 뒤 1.5초 후 게임 클리어 화면이 열린다. `RainyStageController.HandleBossDying`, `TeleportBeastBesideHuman`, `HandleBossDied`, `BossDeathDissolve`가 담당한다. 수정 후 Unity Play 확인은 미실시다.

- 2026-10-17 정식 2막: `RainyTwinBoss` 씬이 BambooStage1 다음 씬이다. `RainyStage_JH`의 50명 웨이브와 비·사운드 설정을 옮기고, 원래 이 씬의 쌍둥이 보스 프리팹과 연기 크기 설정은 유지했다. [비 내리는 스테이지 2](비_스테이지2.md)를 따른다.
- 2026-10-19 2막 진입 제목: RainyTwinBoss 씬 시작에 기존 경고 캔버스로 `2막`을 1.5초 표시한다. 이어 하기·보스 체크포인트 재도전에도 표시하며 `RainyStage_JH` 시험 씬에는 표시하지 않는다. 보스 등장 경고 시 제목은 `강적 출현`으로 되돌린다. Unity Play 화면 확인은 미실시다.

- 기능 설명: `RainyTwinBoss` 씬에서 일반 적 50명 웨이브를 마친 뒤 기존 쌍둥이 보스(TwinBoss)와 싸운다. 비 연출은 약한 비에서 강한 비로 전환한다.
- 동작 조건 및 처리 흐름: `RainyStageController`가 50명 처치 후 방어 웨이브를 멈추고 `강적 출현` 경고를 2초 표시한다. 원형 공터(`Arena`, Edge Inset 2m)의 NavMesh 후보 중 플레이어에서 가장 먼 지점을 찾고 인간·짐승을 플레이어를 향한 좌우(Pair Gap 4m)에 배치한다. 등장 순간 플레이어 HP를 최대로 회복하고 빨간 등장 파동 3회와 카메라 흔들림을 재생한다. `TwinBossController.ConfigureArena`에 원형 공터를 전달하여 질주 원·거합 차징 위치·짐승 출현 가장자리의 기준을 유지한다. 인간·짐승의 `EnemyHealth.Died`를 받아 둘 다 쓰러지면 게임 클리어를 요청한다. 보스 체크포인트가 저장된 재도전은 일반 웨이브를 건너뛴다.
- 구현 상태: 기존 보스 프리팹, 연기 크기 설정, 인간·짐승 체력바, NavMesh를 유지하고 `RainyStageController`와 `RainyStageAudio`를 연결했다. 빌드 목록·Stage1 전환·인트로 이어 하기를 RainyTwinBoss로 변경했다. 쌍둥이 보스의 연기 외형과 도형 늑대는 [쌍둥이 보스](쌍둥이_보스.md)의 2026-10-17 절을 따른다. 실제 Play에서 전체 진행·클리어·재도전은 미확인이다.
- 2026-10-18 일반 Beast 사망음: 이 씬의 `DefenseEnemySpawner._beastDeathSound=DefenseBeastDie`로 스폰된 늑대형 일반 적의 사망에만 두 가지 으르렁거림을 무작위 재생한다. 음량 정렬·피치·FMOD 연결은 [DefenseBeast](DefenseBeast.md)의 「RainyTwinBoss 일반 Beast 사망 으르렁거림」을 따른다. 쌍둥이 보스 짐승의 사망음은 기존 설정을 사용한다.
- 2026-10-18 인간형 일반 적 사망음: 방어 근접 적과 투척수는 `HumanEnemyDie=50`의 5개 음성 중 하나를 재생한다. 기본 -3반음에 사망마다 -2~+2반음을 더하며 [적 전투 및 체력](적_전투_체력.md)의 「인간형 적 사망 음성」을 따른다. 쌍둥이 보스의 사람·짐승 사망음은 변경하지 않았다.
- 2026-10-19 보스 공터 이탈 수정: `DefenseArenaBoundary`는 플레이어만 제한하므로 NavMesh 위의 보스 이동은 대나무 바깥 좌표를 사용할 수 있었다. 특히 짐승의 직선 덮치기가 플레이어를 지나가는 최소 거리와 가장자리 거리를 `Max`로 선택해 경계를 넘었고, 피격 회피 후보도 플레이어 중심으로 뽑아 공터 바깥일 수 있었다. 이제 덮치기 착지, 인간 거합 차징·돌진 목적지를 NavMeshAgent 반지름을 뺀 공터 안쪽으로 제한하고, 회피 후보의 경계를 확인한다. 보스의 실제 위치도 매 프레임 공터 안쪽 NavMesh로 보정해 다른 돌진·순간이동 경로가 경계를 넘는 경우를 막는다. 탑승 중인 인간은 짐승 등 위치를 따르므로 개별 보정을 건너뛴다.
- 2026-10-19 가장자리 덮치기 보정: 위 2m 안쪽 제한 때문에 공터 끝 플레이어에게 덮치기가 닿지 않아, 늑대의 덮치기와 실제 위치에 한해 접촉 반경만큼 공터 안쪽까지 접근하도록 조정했다. 공터 바깥 이동은 허용하지 않는다. 가장자리에서 바깥을 보는 플레이어에게는 안쪽 출현 지점을 다시 찾는다. 늑대의 사람 모양 지면 발자국 표시도 끄고 발소리는 유지한다. 자세한 계산은 [쌍둥이 보스](쌍둥이_보스.md)의 최신 절을 따른다.
- 2026-10-19 거합 차징 방해 위치: 짐승은 덮친 뒤 플레이어 뒤 착지 지점에서 바로 다시 공격하지 않는다. 다음 방해 공격마다 잠수해 거합을 준비 중인 인간 둘레 3m의 빈 공터 지면으로 이동한 뒤 플레이어를 향해 나온다. 위치를 찾지 못하면 잠수 상태로 다음 방해 시각을 기다린다. 자세한 조건은 [쌍둥이 보스](쌍둥이_보스.md)를 따른다.

#### 확인 결과

- 현재 RainyTwinBoss의 보스 프리팹과 연기 크기 오버라이드가 남아 있음을 씬 데이터에서 확인했다. 아래 기록은 이전의 보스전 전용 씬을 만들 당시의 확인 결과다. 이번 통합 후 전체 Play 진행은 미확인이다.
- `dotnet build Assembly-CSharp.csproj --no-restore` 오류 0개, 기존 경고 2개(CS0414). Unity가 아직 새 파일을 가져오지 않아 생성 파일인 csproj에 새 스크립트 Compile 항목 한 줄을 직접 추가해 빌드했다.
- 씬 YAML은 RainyStage 대비 보스 인스턴스·컨트롤러 블록만 다르며 CRLF 유지와 파일 ID 중복 없음을 확인했다.
- Unity 에디터 로그에서 새 스크립트 컴파일과 씬 가져오기·열기를 확인했다. 사용자 Play에서 트윈보스가 등장해 인간 사격(`TwinBossRanged` 15 피해)이 플레이어에 적중한 기록을 확인했다.
- 같은 Play를 끌 때 씬 해제 순서로 경고 Canvas가 먼저 파괴되어 `OnDisable`에서 MissingReferenceException이 났다. Canvas가 남아 있을 때만 숨기도록 수정했으며 수정 후 Play 종료는 미확인이다. 같은 코드가 있는 `BambooStage1Controller`는 범위 밖이라 변경하지 않았다.
- 두 보스 처치 후 클리어, 사망 후 재도전은 Play 미확인이다. 테스트 코드는 작성하지 않았다.
