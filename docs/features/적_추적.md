# 적 추적 시스템

### 기능 이름

#### 2026-10-18 공격 범위 안 교전 이동 연결

- `EnemyController`는 같은 오브젝트에 `IEnemyEngagementMovement` 구현이 있으면 Attacking 상태에서 공격 중이 아닐 때 멈추는 대신 `UpdateEngagement(target)`를 매 프레임 호출하고, `IsReadyToAttack`이 참일 때만 공격을 시도한다. 공격 후딜 중에도 정지·바라보기 대신 같은 이동을 호출한다.
- 구현이 없는 적은 기존 동작(정지 후 공격 시도, 후딜 중 정지·바라보기)을 유지한다. 현재 구현은 DefenseBeast의 `DefenseBeastProwl`(원 그리기·물러나기) 하나다. 상세는 [DefenseBeast 일반 적](DefenseBeast.md)의 2026-10-18 절을 따른다.
- 관련 코드: Assets/Scripts/Enemies/EnemyController.cs의 `Update`·`UpdateRecoveryPursuit`, Assets/Scripts/Enemies/IEnemyEngagementMovement.cs. Play 확인은 미확인이다.

#### 2026-10-12 적별 검 소음 청각 범위 설정 및 표시

- 후속 요청으로 청각 설정과 기즈모를 EnemyController에서 EnemySensor로 옮겼다. Hearing Distance·Show Hearing Range는 센서의 소리 감지 그룹에 있으며 시야 Detection Range와 독립적이다. 탐지 반경 × 1.2 규칙은 적용하지 않는다. 시야 범위는 기존 노란색, 청각 범위는 청록색으로 구분한다. StageSwordNoise는 EnemySensor.HearingDistance를 읽는다. 적 프리팹에 센서 설정 저장·컴파일 확인. 기존 EnemyController의 청각 필드·표시는 제거했다.

#### 2026-10-12 공격 후딜 중 추적 재개

- 충돌 정리 이후 사용자의 구현 복구 요청으로 현재 코드에서 빠진 EnemyController.UpdateRecoveryPursuit와 EnemyMotor.FaceTarget을 다시 추가했다. 센서의 독립 청각 설정과 색상 표시는 기존 구현을 유지한다. 이번 복구는 Unity 컴파일·타입 반영을 확인했으며 추가 Play 교전은 미확인이다. 아래 Play 검증은 최초 구현 시점의 기록이다.
- 사용자 보고에 따라 EnemyController의 Recovery 분기에서도 센서 인지와 경로를 갱신한다. 보이는 대상이 사거리 밖으로 이동하면 기존 추적 허용 설정에 따라 접근하고, 사거리 안이면 정지한 채 EnemyMotor.FaceTarget으로 대상 방향을 바라본다.
- 공격 전조·실행·피격 경직의 이동 제한과 후딜·쿨타임 값은 유지한다. 다음 공격은 기존 EnemyAttackSelector.IsBusy·패턴 IsAvailable 제한을 그대로 적용한다. 관련 코드: EnemyController.Update·UpdateRecoveryPursuit, EnemyMotor.FaceTarget.
- Play NavMesh 검증: 후딜 유지 중 사거리 밖 대상에서 Chasing·agent.isStopped=false, 사거리 안 대상에서 Attacking·agent.isStopped=true, Stagger 중 정지를 확인했다. 초기 차폐된 검증 위치에서는 정상적으로 Idle을 유지했으며 차폐 없는 위치로 변경해 추적을 검증했다. 전체 실제 입력 교전 체감은 미확인이다.
- EnemyController Inspector의 소리 감지 그룹에 Hearing Distance와 Show Hearing Range를 추가했다. Hearing Distance 기본값은 기존 동작을 보존하는 40m이며 0이면 검 소음에 반응하지 않는다. 적 프리팹 또는 씬 인스턴스별로 수정할 수 있다. Show Hearing Range는 선택한 적의 Scene 기즈모를 제어한다.
- StageSwordNoise.AlertEnemies는 기존 완전한 NavMesh 경로 길이와 적별 Hearing Distance·씬 Sword Hearing Distance 중 작은 값을 비교한다. 씬의 Use Sword Noise·거리·경계 유지 시간은 다음 소음 전달마다 읽어 Play 중 Inspector 변경도 반영한다. 시각 감지·순찰·공격·자동 추적 설정은 변경하지 않는다.
- 선택한 적에 주황색 구·수평 원·검 소리 감지 거리 라벨을 그린다. 씬 소음 설정의 상한도 표시 범위에 반영한다. 원은 최대 공간 경계이며 실제로는 벽을 통과하는 직선 거리 대신 연결된 복도의 NavMesh 경로 길이를 검사한다. 씬 소음이 꺼져 있으면 표시 거리는 0이다.
- 관련 코드: Assets/Scripts/Enemies/EnemyController.cs의 HearingDistance·OnDrawGizmosSelected, Assets/Scripts/Maps/StageSwordNoise.cs의 Initialize·AlertEnemies, Assets/Scripts/GameManagers/GameSceneInitializer.cs의 SwordNoiseEnabled·SwordHearingDistance·SwordAlertDuration.
- 적 프리팹 4종에 기본 거리 40m·기즈모 켜짐을 저장했다. 컴파일 성공. Stage_2 Play에서 실제 AlertEnemies와 NavMesh 경로를 사용해 적별 거리 0에서 무반응, 0.5m 범위 안에서 청각 경계 시간 갱신을 확인했다. 검증 후 값 40m 복원·검증용 Play 종료. 기즈모의 실제 화면 시각 확인과 전체 전투 집결 체감은 미확인이다. 사용자 요청으로 청각 범위 제한과 시각화를 추가했으며 기존 씬 값은 임의로 낮추지 않았다.

- 기능 설명: 여러 적 유닛이 공유하는 3D 플레이어 감지, 장애물 우회 추적, 근접·원거리 공격 및 발걸음 확장 시스템. 추적기와 공격 유형을 상속하여 유닛별 행동을 구현할 수 있다.
- 공격 확장: 한 유닛이 여러 공격 패턴을 보유하고 우선순위·사거리·쿨타임으로 선택한다. 전조 시작 때 조준 위치를 고정하고 전조 후 공격을 확정한다. 상세 동작과 팀원 이벤트 계약은 [적 공격 패턴](적_공격_패턴.md)을 따른다.
- 동작 조건 및 처리 흐름: Inspector에 지정한 Target이 감지 거리 안에 있고 장애물이 시야를 가리지 않으면 추적한다. 공격 컴포넌트가 있으면 공격 사거리에서 정지하고 쿨타임마다 공격한다. 시야를 잃으면 마지막 확인 위치로 이동하며 기억 시간이 지나거나 도착하면 대기한다. NavMesh의 이동 가능한 영역으로 경로를 계산한다.
- 구현 상태: 적·공격 관련 코드 구현 및 Unity 6000.0.55f1 컴파일 완료. 별도 EnemyChaseDemo 씬과 NavMesh 데이터 생성. 기존 검증에서 장애물 우회, 감지 차폐, 공격 거리 정지, 발걸음 이벤트 및 수색·대기 전환을 확인했다. 복수 공격의 전조·고정 조준·돌진·취소에 이어 투사체 발사·충돌·피해 전달, 근접 다중 Collider 중복 방지 및 회피를 검증했다. 예제 이름을 역할에 맞게 정리했다. 상세 결과는 적 공격 패턴 명세를 따른다. 체력 상태 및 사운드·발자국 자산은 외부 연결 영역이다.

#### 연결 및 협업

- 연결된 기능: Unity AI Navigation 2.0.8. 사운드와 발자국은 이벤트에 연결할 수 있도록 제공한다.
- 발자국 연결: 사용자 요청으로 합쳐진 FootstepEmitter를 적에 연결했다. 지면 접촉 알림은 EnemyFootsteps로 한 번 중계하고 실제 발자국·파동·빛은 기존 Game.SensoryManager가 생성한다. 적 실제 추적의 접촉 13회와 중계 13회, 효과 생성 및 수명 정리를 확인했다. 사운드 매니저와 팀원 생성 코드는 변경하지 않았다.
- 공유하는 코드 및 상태: EnemyController.StateChanged, EnemyFootsteps.Footstep C# 이벤트. Inspector 이벤트 목록은 제거하며 수신자는 OnEnable/OnDisable에서 구독·해제한다. 기존 SoundManager, PoolManager는 변경하지 않는다.
- 중복 또는 충돌 사항: 기존 적 및 플레이어 스크립트 없음. 기존 씬은 변경하지 않는다.
- 승인 필요 사항 및 결과: 기존 기능과 충돌 없음.

#### Inspector 연결 방법

1. 적 루트에 EnemyController를 추가하면 EnemySensor, EnemyMotor, EnemyAttackSelector, NavMeshAgent도 함께 추가된다. 기존 루트에 선택기가 없다면 직접 추가한다. 발걸음 확장이 필요하면 EnemyFootsteps를 추가한다.
2. EnemySensor의 Target에 플레이어 루트를 연결하거나 비워 둔다. 비어 있으면 Awake에서 Player 태그의 활성 오브젝트를 찾는다. 플레이어는 하나를 사용하며 나중에 생성되는 대상은 SetTarget으로 연결한다. Detection Range는 감지 반경이며 시야각 제한은 없다. Eye Offset, Target Offset은 각 루트의 로컬 좌표다. 기존 공격의 높이 기준은 해당 패턴 명세를 따른다.
3. Obstacle Mask에는 시야를 가리는 Collider의 레이어를 지정한다. 기본값은 Ignore Raycast를 제외한 물리 레이어다. 자신과 플레이어 루트 하위의 Collider 및 Trigger는 차폐에서 제외한다. 다른 적이 시야를 가리지 않게 하려면 적 레이어를 마스크에서 제외한다.
4. EnemyMotor의 Move Speed, Acceleration, Angular Speed, Stopping Distance를 유닛마다 지정한다. NavMeshAgent의 Agent Type, Radius, Height, Area Mask 및 Avoidance Priority는 해당 컴포넌트에서 설정한다.
5. 지형에 NavMeshSurface를 추가하고 같은 Agent Type으로 Bake한다. 움직이는 장애물에는 NavMeshObstacle의 Carve를 사용한다. 에이전트가 NavMesh 밖에 있으면 대기하며 강제로 순간이동하지 않는다.
6. EnemyController의 Perception Interval은 감지 주기, Repath Interval은 경로 갱신 주기, Memory Duration은 마지막 확인 위치를 기억하는 시간이다. 0이면 시야 상실 시 즉시 대기한다.
7. 적 루트의 FootstepEmitter에 지면 레이어와 걸음 거리를 설정한다. 공통 Emitter가 좌우 발 위치와 표면 법선을 계산하고 Game.SensoryManager로 발자국·파동·빛을 생성한다. EnemyFootsteps의 Footstep C# 이벤트는 실제 지면 접촉 위치를 중계하므로 효과를 추가 생성하지 않는다.
8. Hierarchy에 Game 매니저를 배치한다. EnemyFootsteps가 기존 매니저의 관측자가 비어 있을 때만 EnemySensor.Target을 연결한다. 별도 관측자 바인딩 컴포넌트는 사용하지 않는다. 공통 Emitter가 활성화되면 EnemyFootsteps의 거리 설정과 애니메이션 NotifyFootstep은 중복 실행하지 않는다. Emitter가 비활성화되면 기존 이벤트 전용 발걸음 동작을 사용할 수 있다. 접촉 위치의 발소리는 공통 EnemySoundSettings 에셋의 Footstep을 사용하며 None으로 끌 수 있다. 단, 활성 `RainyStageAudio.UseWaterFootsteps`가 켜지면 `EnemyWaterFootstep` 이벤트를 선택한다.
9. 같은 루트에 EnemyMeleeAttack, EnemyRangedAttack, EnemyChargeAttack을 원하는 조합으로 추가한다. 사용할 공격을 선택기의 Patterns에 직접 연결한다. 비어 있으면 공격하지 않는다. 전조·사거리·쿨타임 및 이벤트 연결은 [적 공격 패턴](적_공격_패턴.md)을 따른다. 공격 사거리는 감지 거리보다 작게 설정한다.

#### 추적 및 재사용 규칙

- 미발견 대상이 장애물 뒤에 있으면 감지하지 않는다. 발견 후에도 현재 대상의 실제 위치를 시야 너머에서 계속 갱신하지 않는다.
- 시야 상실 또는 감지 범위 이탈 시 마지막 확인 위치로 이동하며, 도착 또는 Memory Duration 만료 후 Idle로 전환한다. 재감지하면 Chasing으로 복귀한다.
- 장애물 차폐 후 즉시 순찰 복귀 수정: Searching 진입 시 EnemyMotor.Stop으로 이전 추적·공격 경로의 도착 상태를 초기화하고 다음 경로를 즉시 요청한다. 수색 경로의 정지 거리는 0.1m로 지정하여 이전 공격 사거리나 기본 1.5m 정지 거리를 도착 판정에 재사용하지 않는다. 기존에는 새 수색 목적지를 요청하기 전에 이전 경로의 HasArrived가 참이면 Idle로 전환되어 순찰로 돌아갈 수 있었다. Memory Duration 만료·대상 비활성·Allow Walking Chase=false 처리와 벽 뒤 실제 위치를 갱신하지 않는 규칙은 유지한다.
- 수정 검증: Unity 재컴파일 상태는 up_to_date, failed=false, compilationFailed=false, errors=[]다. MainMap 플레이 모드의 02_CourtPatrol에서 기존 목적지 도착 상태를 만든 뒤 임시 Collider로 시야를 차폐했다. oldArrival=true, occluded=true 조건에서 Searching 진입 후 이전 도착 상태가 초기화됐으며 Update 후 Searching 유지, stoppingDistance=0.1, HasArrived=false를 확인했다. 차폐 해제 시 Chasing, 다시 차폐 시 Searching, 마지막 확인 시각을 3초 기억 시간 밖으로 설정하면 Idle을 확인했다. 이는 런타임 직접 상태 검증이며 모든 장애물 경로의 실제 우회 주행을 검증한 것은 아니다. 새 테스트 코드는 작성하지 않았고 플레이 종료로 임시 장애물·위치·컴포넌트 변경을 원복했다.
- 경로가 없거나 목적지 주변에 허용 NavMesh가 없으면 벽을 통과하지 않는다. 부분 경로는 마지막 도달 가능한 지점까지 이동할 수 있으며, 대상이 계속 보이면 일정 주기로 경로를 재요청한다.
- SetTarget은 초기화 완료 후 호출한다. null이면 추적을 중지한다. 비활성 대상 또는 파괴된 대상도 다음 감지 주기에 추적을 중지한다.
- 풀에서 비활성화 시 경로와 추적 상태가 초기화되고 다시 활성화 시 기억과 발걸음 누적값을 초기화한다. 이벤트 구독은 수신 측의 OnEnable/OnDisable에서 등록 및 해제한다.
- 기존 플레이어 입력과 SoundManager, PoolManager 동작은 수정하지 않는다. 장님 컨셉은 플레이어에 해당하며 적은 거리와 시야로 감지한다.

#### 공격 및 상속 확장

- 선택기에 활성 공격 패턴이 없으면 추적 전용 유닛으로 동작한다.
- 공격 범위 안에서는 Attacking 상태로 이동을 멈춘다. 대상이 범위를 벗어나면 접근하며, 이동 정지 거리를 공격 사거리보다 0.2 작게 설정하여 공격 범위에 도달하지 못하고 멈추는 상황을 방지한다. 원거리형은 사거리에서 정지하지만 가까워진 플레이어로부터 후퇴하지는 않는다.
- 패턴 CanAttack은 활성 대상과 사거리를 판단하며 돌진은 직선 경로도 검사한다. 선택기의 TryAttack은 준비된 패턴 하나의 전조만 시작한다. 전조 중에는 이동을 멈추고 실행 중 돌진에만 이동을 허용한다.
- EnemyAttackBehaviour를 상속하여 Range와 PerformAttack(EnemyAttackContext context)을 구현하면 새로운 공격을 만들 수 있다. 고정 조준 문맥을 사용하여 전조를 듣고 회피할 수 있는 공격을 만든다.
- EnemyController를 상속하여 OnStateChanged, UpdatePerception 또는 Unity Lifecycle 메서드를 재정의할 수 있다. 기본 동작을 유지하는 override에서는 base 메서드를 호출한다. 파생 클래스는 protected Sensor, Motor, Attack, AttackSelector 프로퍼티와 ChangeState를 사용할 수 있다.
- 공격 컴포넌트는 프리팹 생성 시 배치하며 Awake에서 캐싱한다. 플레이 중 공격 유형을 AddComponent로 교체하는 기능은 현재 범위에 포함하지 않는다.
- 실제 투사체 이동과 근접 범위 판정은 내장 구현 또는 상속·이벤트 교체 방식으로 제공한다. 체력 기능은 IDamageable 또는 DamageReceiver 이벤트에 연결한다. 전조·실행·종료·취소는 구현되어 있으며 사운드와 발자국은 팀원 담당이다.

#### 예제 씬

- EnemyChaseDemo를 열고 Play하면 플레이어는 고정된 상태로 남는다. Enemy_MultiPattern에는 근접·원거리·돌진을 함께 연결했고, Enemy_SingleRanged는 단일 원거리형, Enemy_SingleMelee는 벽 뒤의 단일 근접형이다. 같은 이름의 프리팹을 Assets/Resources/Enemies에서 재사용할 수 있다. 플레이어 위치와 장애물을 변경해 패턴 선택을 확인할 수 있다.
- 예제의 적 Placeholder Collider는 Ignore Raycast 레이어로 설정하여 다른 적의 시야를 차폐하지 않는다. 플레이어와 지형은 Default 레이어다. 실제 게임에서는 프로젝트 전용 레이어와 Obstacle Mask를 지정한다.
- 예제 원거리 공격에는 EnemyProjectile_Basic 프리팹과 ProjectileMuzzle이 연결되어 있고, 플레이어 루트에는 DamageReceiver가 연결되어 있다. 체력 기능은 피해 수신 이벤트에 연결한다.
- NavigationWorld의 NavMeshSurface는 자식 지형의 Physics Colliders만 수집하여 유닛과 플레이어를 베이크에서 제외한다. 지형 변경 시 다시 Bake한다.
- 기존 EnemyTest와 SampleScene 및 Build Settings는 변경하지 않았다.

- 사용자 요청으로 적 이름·상태 디버그 표시 컴포넌트와 스크립트를 제거했다. 이번 삭제의 실행 검증은 하지 않았다.

- Inspector 연결 방식 수정: Patterns의 런타임 자동 수집을 제거하고 예제 배열에 공격 참조를 저장했다. 원거리는 내장 발사 여부를 명시하며 발사점 자동 대체와 프리팹 누락에 따른 자동 이벤트 전환을 제거했다. 이번 변경은 실행 검증하지 않았다.

- 다중·단일 공격 구성과 사운드 요청 추가: 각 공격의 전조 시작 및 실제 실행 직전에 기존 사운드 API를 호출하고 발걸음은 접촉 순간에 호출한다. 소리는 Assets/Resources/Enemies/EnemySoundSettings.asset 한 곳에서 행동별로 관리한다. 예제 공격 소리는 Footstep 임시 연결이며 전용 소리는 사운드 담당자가 등록한 뒤 공통 에셋에서 교체한다. 이번 변경의 실행 확인은 사용자에게 맡긴다.

- Inspector 정리: 적 코드의 이벤트 연결 목록을 제거하고 설정값과 필요한 참조만 노출한다. C# 이벤트 및 상속 확장은 유지한다. 이번 변경의 실행 검증은 수행하지 않는다.

- Allow Walking Chase는 기본 true다. false인 적은 보이는 대상에게 공격할 수 있을 때만 공격 상태가 되고 공격 불가·시야 상실 시 대기한다. 추적과 마지막 위치 수색을 사용하지 않는다. Enemy_RhythmCharge 프리팹과 예제 적은 false 및 감지 거리 18m로 설정하여 먼 거리에서 전조 후 박자 돌진을 시작한다. 실행은 미확인이다.

- 박자 돌진 재현 및 수정 검증: 사용자 요청으로 직접 Play 테스트를 수행했다. 대상의 몸 중심 높이 때문에 NavMesh 검사에 실패한 문제를 해당 공격의 지면 투영으로 수정했다. 수정 후 9m에서 전조 동안 이동하지 않고 네 돌진으로 대상 앞 약 0.06m까지 접근했다. 종료 시 편집 모드로 복귀하여 실행 중 변경은 원복했다. 상세 시간·위치는 적 공격 패턴 명세에 기록한다.

#### 기본 왕복 순찰

- EnemyPatrol은 배치 위치에서 Local Direction 방향의 Distance만큼 떨어진 지점까지 이동하고 돌아온다. Distance는 편도 거리이며 기본 3m, Local Direction은 적의 로컬 앞 방향, Wait Duration은 각 끝점에서의 대기 시간이며 기본 1초다. Distance 0 또는 컴포넌트 비활성화는 순찰을 끈다. 경유지 배열은 사용하지 않는다.
- EnemyController가 대상 미발견 상태에서만 Patrolling 상태로 순찰을 호출한다. 플레이어 발견 시 순찰 경로를 중단하고 추적 또는 공격으로 전환한다. 기억이 끝나거나 대상이 없어지면 기존 두 끝점의 순찰을 재개하며 실행 중 공격 위치로 순찰 기준을 옮기지 않는다. 풀 재활성화 시 새 배치 위치를 기준으로 초기화한다.
- Allow Walking Chase=false인 박자 돌진 적도 미발견 상태의 순찰은 허용한다. 플레이어가 보이면 돌진이나 쿨타임 대기만 수행하며 돌진 경로가 막혔다고 순찰로 접근하지 않는다. 순찰 기능은 플레이어를 향해 걷는 추적 기능과 별개다.
- 기존 EnemyMotor와 NavMeshAgent로 장애물을 우회한다. 끝점 주변 NavMesh로 위치를 보정하며 부분 경로 끝 또는 잘못된 경로에서는 정지 후 반대 지점을 시도한다. 이동 중 기존 FootstepEmitter와 공통 발걸음 소리는 그대로 작동한다.
- 네 적 프리팹 및 EnemyChaseDemo의 적에 기본 순찰 컴포넌트를 연결한다. 플레이어가 이미 보이는 예제 적은 순찰보다 감지·공격이 우선한다. 순찰 동작은 이번 요청에서 실행 검증하지 않았다.

#### 쉬운 적 배치 및 NavMesh 설정

1. Scene 뷰에서 배치할 곳을 보고 GameObject > BlindBlade > Enemies 메뉴에서 적 종류를 고른다. 또는 Assets/Resources/Enemies의 프리팹을 드래그한다. 프리팹에는 공격 배열·원거리 발사점·순찰 연결이 저장되어 있다.
2. 생성 메뉴는 Scene 뷰 중심 근처의 같은 에이전트 유형 NavMesh를 찾아 배치하고 선택한다. 가까운 NavMesh가 없으면 Scene 뷰 중심에 생성하므로 지면 위로 직접 옮기고 Bake해야 한다. 생성은 Undo로 취소할 수 있다.
3. 플레이어 루트에 Player 태그를 설정하면 비어 있는 적 Target은 시작 시 자동 연결된다. 예제 StationaryPlayer에 Player 태그를 지정했다. 수동 Target 참조가 있으면 우선 사용하며 팀원 플레이어 코드는 수정하지 않는다.
4. 적을 선택하면 청록색 선과 두 원으로 순찰 시작점·끝점이 보인다. 적의 위치·회전 또는 EnemyPatrol의 Distance와 Local Direction을 조절한다. Gizmos가 켜져 있어야 표시된다.
5. NavMeshSurface는 지형에서 걷는 영역을 Bake하고 NavMeshAgent는 그 영역에서 경로를 따라간다. 예제는 NavigationWorld의 타입 0 Surface와 같은 타입의 에이전트 4개, SightBlockingWall 장애물 1개를 사용하며 NavMeshLink는 없다. 지형 변경 시 Surface를 다시 Bake하며 적 추가만으로는 다시 Bake할 필요가 없다. 지형 수집 범위에 적을 포함하지 않는다.
6. 다른 맵에는 해당 에이전트 유형의 NavMeshSurface와 베이크 데이터, 기존 Game 감각 매니저가 필요하다. 발자국 지면 레이어는 새 지형에 맞춘다. 팀원 매니저·감각 코드는 수정하지 않는다.

- 박자 돌진 추가: EnemyChaseDemo에 Enemy_RhythmCharge를 추가하고 Assets/Resources/Enemies/Enemy_RhythmCharge.prefab으로 제공한다. 탓·탓·타탓의 네 이동을 세 박자 그룹으로 실행하며 이동 직전 공통 사운드를 호출한다. 상세 설정과 타격 연결은 적 공격 패턴 명세를 따른다. 실행은 미확인이다.
