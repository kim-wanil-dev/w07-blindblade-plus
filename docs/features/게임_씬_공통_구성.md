#### 2026-10-12 공통 UI 씬 사전 배치

- 현재 UI는 런타임 생성하지 않는다. UIManager.prefab의 Canvas 아래에 MonologueUI·OpenDoorPromptUI·GameOverUI를 중첩 프리팹으로 배치하고, 세션 Initializer를 사용하는 11개 씬에 UIManager 프리팹을 저장했다.

#### 연결 및 협업

- 연결된 기능: 플레이어 시스템·피격·적 전투·감각·지형 기억·복도 라운드·스테이지 이동.
- 공유하는 코드 및 상태: Game.Player는 PlayerController, Game.Instance.InputManager는 InputManager, Game.Instance.GameStateManager는 GameStateManager, Game.Instance.UIManager는 UIManager를 제공한다. 씬 종료 시 이벤트·플레이어 연결과 화면을 정리하며 매니저 인스턴스는 Game 하위에 유지한다.
- 입력 계약: InputManager는 GameplayState에 따라 입력 허용 상태를 변경하고 GameplayInputEnabledChanged(bool)를 발행한다. 활성 어댑터가 이를 구독하여 SetInputAllowed를 적용한다. 일반 어댑터가 활성화된 경우 카타나 어댑터는 명령 전달을 억제한다. 정책 변경으로 컴포넌트 enabled를 끄지 않으며 UI 입력은 유지한다. 이동·시점·가드·차지 및 카타나 쳐내기 정리는 어댑터가 담당한다.
- 상태 계약: StateChanged는 GameplayState를 전달한다. GameOver 상태를 먼저 기록해 SetDead로 발생하는 사망 이벤트의 재진입을 막는다. 시간·커서 복구는 재시작 또는 세션 해제 시 실행한다.
- UI 계약: GameOverUI는 기존 RESTART 및 NOT YET 버튼 표현을 사용한다. 재시작을 GameStateManager.Restart에 전달하고 머무르기는 화면을 유지한다. 새 화면 디자인은 추가하지 않는다.
- 수명: 입력·상태·UI 매니저는 Game이 리소스에서 생성하여 보유하고 씬 종료 시 세션 연결만 정리한다. UIManager는 Game 하위의 개별 객체이며 화면은 UIManager 하위, 지형 기억은 씬 Initializer 하위에 생성한다. 기존 영속 감각·이펙트 서비스 생성 경로는 유지한다.
- 씬 설정: GameSceneInitializer의 공통 프리팹 참조, 지형 기억 사용 여부·최소 좌표·크기, 복도 규칙 사용 여부를 인스펙터에서 조정한다. 지형 기억 해상도·반경·색상은 해당 기억 프리팹에서 조정한다.
- 팀원 연결 작업: 라운드 패배 요청은 Game.Instance.GameStateManager.RequestGameOver()를 사용한다. 외부에서 입력 어댑터를 직접 비활성화하지 않는다. 추가 입력 정책은 InputManager에서 처리한다.
- 중복 또는 충돌 사항: 기존 Assets/Scripts/Managers/InputManager.cs의 실제 PlayerInputController는 수정하지 않는다. 입력 정책은 Assets/Scripts/GameManagers/InputManager.cs의 InputManager가 담당한다. StraightCorridor의 씬 변경은 보존하면서 공통 초기화 구성으로 전환한다.
- 승인 필요 사항 및 결과: 사용자가 A 모드로 전체 PLAN_0005 수행을 승인했다. dev 브랜치에서 Git CLI는 금지되어 커밋은 수행하지 않는다.

#### 실행 검증 결과

- Unity 에디터 재컴파일 오류 0건. 전환한 네 씬에서 Initializer 1개, Player.prefab 연결, 누락 스크립트 0개를 확인했다.
- 복도 Play에서 게임오버 요청 두 번에도 GameOver 상태·입력 차단·시간 배율 0·패널 표시·RESTART 선택을 확인했다. NOT YET은 상태를 유지했고 RESTART 요청 후 Playing·시간 배율 1·현재 플레이어 Free 및 상태 서비스 1개를 확인했다.
- 입력 차단 API 호출 후 이동·대기 시점 입력이 0이고 차지가 해제됨을 확인했다. 어댑터의 기존 enabled 상태는 변경하지 않는다.
- 기존 피해 수신 API로 적 피해를 전달해 첫 적중 전 피격 패배가 GameOver 및 입력 차단으로 연결됨을 확인했다. 플레이어 내부 전투 판정 API는 적 HP 30→0을 적용했고 동일 ActionId 중복 호출은 결과를 유지했다.
- TCorridor·Stairwell·MainMap에서 실제 Play 씬 이동 후 Playing 상태와 상태 서비스 1개를 확인했다. Stairwell·MainMap의 지형 기억 텍스처와 활성 상태를 확인했다.
- 샌드박스 전용 테스트 디버그 구성은 현재 프로젝트에서 제거되었다. 카타나 전투 디버그 오버레이는 유지한다.
- MainMap은 기존 적 원본 GUID 4종 누락으로 적 인스턴스 5개가 정상 로드되지 않는다. 이 복구는 이번 공통 구조 변경 범위에 포함하지 않아 실제 교전·전체 이동·문 통과 검증은 미확인이다. FMOD 포트 충돌 및 리스너 관련 경고도 별도 확인 대상이다.
- 검증은 기존 Unity Play와 API 호출로 수행했으며 새로운 테스트 코드나 임시 검증 스크립트는 만들지 않았다. 검증 중 상태·피해·씬 이동은 런타임에서만 적용하고 저장하지 않았다.
- Play 종료 후 원래 열린 StraightCorridor(미저장) 및 Stairwell(저장됨) 구성을 복원했다. StraightCorridor의 씬 파일 전환은 미완료로 남긴다.

#### 매니저 분리 및 제네릭 UI 접근

- 묶음 GameplayServices 및 검증용 Variant를 제거했다. Game이 InputManager·GameStateManager·UIManager를 Game 하위에 각각 동적 생성하고 씬 종료 시 세션을 정리한다.
- UIManager는 GameUI 프리팹을 생성·초기화하고 실제 타입으로 캐싱한다. Get<T>()는 해당 인스턴스를 반환하고 Show<T>()·Hide<T>()는 표시 상태를 변경한다. 첫 조회 시 타입별 리소스 경로로 동적 생성하며, 미등록 타입은 오류를 보고하고 null을 반환한다.
- GameOverUI는 기존 화면의 버튼과 패널만 담당한다. 기존 스크립트 GUID를 보존해 프리팹 연결을 유지했다. GameplayControlsUI는 기존 검증 패널 버튼을 담당하며 씬의 조작 UI 표시 설정이 꺼져 있으면 초기화 시 생성하지 않는다.
- GameUI.Initialize(), SetVisible(visible), Shutdown()이 화면 계약이다. 새 화면은 이 타입을 상속하고 ResourcePaths.UI의 타입별 경로에 등록한다. 게임오버 상태에 따른 화면 표시 연결은 GameOverUI가 StateChanged를 구독하여 담당한다. UIManager에는 게임오버 상태 판단이 없다.
- 접근 예: Game.Instance.UIManager.Show<GameOverUI>(); Game.Instance.UIManager.Get<GameplayControlsUI>(); Game.Instance.UIManager.Hide<GameplayControlsUI>();

- UIManager.Initialize()는 프리팹 인자 없이 이벤트 시스템을 준비한다. Game.InitializeSession에서 상태·입력·UI 순으로 초기화하며, GameOverUI는 Game의 상태 매니저만 캐싱하고 GameplayControlsUI는 상태·입력 매니저를 각각 캐싱한다.

#### 입력 정책과 어댑터 책임 분리

- InputManager.Initialize(state)는 상태 이벤트만 구독한다. InputManager는 플레이어·모터·어댑터 참조와 플레이어 명령 호출을 갖지 않는다. SetGameplayInputEnabled는 값이 달라질 때 GameplayInputEnabledChanged(bool)를 발행한다.
- SceneServicesChanged는 제거했다. Initializer가 Game.InitializeSession 이후 활성 어댑터 Initialize()를 호출하고 종료 시 Shutdown()을 호출한다. 어댑터는 초기화된 InputManager의 정책 이벤트만 구독하고 즉시 현재 상태를 적용하며, 비활성화 시 구독을 해제한다.
- PlayerInputCommandAdapter는 이동·가드·차지 종료와 PlayerMotor.ClearInput을, KatanaInputCommandAdapter는 이동·쳐내기·차지 종료와 가드 및 모터 입력 정리를 수행한다. 매니저가 없는 기존 독립 검증 씬은 초기 어댑터 허용 상태를 유지한다.
- Play API로 카타나 차지와 일반 가드 정리, 이동·시점 입력 0, 어댑터 재활성화 시 구독 1개, 씬 서비스 해제 시 구독 제거와 재초기화 시 구독·매니저 각각 1개를 확인했다. 게임오버 표시와 재시작 후 Playing·입력 허용을 확인했다. 실제 물리 키보드·포인터 조작은 추가 검증하지 않았다.

#### Game 내부 매니저 로드와 명시적 세션 연결

- Game.InitializeSingleton은 ResourcePaths.Managers의 INPUT_MANAGER_PATH·GAME_STATE_MANAGER_PATH·UI_MANAGER_PATH로 각 프리팹을 ResourceManager에서 로드한다. 기존 자식 매니저가 있으면 재사용한다. 개별 프리팹은 Assets/Resources/Prefabs/GameManagers에 위치한다.
- Initializer는 Game.InitializeSession()을 요청한 뒤 기존 매니저를 참조하고 플레이어 전투·활성 입력 어댑터·맵별 감각·기억·복도 규칙을 준비한 후 BeginPlaying()을 호출한다. Game.InitializeSession은 등록된 플레이어를 상태 매니저에 연결하고 입력·UI를 초기화한다. Initializer에는 공통 매니저 생성·등록·파괴 코드가 없다.
- 종료 시 어댑터 Shutdown()으로 구독을 해제한 뒤 Game.ShutdownSession()이 입력 정책·화면·플레이어 상태 연결을 정리한다. 매니저 인스턴스와 공개 접근점은 유지된다. 플레이어 등록 해제는 현재 플레이어 참조만 제거하며 세션 종료는 Initializer가 담당한다.
- 어댑터 OnEnable은 InputManager.IsInitialized일 때 Initialize()를 호출한다. 공통 세션이 없는 독립 플레이어 검증 씬에서는 기존 입력 허용 동작을 유지한다.
- Unity 컴파일 오류 0건. StraightCorridor→검증 씬→재시작에서 입력·상태·UI 매니저의 동일 인스턴스 ID를 확인했다. 입력 정리·게임오버 표시, Initializer 및 어댑터 비활성화 시 구독 해제와 재활성화 시 단일 구독·단일 매니저를 Play API로 확인했다.

#### 공통 Canvas

- UIManager.prefab 하위 Canvas 하나에 Screen Space Overlay·CanvasScaler·GraphicRaycaster를 구성했다. 기준 해상도는 1920×1080, Match Width Or Height는 0.5다. UIManager의 _canvas 연결은 프리팹에 저장돼 있다.
