# 전투 로컬 로그 및 Google Sheets 자동 전송

### 기능 이름

- 기능 설명: BambooStage1의 1-1 웨이브·1-2 보스전을 도전별로 구분하여 사망, 피해 원인, 입력 시도, 반응 시간, 위치·공격 히트맵과 적 공격 결과를 기록한다. 스키마는 **0.3.0**, 게임 공통 계약 API는 **0.2.0**이다.
- 동작 조건 및 처리 흐름: Recorder Start(200)에서 공급자를 구독한다. EnemyAttackContext·투척수·보스가 전조 시 AttackId를 발급하고 피해 문맥까지 전달한다. KatanaDamageReceiver가 확정한 접촉 결과가 권위 있는 결과다. 비접촉 종료는 LateUpdate까지 대기하여 패리 반격으로 발생한 적 사망·공격 취소가 실제 패리 결과를 가리지 않게 한다. 저장·재시도·ACK 커서 흐름은 유지한다.
- 구현 상태: C# 빌드와 Unity Editor 컴파일 오류 0건. Stage1 씬 참조·표본 간격·업로드 활성값과 Intro 시작 대상 확인. 보스 재도전 실제 Play에서 BossRanged 3회와 BossCharge 1회의 시작·실행·Hit 및 피해 70을 확인했다. 자동 전송은 64건 ACK, Events 행과 도전별 Sessions 행을 확인했다. 회피·방어 입력과 1-1 웨이브의 실전 기록은 미확인이다. 테스트 코드는 작성하지 않았다.

#### 연결 및 협업

- 연결된 기능: 전투 입력·방어 판정, 일반 적 패턴, 보스 패턴, Stage1 진행, 자동 업로드.
- 공유하는 상태: 세션 ID·AttackId 발급은 CombatSessionRuntime, 전투 판정은 KatanaDamageReceiver, 스테이지 전환은 Stage1Controller, 분석 누적은 Recorder가 관리한다.
- 중복 또는 충돌 사항: 기존 InputResolved 생산자를 사용하고 별도 키보드 폴링을 추가하지 않는다. ID와 관측 신호를 추가하며 전투 피해 수치는 변경하지 않는다.
- 승인 필요 사항 및 결과: 사용자가 전조→입력과 입력→접촉을 모두 선택했고 기존 로컬 로그와 Google Events·Sessions 삭제를 승인했다. 엔드포인트·공유 토큰·익명 PC ID는 유지한다.

#### 집계 규칙

- 1-1은 웨이브와 보스 경고, 1-2는 보스 활성화부터 사망/완료까지다. 보스 재도전은 1-1 행을 생성하지 않는다. Sessions의 키는 `sessionId:stageId`이며 구간마다 1행이다. 재전송은 최신 누적 값으로 덮어써 이중 합산하지 않는다.
- `deaths`는 도전당 0 또는 1. `activePlaySeconds`는 Playing 동안 실제 경과 시간으로 일시정지·게임오버 대기를 제외한다. 경고/등장 연출도 Playing이면 포함한다. 강제 종료는 최신 `in_progress` 요약만 남을 수 있다.
- `player_input.isAttempt=true`인 고유 InputId만 시도 수에 포함한다. Rejected도 시도다. GuardHoldResume·GuardRelease는 새 시도가 아니다. Buffered→Started는 1회다. 실제 회피 시작은 dodgeStarted로 별도 집계한다.
- 패리·퍼펙트 패리·가드·피격은 **접촉 수**다. 하나의 방어 입력이 여러 공격을 막을 수 있으므로 그 합을 방어 입력 수로 나눠 성공 확률로 해석하지 않는다. guardAttemptsWithContact/WithoutContact는 고유 입력 기준이다. guardHitCount는 가드 입력 후 버튼을 놓기 전에 맞은 접촉이며 거부된 가드 의도도 포함한다.
- enemyAttackCount는 실제 실행된 공격. enemyResolvedCount는 실행된 공격 중 종료된 결과이며 Cancelled/Interrupted는 제외한다. Hit/Resolved가 적중률이다. Dodge는 실제 회피 판정(극한 회피와 회피 무적)을 뜻한다. 이동으로 비켜나 접촉하지 않은 공격은 Miss다. Invulnerable은 회피 이외 무적, Destroyed는 플레이어 검기 등으로 수리검 제거, Ignored는 판정 제외다. 이 결과를 숨기거나 회피로 재분류하지 않는다.
- ranged/melee 및 bossRanged/bossCharge 열에는 공격 시도·결과·피해·적중률·피해량 비중을 제공한다. 상위 분류와 보스 패턴 분류는 겹치므로 서로 더하지 않는다. 세부 패턴은 patterns_json과 Patterns.csv에 보존한다.
- 피해량 비중=패턴 적용 피해/전체 적용 피해. 피격 횟수 비중=패턴 피해 접촉 수/전체 피해 접촉 수. 분모 0은 빈 값이며 0%로 취급하지 않는다. 전체 통합 비율은 세션 비율의 평균 대신 분자 합/분모 합을 사용한다.
- 반응은 같은 엔진 realtime 시계의 전조 시작→입력 처리 프레임으로 계산한다. 원시 deviceTime도 보존하지만 보정 없이 서로 빼지 않는다. 입력→접촉은 정확한 AttackId의 접촉 시점과 연결된 입력의 차이다. 전조보다 먼저 누른 가드는 reactionSeconds가 빈 값이다.
- reaction_candidate는 입력 당시 살아 있는 모든 전조/비행 공격의 시간상 후보다. 여러 후보 중 어느 공격을 보고 반응했는지는 단정하지 않는다. 최종 접촉의 reactionAssociation=resolved_contact를 우선 분석하며 held_guard_intent는 실패한 가드 의도 추정이다. 현재 평균은 이 두 접촉 연결을 포함한다.
- 좌표는 월드 XZ, 단위 m. movement_sample.durationSeconds로 시간 가중 이동 히트맵을 만든다(기본 0.5초). player_input의 Attack/isAttempt로 공격 시도 히트맵, enemy_attack_resolved의 appliedDamage>0 접촉 위치로 피격 히트맵을 만든다. 원거리는 origin→position 직선이며 유도 곡선 궤적이 아니다.
- 전투 분석에 불필요한 발소리·HUD 프레임 변경·자원/연출 로그는 이 스키마에서 발송하지 않는다. 시간 표기는 KST 유지. 로컬 파일은 세션별 JSONL이며 Sessions는 구간별 요약 사건으로 만든 서버/CSV 보기다.

#### 운영 및 확인

- 로컬 경로: `%USERPROFILE%/AppData/LocalLow/DefaultCompany/w07-blindblade+/CombatTelemetry`.
- 2026-10-16 기존 57개 세션의 JSON/JSONL 114개와 전송 커서 6개를 삭제했다. 익명 ID 파일은 유지했다.
