# 전투 로컬 로그 및 Google Sheets 자동 전송

### 기능 이름

- 기능 설명: BambooDefense의 현재 확정 사건을 세션별 JSON/JSONL로 저장하고, 설정된 Apps Script 수신기로 디스크의 미확인 사건을 자동 전송한다.
- 동작 조건 및 처리 흐름: GameSceneInitializer 초기화 뒤 execution order200의 Recorder가 기존 사건 공급자를 구독한다. 값 스냅샷 → 한정 메모리 버퍼 → 백그라운드 원본 저장 → 전송 배치 → 서버 저장 확인 → URL별 디스크 커서 갱신 순서다. Scene 전환 뒤에도 전송 서비스는 유지한다.
- 구현 상태: 로컬 저장·전송기·Apps Script 수신기·PowerShell CSV 전처리·정식 씬 연결 구현. C# 컴파일 성공. 실제 Play·네트워크 전송·수신 스크립트 실행·전처리 실행은 미확인. Google 수신 URL/token 입력 전 전송은 비활성이다. D5 전체 완료를 뜻하지 않는다.

#### 연결 및 협업

- 연결된 기능: PlayerHealth, PlayerController, KatanaCombatCoordinator.Events, GameStateManager, BambooDefenseDirector, DefenseEnemySpawner, CombatThreatPresentationProvider, CombatSessionRuntime.
- 공유하는 코드 및 상태: 기존 API를 구독만 한다. 전투 판정·피해·시간·스폰 설정을 변경하지 않는다. `CombatTelemetryEnvelope`의 데이터와 ID를 저장한다.
- 중복 또는 충돌 사항: 현재 PlayerCombatEvents는 `BlindBlade.Combat.Contracts.DefenseResolution`을 사용한다. Recorder는 명시적 타입 별칭으로 공통 계약을 소비한다. 현재 공통 결과에는 DodgeId가 없으므로 방어 사건의 correlation.dodgeId는 0이다. 별도 dodge_changed 사건의 공급자 DodgeId는 그대로 보존한다. 다른 공급자 스크립트는 수정하지 않았다.
- 승인 필요 사항 및 결과: 사용자가 D5 로컬 로그와 자동 전송 추가를 요청했고 프로젝트 내부 수정 상시 승인이 있다. Google 계정·원격 배포·실제 데이터 전송은 수행하지 않았다. 실제 URL과 token은 사용자가 로컬 설정에 입력한다.

#### 설정·운영·지표

- [설치·Google 배포·테스터 PC 설정·전처리·오류 처리 안내](../../tools/combat_telemetry/README.md)를 따른다.
- 현재 기록: 세션/상태/준비 종료/표본, HP/실제 피해/사망, 행동/카타나 단계, 방어/회피/파동, 수리검 발사/투척 전조, 처치 수, C 위협 표시 상태/원본 발소리, 시간 배율.
- 실제 InputResolved 발행부와 스태미너·강화 공급자는 현재 없다. 계약 구독만으로 없는 기록을 생성하지 않는다. 실제 입력 시도 수·장치 시계 보정이 없으므로 early/late 및 입력 성공률은 산출 불가다. 선택지 이벤트도 아직 공급자가 없다.
- 피해 합계는 damage_applied.appliedDamage만 사용한다. resource_changed와 defense_resolved에 같은 감소가 있어도 중복 합산하지 않는다. parryCount/defenseCount는 접촉 중 패링 비율이며 시도 성공률이 아니다.
- runRealtimeSeconds는 준비·일시정지·포커스 이탈을 포함하고 GameOver 대기는 제외한다. combatRealtimeSeconds와 survivalGameSeconds를 함께 보존한다. 참가자별 총 체험 시간은 별도 참가자 매핑·재도전 합산 규칙이 필요하다.
- 익명 ID는 PC 설치 단위다. 동일 PC의 여러 참가자를 자동 구분하지 않는다.
- 저장 한도·실패에서 전투를 막지 않고 누락을 진단한다. 매 프레임 파일 쓰기/전체 객체 검색은 추가하지 않았다. 디스크 백그라운드 작업은 Unity 객체를 조회하지 않는다.
