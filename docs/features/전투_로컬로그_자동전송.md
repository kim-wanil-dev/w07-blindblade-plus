# 전투 로컬 로그 및 Google Sheets 자동 전송

### 기능 이름

- 기능 설명: BambooDefense의 현재 확정 사건을 세션별 JSON/JSONL로 저장하고 Apps Script 수신기로 자동 전송한다. 각 사건에 한국 표준시(+09:00) 절대시각을 기록한다. 빌드 기본 설정을 포함해 새 PC는 별도 CONFIG 없이 같은 시트로 전송한다.
- 동작 조건 및 처리 흐름: GameSceneInitializer 초기화 뒤 execution order200의 Recorder가 기존 사건 공급자를 구독한다. 값 스냅샷 → 한정 메모리 버퍼 → 백그라운드 원본 저장 → 전송 배치 → 서버 저장 확인 → URL별 디스크 커서 갱신 순서다. 경과 시간은 분석용 초 단위로 유지하고 절대시각은 KST ISO 8601 문자열로 별도 기록한다. Scene 전환 뒤에도 전송 서비스는 유지한다.
- 구현 상태: 로컬 저장·전송·수신기·기본 CSV 전처리·정식 씬 연결 구현. 로컬 CONFIG 경로에서 실제 Unity Play 전송400건 ACK를 확인했다. Resources의 활성 기본 설정과 로컬 파일이 없는 PC의 기본값 선택을 구현했다. 최신 JSONL과 CSV의 KST 저장을 확인하고, Google 웹 앱 버전 2를 배포해 실제 사건의 KST 열 저장을 확인했다. 새 PC 전송, 전체 백로그·장애/재도전은 미확인이다. D5 전체 완료를 뜻하지 않는다.

#### 연결 및 협업

- 연결된 기능: PlayerHealth, PlayerController, KatanaCombatCoordinator.Events, GameStateManager, BambooDefenseDirector, DefenseEnemySpawner, CombatThreatPresentationProvider, CombatSessionRuntime.
- 공유하는 코드 및 상태: 기존 API를 구독만 한다. 전투 판정·피해·시간·스폰 설정을 변경하지 않는다. `CombatTelemetryEnvelope`의 데이터와 ID를 저장한다.
- 중복 또는 충돌 사항: 현재 PlayerCombatEvents는 `BlindBlade.Combat.Contracts.DefenseResolution`을 사용한다. Recorder는 명시적 타입 별칭으로 공통 계약을 소비한다. 현재 공통 결과에는 DodgeId가 없으므로 방어 사건의 correlation.dodgeId는 0이다. 별도 dodge_changed 사건의 공급자 DodgeId는 그대로 보존한다. 다른 공급자 스크립트는 수정하지 않았다.
- 승인 필요 사항 및 결과: 사용자가 D5 저장·전송과 후속 CONFIG 없는 자동 전송을 요청했다. 정상 동작한 현재 URL/token을 배포 기본 에셋에 복사했다. Google 계정/원격 배포를 변경하지 않았다. 이전 원격 전송 확인 기록과 새 기본값 선택 기능 확인 범위는 아래를 따른다.

#### 설정·운영·지표

- [설치·Google 배포·테스터 PC 설정·전처리·오류 처리 안내](../../tools/combat_telemetry/README.md)를 따른다.
- 현재 기록: 세션/상태/준비 종료/표본, HP/실제 피해/사망, 행동/카타나 단계, 방어/회피/파동, 수리검 발사/투척 전조, 처치 수, C 위협 표시 상태/원본 발소리, 시간 배율.
- 실제 InputResolved 발행부와 스태미너·강화 공급자는 현재 없다. 계약 구독만으로 없는 기록을 생성하지 않는다. 실제 입력 시도 수·장치 시계 보정이 없으므로 early/late 및 입력 성공률은 산출 불가다. 선택지 이벤트도 아직 공급자가 없다.
- 피해 합계는 damage_applied.appliedDamage만 사용한다. resource_changed와 defense_resolved에 같은 감소가 있어도 중복 합산하지 않는다. parryCount/defenseCount는 접촉 중 패링 비율이며 시도 성공률이 아니다.
- runRealtimeSeconds는 준비·일시정지·포커스 이탈을 포함하고 GameOver 대기는 제외한다. combatRealtimeSeconds와 survivalGameSeconds를 함께 보존한다. 참가자별 총 체험 시간은 별도 참가자 매핑·재도전 합산 규칙이 필요하다.
- 익명 ID는 PC 설치 단위다. 동일 PC의 여러 참가자를 자동 구분하지 않는다.
- 저장 한도·실패에서 전투를 막지 않고 누락을 진단한다. 매 프레임 파일 쓰기/전체 객체 검색은 추가하지 않았다. 디스크 백그라운드 작업은 Unity 객체를 조회하지 않는다.
- 설정 우선순위: 로컬 upload-config.json이 있으면 우선 사용하며 enabled=false·파싱 오류를 기본값으로 우회하지 않는다. 없으면 Resources의 기본 에셋을 읽는다. 새 비활성 CONFIG는 자동 생성하지 않는다. 기존 CONFIG를 덮어쓰거나 삭제하지 않는다.
- 벽시각: `occurredAtKst`, `recordedAtKst`, `payload.startedKst`는 `yyyy-MM-ddTHH:mm:ss.fff+09:00` 형식이다. PC 시간대 설정과 무관하게 +09:00을 사용한다. 각 기록 시점의 한국시간과 realtime 차이로 사건 발생 시각을 계산한다. 기존 `occurredAt`/`recordedAt`의 realtime·gameplay·active 경과 초는 그대로 유지한다. 과거 JSONL의 UTC 또는 KST 필드가 없는 사건은 바꾸지 않는다.
- Sheets/CSV 호환: 새 출력에는 UTC 열을 만들지 않는다. 기존 Events/Sessions 시트의 `received_utc`와 `started_utc` 값은 KST로 변환해 같은 열에 저장한 뒤 헤더를 바꾼다. 오른쪽에 이미 추가된 KST 열은 값을 합쳐 제거한다. 이전 JSONL의 `startedUtc`는 CSV의 `started_kst`로 변환하지만 원본 파일은 수정하지 않는다. 과거 사건의 발생 KST는 원본에 없으면 빈 값이다. 2026-10-15에 운영 웹 앱 버전 2 배포와 `setupSheets` 실행을 완료했다.
- 배포 기본 에셋에 활성 여부·URL·공유 token을 포함한다. token은 Inspector에서 숨기고 출력하지 않지만 빌드에서 추출 가능하다. Google 계정 비밀번호나 서비스 계정 키를 포함하지 않는다. 배포 설정 변경 후 재빌드가 필요하다.

- 2026-10-15: 실제 접속 설정의 enabled=false를 true로 수정한 뒤 기존 로그1건 POST에서 HTTP200/ok=true/정확한 ACK를 확인했다. Unity Play 자동 전송에서도 확인400건·누락0·LastError=null과 디스크 커서를 관측했다. 확인 후 Play 종료, 실제 전송 설정은 활성 유지했다. Google 화면 직접 열람·전체 백로그/장애 검증은 하지 않았다.
- 2026-10-15 후속: CONFIG 없는 PC에서 배포 기본값을 사용하는 코드를 추가했다. Editor API로 기본 에셋 생성/저장, enabled=true·URL/token 설정됨을 비밀 값 출력 없이 확인했다. C# 재컴파일 오류0·경고0. 이번 수정 뒤 Play/Standalone 실행·새 PC 전송은 미확인이다.
- 2026-10-15 후속: JSONL 사건에 `occurredAtKst`/`recordedAtKst`, 세션 시작 메타데이터에 `startedKst`를 추가하고 CSV 및 Apps Script 열을 한국 표준시로 바꿨다. `realtimeSeconds` 등 기존 경과 시계는 유지하고, 기존 시트 UTC 열/데이터는 보존하면서 KST 열을 오른쪽에 추가하도록 했다. 이번 날짜 변경의 컴파일·Play·시트 표시는 미확인이다. Apps Script 새 버전 배포와 `setupSheets` 실행이 필요하다.
- 2026-10-15 KST 후속 확인: 위 초기 구현 기록 이후 UTC 출력 열을 제거했다. 운영 Apps Script 버전 2를 같은 URL로 배포하고 `setupSheets`를 완료했다. `Events!B1=received_kst`, `Sessions!D1=started_kst`이며 기존 `Events!B7816`의 `05:01:15.951Z`는 `14:01:15.951+09:00`으로 변환됐다. 실제 로컬 `session_started` 사건을 전송해 HTTP 200/ACK 1건을 받고 `Events!B7817=2026-10-15T14:11:25.273+09:00`, `V7817=W7817=2026-10-15T13:59:50.074+09:00`, `Sessions!D7=2026-10-15T13:59:50.067+09:00`을 확인했다. 이전 배포에서 비어 있던 `Sessions!D5:D6`도 원본 시작 사건 재전송으로 KST 값이 채워졌다. 로컬 CSV 내보내기 결과는 사건 12,783건, 세션 6건, 진단 0건이다. Unity 재컴파일은 최신 상태, 오류·경고 0건이었다. 과거에 수신하지 못한 사건별 발생·기록 KST는 시트에서 소급 생성하지 않는다.
