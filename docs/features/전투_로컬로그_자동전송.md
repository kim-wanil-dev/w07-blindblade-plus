#### 2026-10-16 전송 완료 로그 즉시 정리

- 사용자가 전송 완료 로그의 즉시 삭제를 승인했다. TelemetryDiskStore는 AppendAsync에서 작성 중인 세션을 추적하고 `session_ended`가 디스크에 저장되면 비활성으로 전환한다. 온보딩도 최종 종료 때 기존 허용 이벤트 `session_ended`를 한 번 기록한다. 단계 종료만으로 세션을 닫지는 않는다.
- AcknowledgeAsync는 검증된 ACK 커서를 먼저 저장한 뒤 비활성 세션의 커서가 현재 JSONL 전체 길이와 정확히 같을 때만 JSONL·메타데이터 JSON·해당 세션 커서를 삭제한다. 삭제한 현재 스키마 원본 용량은 저장 예산에서 차감한다. 미전송·부분 전송·작성 중인 파일은 보존한다.
- ReadBatchAsync는 이전 실행에서 남은 완전 ACK 파일도 같은 목적지 커서를 확인하여 정리한다. 구버전도 완전 ACK가 확인된 경우에만 삭제한다. 강제 종료로 남은 미확인 원본은 보존하며 새 실행에서 현재 스키마 기록의 재전송을 이어간다.
- 스프레드시트 데이터·공유 토큰·익명 ID는 삭제하지 않는다. 로컬 원본은 전송 확인 후 사라지므로 장기 분석·백업은 스프레드시트에서 한다. C# 컴파일 오류 0건, 기존 경고 2건. 실제 플레이 중 전송·삭제 순서의 실기 확인은 미확인이다.

#### 연결 및 협업

- 연결된 기능: 전투 입력·방어 판정, 일반 적 패턴, 보스 패턴, Stage1 진행, 자동 업로드.
- 공유하는 상태: 세션 ID·AttackId 발급은 CombatSessionRuntime, 전투 판정은 KatanaDamageReceiver, 스테이지 전환은 Stage1Controller, 분석 누적은 Recorder가 관리한다.
- 중복 또는 충돌 사항: 기존 InputResolved 생산자를 사용하고 별도 키보드 폴링을 추가하지 않는다. ID와 관측 신호를 추가하며 전투 피해 수치는 변경하지 않는다.
- 수리검 패턴명은 `DefenseShuriken`으로 통일한다. BambooThrower는 전조 시작 시 이 이름으로 Begin을 한 번 보내고 같은 AttackId를 투사체에 전달한다. 투사체 Launch는 전달된 ID를 재사용해 Commit만 보내며, 접촉 결과도 같은 패턴명으로 기록한다. 시작 신호를 제거하면 전조 시각이 발사 시각으로 늦춰져 반응 시간이 왜곡되므로 Begin은 유지한다.
- `TryThrowForOnboarding` 경로는 BambooThrower의 자동 발사 전조 루프를 거치지 않으므로 투사체 Launch가 `DefenseShuriken` 시작 신호를 직접 발급한다. 두 경로 모두 세션 집계에서는 같은 패턴으로 합산한다. 전조 도중 취소된 공격은 시작·취소 사건은 남지만 Commit이 없으므로 실제 발사 시도 수에는 포함하지 않는다.
- 기존 `BambooShuriken` 로그는 변경 전 데이터로 보존한다. 변경 이후 새 로그에는 이 패턴명이 생성되지 않는다.
- 승인 필요 사항 및 결과: 사용자가 전조→입력과 입력→접촉을 모두 선택했고 기존 로컬 로그와 Google Events·Sessions 삭제를 승인했다. 엔드포인트·공유 토큰·익명 PC ID는 유지한다.

#### 집계 규칙

- 1-1은 웨이브와 보스 경고, 1-2는 보스 활성화부터 사망/완료까지다. 보스 재도전은 1-1 행을 생성하지 않는다. Sessions의 키는 `sessionId:stageId`이며 구간마다 1행이다. 재전송은 최신 누적 값으로 덮어써 이중 합산하지 않는다.
- `deaths`는 도전당 0 또는 1. `activePlaySeconds`는 Playing 동안 실제 경과 시간으로 일시정지·게임오버 대기를 제외한다. 경고/등장 연출도 Playing이면 포함한다. 강제 종료는 최신 `in_progress` 요약만 남을 수 있다.
- `player_input.isAttempt=true`인 고유 InputId만 시도 수에 포함한다. Rejected도 시도다. GuardHoldResume·GuardRelease는 새 시도가 아니다. Buffered→Started는 1회다. 실제 회피 시작은 dodgeStarted로 별도 집계한다.
- 패리·퍼펙트 패리·가드·피격은 **접촉 수**다. 하나의 방어 입력이 여러 공격을 막을 수 있으므로 그 합을 방어 입력 수로 나눠 성공 확률로 해석하지 않는다. guardAttemptsWithContact/WithoutContact는 고유 입력 기준이다. guardHitCount는 가드 입력 후 버튼을 놓기 전에 맞은 접촉이며 거부된 가드 의도도 포함한다.
- enemyAttackCount는 실제 실행된 공격. enemyResolvedCount는 실행된 공격 중 종료된 결과이며 Cancelled/Interrupted는 제외한다. Hit/Resolved가 적중률이다. Dodge는 실제 회피 판정(극한 회피와 회피 무적)을 뜻한다. 이동으로 비켜나 접촉하지 않은 공격은 Miss다. Invulnerable은 회피 이외 무적, Destroyed는 플레이어 검기 등으로 수리검 제거, Ignored는 판정 제외다. 이 결과를 숨기거나 회피로 재분류하지 않는다.
- ranged/melee 및 bossRanged/bossEscapeBarrage/bossCharge 열에는 공격 시도·결과·피해·적중률·피해량 비중을 제공한다. 상위 분류와 보스 패턴 분류는 겹치므로 서로 더하지 않는다. 세부 패턴은 patterns_json과 Patterns.csv에 보존한다.
- 2026-10-17 보스 방어 반격: `CombatTelemetryRecorder` 요약에 `bossCounterSlash` 그룹(PatternId `BossCounterSlash`)을 추가했다. Apps Script(`Code.gs`)의 Sessions 열은 아직 추가하지 않아 시트에는 요약 열이 없고, Events 행과 patterns_json에는 pattern_id로 따로 남는다. 시트 열 추가는 사용자 결정으로 차후 작업이다. 반격 흐름은 [사운드 중심 보스전](사운드_중심_보스전.md)의 2026-10-17 절을 따른다.
- BossEscapeBarrage는 4초 안에 30 이상의 누적 피해를 받으면 발동하는 도주 난사다. 각 수리검마다 별도 공격 ID를 사용해 발사 시도를 분모로 하고 접촉 판정 또는 수명 만료 Miss를 결과로 센다. bossEscapeBarrage 집계 열은 도주 난사의 피해·결과를 BossRanged와 분리한다. 기존 BossRanged로 저장된 로그는 난사와 기본 수리검을 구분할 수 없다.
- 피해량 비중=패턴 적용 피해/전체 적용 피해. 피격 횟수 비중=패턴 피해 접촉 수/전체 피해 접촉 수. 분모 0은 빈 값이며 0%로 취급하지 않는다. 전체 통합 비율은 세션 비율의 평균 대신 분자 합/분모 합을 사용한다.
- 반응은 같은 엔진 realtime 시계의 패턴별 기준 신호→입력 처리 프레임으로 계산한다. 대부분은 전조 시작이며, 2막 짐승 물기(`TwinBeastBite`)는 돌진 중 눈 섬광(`PounceGlint`) 시점이다. 원시 deviceTime도 보존하지만 보정 없이 서로 빼지 않는다. 입력→접촉은 정확한 AttackId의 접촉 시점과 연결된 입력의 차이다. 기준 신호보다 먼저 누른 입력은 reactionSeconds가 빈 값이다.
- reaction_candidate는 입력 당시 살아 있는 모든 전조/비행 공격의 시간상 후보다. 여러 후보 중 어느 공격을 보고 반응했는지는 단정하지 않는다. 최종 접촉의 reactionAssociation=resolved_contact를 우선 분석하며 held_guard_intent는 실패한 가드 의도 추정이다. 현재 평균은 이 두 접촉 연결을 포함한다.
- 좌표는 월드 XZ, 단위 m. movement_sample.durationSeconds로 시간 가중 이동 히트맵을 만든다(기본 0.5초). player_input의 Attack/isAttempt로 공격 시도 히트맵, enemy_attack_resolved의 appliedDamage>0 접촉 위치로 피격 히트맵을 만든다. 원거리는 origin→position 직선이며 유도 곡선 궤적이 아니다.
- 전투 분석에 불필요한 발소리·HUD 프레임 변경·자원/연출 로그는 이 스키마에서 발송하지 않는다. 시간 표기는 KST 유지. 로컬 파일은 세션별 JSONL이며 Sessions는 구간별 요약 사건으로 만든 서버/CSV 보기다.

- 사용자 요구에 따라 변경 적용 이전의 과거 세션은 앞으로 자동 전송하지 않는다. 일반 런타임과 Editor 업로더 모두 현재 실행에서 기록한 sessionId만 읽으며, 남은 과거 파일은 전송 대기열에서 제외한다. 범위 제한을 적용하기 전 수동 재전송으로 과거 세션 2개가 전체 ACK되어 기존 보관 정책에 따라 원본 파일이 정리됐고, 세 번째 세션 일부가 ACK된 뒤 전송을 멈췄다.
#### 2026-10-22 중요 이벤트 업로드 즉시 요청

- `RequestFlush()`는 일반 이벤트를 즉시 로컬 저장하고 정기 전송 주기를 앞당기지만, 직전 네트워크 오류가 설정한 20초 재시도 대기는 유지한다.
- 사망, 인게임/앱 일시정지, `stage_ended`, `game_completed`, 세션 종료는 `RequestFlushImmediately()`를 호출한다. 이 요청은 재시도 대기를 우회해 저장 완료 후 즉시 전송을 시작하며, 이미 전송 중인 요청이 실패해도 긴급 요청을 유지해 이어서 보낸다.
- HTTP 요청과 ACK 대기는 비동기다. 즉시 전송은 첫 시도를 앞당기는 동작이며, 서버·네트워크 오류나 로컬 저장 실패까지 성공을 보장하지 않는다. 즉시 시도도 실패하면 다음 재시도는 20초 간격을 따른다.
- Unity Editor 컴파일 오류 0건·경고 0건. 플레이 중 실전 이벤트 전송은 미검증이다.
