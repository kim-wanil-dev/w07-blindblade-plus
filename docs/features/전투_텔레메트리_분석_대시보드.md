# 전투 텔레메트리 분석 대시보드

### 기능 이름

- 기능 설명: 온보딩, 일반 전투, 보스전 텔레메트리를 시각화해 플레이 의도와 플레이어 행동을 비교한다. 전장 히트맵은 2m 격자와 원거리 공격 결과별 색상 선을 표시하며, 온보딩 이탈 지점과 보스 패턴별 피해·판정·반응 시간도 제공한다. 비공개 Sites URL은 `https://blindblade-combat-analysis.wan1k.chatgpt.site`다.
- 동작 조건 및 처리 흐름: 페이지 진입 시 Sites Worker가 서버에서 Apps Script 읽기 API로 POST 요청을 보내 Events·Sessions·OnboardingSteps의 분석 필드만 읽는다. 연결이 준비되지 않았을 때는 사용자가 Google Sheets 탭별 CSV 또는 `Export-Telemetry.ps1`로 생성한 CSV를 선택해 브라우저에서 분석할 수 있다.
- 구현 상태: 대시보드 Worker를 소유자 전용 Sites 버전 5로 배포했고, 기존 Apps Script 웹 앱 버전 7과 URL을 유지한다. Apps Script 실행 계정과 `Anyone` 액세스 설정은 기존 값 그대로다. 두 위치의 동일한 `DASHBOARD_READ_TOKEN` 설정과 자동 읽기를 기존 배포에서 확인했다. 사이트와 스프레드시트의 기존 접근 범위는 유지한다.

#### 연결 및 협업

- 연결된 기능: [전투 로그 및 Google Sheets 자동 전송](전투_로컬로그_자동전송.md)의 현재 온보딩 0-1~0-5 및 과거 0-1~0-7·1-1·1-2 데이터와 CSV 전처리기.
- 공유하는 상태: 대시보드 상태는 페이지 메모리에만 둔다. CSV 행과 지표를 서버로 보내거나 브라우저 저장소에 기록하지 않는다.
- 중복 또는 충돌 사항: Events·Sessions·OnboardingSteps는 필수 권장 입력이다. Patterns·Heatmaps·Diagnostics를 추가로 올릴 수 있으며, 이미 제공된 Events로 같은 히트맵을 다시 계산할 수도 있다.
- 승인 필요 사항 및 결과: 자동 연결용 `DASHBOARD_READ_TOKEN`은 Apps Script Script Properties와 Sites 런타임 secret에 설정되어 있다. 토큰 값은 소스와 문서에 저장하지 않는다. 스프레드시트 접근 범위는 소유자로 제한하고 게임 업로드용 `UPLOAD_TOKEN`과 분리한다.

#### 집계 규칙

- Sessions를 구간별로 묶어 도전 수·사망 합계·사망률·평균 처치 횟수·평균 사망 횟수·평균 활성 플레이 시간을 표시한다. 평균 처치·사망은 각 수치가 기록된 Sessions 행을 평균 분모로 삼으며, 필터링된 1-1·1-2 행에 적용된다. 사망률은 사망 수/도전 수다.
- 피해 원인은 Events의 enemy_attack_resolved에서 실제 적용 피해(applied_damage)를 pattern_id별로 합산한다. BossRanged는 ‘보스 수리검’, BossEscapeBarrage는 ‘보스 도주 난사’, BossCharge는 ‘보스 돌진’, BossTripleSlash는 ‘보스 삼연속 베기’로 표시하며, Events가 없을 때는 Sessions의 일반·보스 피해 합계를 사용한다.
- 온보딩은 OnboardingSteps의 목표 행으로 활성 시간, 첫 입력, 행동 시도, 오입력, 이동 시도, 재도전, 종료 이유를 표시한다. CSV와 Apps Script 응답의 숫자는 문자열로 전달되므로 표시 전에 숫자로 변환한다.
- 세션별 마지막 온보딩 진행 지점은 OnboardingSteps를 run_id별로 묶고 step_index·objective_index가 가장 큰 목표 행을 표시한다. 단계 필터는 해당 단계가 기록된 실행을 고른 뒤 그 실행의 가장 뒤 진행 지점을 보여준다. 표시되는 reason은 목표 행의 기록 사유이며, 실제 프로그램 종료 원인을 단정하지 않는다. OnboardingSteps 응답에 이미 필요한 열이 있으므로 Apps Script API 열을 추가하지 않는다.
- Events의 enemy_attack_resolved에서 outcome별 적 공격 결과 및 적중률을 집계한다. BossEscapeBarrage의 attack_id는 발사 수리검마다 다르므로 난사 묶음이 아닌 개별 수리검의 결과로 집계한다. BossRanged·BossEscapeBarrage·BossCharge·BossTripleSlash 등 알려진 패턴은 한글 이름으로 표시하고, reaction_seconds 분포는 pattern_id별 구간 표로 나눈다. input_to_contact_seconds는 전체 평균으로 유지한다.
- 2026-10-16 이후 새 로그는 도주 난사를 BossEscapeBarrage로 기록한다. 이전 로그의 도주 난사는 BossRanged로 합쳐져 있어 기존 행만으로는 분리할 수 없다.
- Heatmaps.csv는 stage_attempt_id별 stage·layer·격자 좌표·가중치 합계다. 구간 필터는 직접 적용한다. 빌드·날짜·Editor 필터는 Heatmaps.csv 자체에 관련 열이 없으므로 Sessions를 함께 불러온 경우 해당 Sessions의 stage_attempt_id만 남긴다. Sessions가 없을 때는 필터를 정확히 적용할 수 있는 Events.csv에서 다시 계산한다.
- 전장 히트맵은 `BambooStage1`의 `Arena` 원점인 월드 `(0,0)`을 화면 중앙에 고정하고 2m × 2m 격자로 표시한다. Heatmaps.csv의 1m 셀은 화면에서 2m 셀로 합산한다. 대나무 666개가 거의 원형으로 배치되어 있어 반경 약 25~33m의 벽 띠와 줄기 표시로 근사한다. 이 오버레이는 지형 읽기를 위한 참고이며 각 나무의 충돌 좌표는 아니다.
- 현재 온보딩 `stageId`는 0-1~0-5다. 이전 7단계 기록의 0-6·0-7 값과 초기 `onboarding-2026-10-16` 설정의 0-1/0-2 로그는 구버전 행으로 보존한다. 초기 설정 로그는 복수 단계를 합친 의미여서 기본 제외하며, `이전 2구간 온보딩 로그 포함`을 켜면 과거 행임을 별도로 표기한다.
- 원거리 공격 선은 Events의 origin_x/origin_z에서 x/z로 연결한다. 적중은 빨강, 패링은 금색, 빗나감은 밝은 회색, 회피는 파랑으로 표시하며 실제 유도 궤적을 뜻하지 않는다.
- 스프레드시트 CSV를 불러올 때 각 탭을 개별 CSV로 저장한 뒤 한 번에 선택한다. 로컬 JSONL을 쓸 경우 README의 전처리 명령으로 CSV를 만든다.

#### 자동 연결 보안 구조

- 정적 페이지는 Google 로그인 세션이나 서비스 계정을 갖지 않는다. 시트 URL을 아는 것만으로 소유자 전용 데이터를 가져올 수 없다.
- 시트 공유를 링크 공개로 바꾸면 Sites 서버에 권한을 준 것이 아니라 데이터가 링크 보유자에게 공개된다. 이 프로젝트의 플레이 로그에는 권장하지 않는다.
- Apps Script `doPost`의 `dashboard_snapshot` 경로는 별도 `DASHBOARD_READ_TOKEN` Script Property를 검증하고 Events·Sessions·OnboardingSteps의 허용 열만 JSON으로 반환한다. 2026-10-16에 기존 URL의 웹 앱 버전 7로 배포했다. OnboardingSteps가 이미 `run_id`, 단계·목표 인덱스, `reason`을 반환하므로 이번 세션별 진행 위치 표에는 Apps Script 재배포가 필요하지 않다. 게임 전송의 `UPLOAD_TOKEN`과 분리한다.
- Sites Worker는 브라우저 요청의 Sites 사용자 인증을 확인한 뒤 서버에서 Apps Script URL로 POST하고, 키를 런타임 secret `DASHBOARD_READ_TOKEN`으로만 읽는다. 브라우저에는 키를 전달하지 않는다. Apps Script 웹 앱은 요청을 받을 수 있어야 하며, 읽기 핸들러가 별도 토큰을 반드시 검증해야 한다.
- 2026-10-16 확인: 배포 사이트가 자동 연결 상태를 표시하고 Sheets API에서 Events·Sessions·OnboardingSteps를 가져왔다. 현재 세 탭은 각각 0행이라 지표는 표본 부족 상태다. 비로그인 호출 거부, 행 제한과 장기 데이터 누락 여부는 별도 점검 대상이다.

- 2026-10-16: Sites 버전 4와 Apps Script 웹 앱 버전 7의 배포가 `succeeded`로 확인됐다. 배포 URL은 `https://blindblade-combat-analysis.wan1k.chatgpt.site`이고 기존 웹 앱 URL도 유지했다. Worker ESM 생성·아티팩트 검증, 브라우저 자동 연결, 7단계 필터, (0,0) 중앙과 대나무 벽 근사 표시를 확인했다. 데이터 행은 당시 0건이었다.
- 2026-10-16: 2m 히트맵 격자와 원거리 결과 색상, 한글 보스 패턴 피해·결과, 패턴별 반응 시간 표, 숫자 문자열 포맷 보정, OnboardingSteps의 run_id별 마지막 단계·목표 표를 소스 커밋 `7239122534d7de090b1b6336eb3c48f596057154`으로 Sites 버전 5에 배포했다. Worker 생성과 ESM 아티팩트 검증이 통과했고, Sites 배포 결과는 `succeeded`다. 실제 세션 행을 이용한 브라우저 렌더링은 이번 배포에서 별도로 확인하지 않았다.
- 2026-10-16: `BossEscapeBarrage` 라벨을 피해 원인·패턴별 공격 결과·반응 시간에 추가했다. 게임 로그는 난사 수리검별 `pattern_id`와 `attack_id`를 기록한다. 기존 `BossRanged` 로그는 사후 분리할 수 없다. 이 변경의 대시보드 라벨은 Sites 버전 6에 포함해 배포했다.

Sites 버전 6 배포는 `succeeded`이며 소스 커밋은 `9051745f74520d497d0f0500f6732c52468fbfd6`, URL은 `https://blindblade-combat-analysis.wan1k.chatgpt.site`다.
