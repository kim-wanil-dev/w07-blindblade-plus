# 전투 텔레메트리 분석 대시보드

### 기능 이름

- 기능 설명: 온보딩, 일반 전투, 보스전 텔레메트리를 시각화해 플레이 의도와 플레이어 행동을 비교한다. 전장 히트맵은 2m 격자와 원거리 공격 결과별 색상 선을 표시하며, 온보딩 이탈 지점과 보스 패턴별 피해·판정·반응 시간도 제공한다. 통합 쌍둥이 보스는 일반 패턴 결과에 포함한다. 운영 URL은 `https://blindblade-combat-analysis.wan1k.chatgpt.site`이며 현재 Sites 접근 모드는 `public`이다.
- 동작 조건 및 처리 흐름: 페이지 진입 시 Sites Worker가 서버에서 Apps Script 읽기 API로 POST 요청을 보내 Events·Sessions·OnboardingSteps의 분석 필드만 읽는다. 연결이 준비되지 않았을 때는 사용자가 Google Sheets 탭별 CSV 또는 `Export-Telemetry.ps1`로 생성한 CSV를 선택해 브라우저에서 분석할 수 있다.
- 구현 상태: Sites v26이 운영 중이며 공개 URL과 기존 공개 범위를 유지한다. R2 공유 캐시·Events 증분 조회·전역 임대를 운영에 사용한다. 전체요약은 구간 합계·공격 패턴 결과·플레이어 누적 시간과 이탈 통계를 기본 표시하고, 세션 및 플레이어별 상세는 접어서 연다. Apps Script 웹 앱 v17을 2026-10-22 기존 운영 URL에 배포했으며 실행 주체(소유자 계정)와 모든 사용자 접근 권한을 유지했다. 실제 시트 저장/ACK는 미확인이다.

#### 2026-10-22 극한 회피 발동 공격 연결

- `PlayerDodgeEvent.PerfectDodge`의 `AttackId`가 가리키는 공격을 극한 회피를 유발한 공격으로 본다. 해당 공격의 최종 결과를 `PerfectDodge`로 기록하고 이벤트 상관관계에 `dodgeId`도 보존한다.
- 회피가 끝나기 전에 발생한 해당 구간의 공격 접촉·종료 결과는 회피 종료까지 대기해 잔상 회피 보상도 발동 공격에 연결한다. 기존 접촉 판정 `defenseOutcome=DodgeAvoided`도 같은 `PerfectDodge` 결과로 유지한다.
- 전체요약은 `dodge_changed`의 양수 `attack_id`로 이미 수집된 `enemy_attack_resolved`를 연결해 극한 회피 결과를 바로잡는다. 원본 Events와 Sessions는 소급 변경하지 않는다.
- 회피 동작은 `DodgeId`, 적 공격 결과는 `AttackId` 단위로 각각 한 건씩 집계한다.

#### 선택 빌드의 패턴 합산·플레이어별 시간·사망 시 피격 분석

- `패턴별 공격 결과`는 선택한 모든 빌드의 같은 `pattern_id`를 한 행으로 합산한다. 열은 패턴명, 전체 결과, 유효 판정, 적중, 회피, 퍼펙트 패링, 방어, 빗나감, 취소, 중단, 유효 판정 적중률이다. 빌드 열·일반 패링 열·시작/실행/ID 연결 진단 열은 이 표에서 표시하지 않는다. 반응 시간 표는 기존의 빌드별 분리를 유지한다.
- 전체 결과는 중복 제거한 `enemy_attack_resolved` 수이며, 유효 판정은 취소·중단을 제외한 모든 결과다. 일반 패링과 기타 판정도 유효 판정 분모에는 포함된다. 적중률은 합산된 적중 수 / 합산된 유효 판정 수이며 빌드별 비율을 평균하지 않는다. Patterns.csv만 입력하면 전체 결과·취소·중단이 없어 `미수집`으로 표시한다.
- 전체 요약의 `플레이어별 총 플레이시간`은 전체 익명 ID를 키로 도전별 최신 Sessions를 중복 제거한 뒤 `active_play_seconds`를 합산한다. 구간·빌드·날짜·Editor·과거 온보딩 필터를 적용하고 시:분:초로 표시한다. 시간 누락은 0초로 만들지 않으며 ID 없는 도전은 한 플레이어로 합치지 않는다. 같은 PC의 여러 참가자 또는 ID 초기화 전후는 실제 사람과 일대일 대응하지 않을 수 있다.
- 전투 판정의 `사망할 때 맞은 공격`은 사망 이벤트마다 같은 도전의 실제 피해량이 0보다 큰 최종 공격 결과를 연결한다. 같은 realtime 시계를 우선하고 없으면 occurred_at_kst를 쓴다. 사망 전후 0.1초의 피해를 모두 후보로 표시해 사망 콜백 뒤 최종 피해가 기록되는 순서를 허용한다. 동시 후보가 없으면 사망 전 마지막 피격을 추정으로 표시하며 간격도 보여 준다. 치명타 ID가 없는 기존 로그에서 원인을 확정하지 않는다. 시계·피해·공격 기록이 없으면 연결 불가다.
- 게임 코드·생산자·전송 형식·원본 시트 행은 수정하지 않는다. 기존 자동 연결 API의 Sessions 응답에는 `anonymous_player_id`가 빠져 있어 플레이어별 자동 집계에는 읽기 허용 열 추가가 필요하다. 해당 범위 포함 여부를 사용자에게 질문했으며 현재 답변 대기다. ID를 포함한 원본 Sessions.csv에서는 사이트 구현만으로 집계한다.

#### 연결 및 협업

- 연결된 기능: [전투 로그 및 Google Sheets 자동 전송](전투_로컬로그_자동전송.md)의 현재 온보딩 0-1~0-5 및 과거 0-1~0-7·1-1·1-2 데이터와 CSV 전처리기.
- 공유하는 상태: 대시보드 상태는 페이지 메모리에만 둔다. CSV 행과 지표를 서버로 보내거나 브라우저 저장소에 기록하지 않는다.
- 중복 또는 충돌 사항: Events·Sessions·OnboardingSteps는 필수 권장 입력이다. Patterns·Heatmaps·Diagnostics를 추가로 올릴 수 있으며, 이미 제공된 Events로 같은 히트맵을 다시 계산할 수도 있다.
- 승인 필요 사항 및 결과: 자동 연결용 `DASHBOARD_READ_TOKEN`은 Apps Script Script Properties와 Sites 런타임 secret에 설정되어 있다. 토큰 값은 소스와 문서에 저장하지 않는다. Apps Script 웹 앱은 소유자 실행·모든 사용자 접근 설정으로 동작하며 별도 읽기 토큰을 검사한다. Google Spreadsheet 자체는 비공개로 유지한다. Sites 프로젝트 접근 모드는 현재 `public`이며 Worker는 `oai-authenticated-user-id` 헤더의 존재를 검사하지만 소유자 ID 허용 목록은 검사하지 않는다. 따라서 자동 연결된 대시보드 데이터는 해당 공개 Site의 인증된 방문자가 요청할 수 있다. 이 작업에서는 기존 접근 범위를 변경하지 않았다.

#### 집계 규칙

- `이탈 분석`은 `stage_attempt_id`별 최신 `last_event_sequence` 요약만 사용한다. ID가 없으면 `session_id + stage_id`를 사용하며 식별자가 전혀 없는 행은 서로 합치지 않는다. 구간·빌드·날짜·Editor 필터를 적용한다. 날짜 필터는 구간 시작일(KST) 기준이다.
- 중도 종료는 Sessions `status=application_quit`, 또는 해당 도전에 연결된 Events `session_ended / reason=application_quit`로 확인한다. `death` 상태에서 종료 이벤트가 있으면 ‘사망 후 게임 종료’, `cleared` 또는 쌍둥이 전체 처치 후 종료는 ‘구간 완료 후 게임 종료’다. 완료 후 종료는 중도 종료의 분자에서 제외한다. 사망만 있거나 다음 구간에 도달하지 않은 기록은 중도 종료로 단정하지 않는다.
- 도전 기준 중도 종료율 = 확인된 중도 종료 도전 수 / 완료·사망·종료가 확정된 도전 수. 진행 중, 씬 이탈 등 종료 여부가 미확정인 도전은 별도로 표시하고 비율 분모에서 제외한다. 이는 참가자 기준 영구 이탈률이 아니다. `run_id`는 종료 후 이어 하기에서도 유지될 수 있으므로 `run_id`별 최종 행 하나로 합치지 않고 과거 종료 도전도 유지한다.
- 종료 시간대는 해당 구간 진입 후 `active_play_seconds`로 30초 미만, 30초~1분, 1~2분, 2~3분, 3~5분, 5~10분, 10분 이상을 구분한다. 일시정지·사망 후 대기 시간은 포함하지 않는다. 0초는 유효 표본이며 누락 시간은 분포에서 제외하고 누락 수를 표시한다. 게임 전체 누적 시간은 아니다.
- 종료 상세는 최근 50건에 구간·상황·활성 시간·처치·사망·빌드·세션 ID를 표시한다. 종료 KST는 종료 이벤트의 `occurred_at_kst`만 사용하고, 이벤트가 없으면 ‘종료 이벤트 미수집’으로 표시한다. 시작 시각에 활성 시간을 더해 실제 종료 시각으로 만들지 않는다. Events를 아직 불러오는 중에도 Sessions의 종료 상태를 먼저 표시하며, 나중에 사망 후 종료와 정확한 종료 시각을 보충한다. 기존 읽기 API 열을 사용하므로 Apps Script 재배포나 Unity 새 빌드는 필요하지 않다.
- 기존 진행 퍼널은 ‘저장 진행별 스테이지 도달 / 이전 지점 대비 미도달’로 표시해 확인된 게임 종료와 구분한다.

- Sessions를 구간별로 묶어 도전 수·사망 합계·사망률·평균 처치 횟수·평균 사망 횟수·평균 활성 플레이 시간을 표시한다. 평균 처치·사망은 각 수치가 기록된 Sessions 행을 평균 분모로 삼으며, 필터링된 1-1·1-2 행에 적용된다. 사망률은 사망 수/도전 수다.
- 피해 원인은 Events의 enemy_attack_resolved에서 실제 적용 피해(applied_damage)를 pattern_id별로 합산한다. BossRanged는 ‘보스 수리검’, BossEscapeBarrage는 ‘보스 도주 난사’, BossCharge는 ‘보스 돌진’, BossTripleSlash는 ‘보스 삼연속 베기’로 표시하며, Events가 없을 때는 Sessions의 일반·보스 피해 합계를 사용한다.
- 온보딩은 OnboardingSteps의 목표 행으로 활성 시간, 첫 입력, 행동 시도, 오입력, 이동 시도, 재도전, 종료 이유를 표시한다. CSV와 Apps Script 응답의 숫자는 문자열로 전달되므로 표시 전에 숫자로 변환한다.
- 세션별 마지막 온보딩 진행 지점은 OnboardingSteps를 run_id별로 묶고 step_index·objective_index가 가장 큰 목표 행을 표시한다. 단계 필터는 해당 단계가 기록된 실행을 고른 뒤 그 실행의 가장 뒤 진행 지점을 보여준다. 표시되는 reason은 목표 행의 기록 사유이며, 실제 프로그램 종료 원인을 단정하지 않는다. OnboardingSteps 응답에 이미 필요한 열이 있으므로 Apps Script API 열을 추가하지 않는다.
- Events의 enemy_attack_resolved에서 outcome별 적 공격 결과 및 적중률을 집계한다. BossEscapeBarrage의 attack_id는 발사 수리검마다 다르므로 난사 묶음이 아닌 개별 수리검의 결과로 집계한다. - 정적 페이지는 Google 로그인 세션이나 서비스 계정을 갖지 않는다. Google Spreadsheet 자체는 비공개지만 Site의 공개 설정과 Worker 접근 검사는 별개다.
