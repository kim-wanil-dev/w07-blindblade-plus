### 대숲 스테이지 1

#### 2026-10-15 보스 체크포인트 재도전

- Stage1에서 근접 적 5명을 처치하고 보스가 실제 활성화되면 `BambooStage1Progress`가 `PlayerPrefs`에 보스 체크포인트를 저장한다. 이 저장값은 씬 재로드와 게임 재실행 뒤에도 유지한다. 보스 경고 도중 사망해 아직 보스가 켜지지 않았다면 저장하지 않는다.
- 저장값이 있는 Stage1 재로드에서는 `BambooStage1Controller.Start`가 일반 적 웨이브를 즉시 종료한다. 플레이어는 공터 중앙에 두고, 씬 시작 시 바라보는 수평 방향의 공터 끝에서 중심까지 NavMesh 경로가 연결된 가장 바깥 지점에 보스를 배치한다. 현재 설정의 `Arena` 반경 23.6m, `Edge Inset` 2m에서 목표 거리는 중심으로부터 21.6m다. 경고 대기 없이 보스가 활성화되는 순간 첫 등장과 같은 빨간 파동을 시작한다. 재도전에서는 카메라를 흔들지 않는다.
- 2026-10-15 재도전 시점·파동: 보스 재도전에서만 `PlayerPerfectPulse.SuppressStartPulse`로 플레이어 발밑의 자동 흰 시작 파동을 생략한다. 보스 배치 뒤 `PlayerMotor.FaceTarget`이 플레이어의 좌우·상하 시점 상태와 카메라 회전을 보스 몸체 중앙으로 맞추고 남아 있는 시점 입력을 지운다. 첫 보스 진입과 일반 웨이브 시작의 흰 파동, 전투 중 패링·회피·걸음 파동은 유지한다. 붉은 보스 등장 파동은 그대로 재생한다.
- 첫 보스 진입은 기존 5명 처치, 경고, 먼 지점 등장 연출을 유지한다. 저장값이 있어도 재도전 위치를 찾지 못하면 오류를 출력하고 일반 웨이브를 유지한다. 보스 사망 뒤 스테이지 2 이동은 아직 연결하지 않는다.
- 에디터 메뉴 `Tools > Blind Blade > Reset Stage Progress`는 에디터 Play에 사용하는 로컬 Stage1 체크포인트 키만 삭제한다. 다음 씬 로드부터 다시 일반 웨이브로 시작하며 음량 등 다른 `PlayerPrefs`는 지우지 않는다. 별도 Windows 빌드의 플레이어 설정은 이 에디터 메뉴의 대상이 아니다.
- 코드: `Assets/Scripts/Defense/BambooStage1Controller.cs`의 `Start`, `TryFindBossRetryPosition`, `ActivateBoss`; `Assets/Scripts/Defense/BambooStage1Progress.cs`의 `MarkBossCheckpointReached`, `Clear`; `Assets/Editor/BambooStage1ProgressTools.cs`의 `ResetStageProgress`. 재도전 버튼과 `GameStateManager.Restart`는 기존 씬 재로드 흐름을 사용한다.
- 확인: 시작 플레이어 위치는 공터 중앙 (0, 0, 0), 초기 시선은 +Z, +Z 방향 21.6m의 NavMesh 표본은 유효하다. Unity Editor 재컴파일 오류 0건, 외부 C# 빌드 오류 0건(기존 경고 2건). 실제 사망 후 재도전 Play 확인은 미실시다.

#### 2026-10-15 보스 이동 파동·수리검·공터 경계

- 보스가 재배치·돌진 등으로 실제 이동해 걸음 거리를 채우면 `BossPresentation`이 기존 발자국과 함께 빨간 지면 파동을 낸다. `Movement Ripple`의 반경(기본 8m), 확산 시간(0.9초), 링 수(2), 간격(0.12초), 잔상(1.2초), 색을 Inspector에서 조절한다. 빠른 이동 중 과도하게 겹치지 않도록 `Movement Ripple Interval`의 기본 0.45초 간격을 둔다. 이동하지 않거나 순간이동할 때는 파동을 내지 않는다.
- `Boss_SoundDuel`의 원거리 투사체를 공용 `Shuriken3`에서 전용 `BossShuriken`으로 교체했다. 외곽 투척수의 `DefenseShuriken`처럼 `OutlineLayer` Threat와 `MovingPerceptionReveal`을 사용해 빨간 위협 실루엣으로 표시한다. 보스 전용 프리팹의 `Homing Turn Rate`는 20도/초로 외곽 수리검의 45도/초보다 약하고, 플레이어 3m 이내에서는 직진한다. 패링으로 반사되면 빨간 위협 분류와 유도가 해제된다. 일반 적이 사용하는 `Shuriken3`는 직진을 유지한다.
- Stage1이 보스를 켜기 전에 `BossController.ConfigureArena`에 `Arena`와 `Edge Inset`(기본 2m)을 전달한다. 보스는 원형 공터 안의 NavMesh 목적지와 경로만 선택하며, 빠른 재배치 및 돌진 이동도 반경 안으로 제한된다. `DefenseArenaBoundary`의 플레이어 제한은 유지한다. 다른 씬에서 별도 설정 없이 쓰는 보스는 기존 이동 범위를 유지한다.
- 확인: `dotnet build Assembly-CSharp.csproj --no-restore` 오류 0건(기존 경고 2건), Unity Editor 재컴파일 오류 0건. 열린 Stage1 씬은 dirty=false였고, 보스 프리팹의 투사체 연결·유도 20도/초·이동 파동 반경 8m·Threat 컴포넌트를 확인했다. 씬의 대나무 666개의 중심점은 공터 중심에서 최소 24.39m이고 보스 이동 상한은 21.6m다. 실제 Play에서 색·파동·경계 체감 확인은 아직 수행하지 않았다.

#### 2026-10-15 보스 등장 파동 강화

- 보스 등장 순간 반경 48m의 빨간 파동을 0.32초 간격으로 3번 낸다. 한 파동은 반경이 조금씩 다른 기존 `Wave/Wave` 링 5장을 겹쳐 약 2m의 굵기를 만든다. 각 링은 1.5초 동안 확산하며 기존 프리팹의 색·반경·수명 설정은 바꾸지 않는다.
- `BambooStage1Controller` Inspector에서 Entrance Wave Radius, Thickness, Count, Interval, Duration을 조절한다. 카메라 흔들림은 기존 등장 순간 한 번 유지한다.
- 반사 수리검의 피해는 `DefenseShuriken`의 Reflect Damage=10으로 별도 설정한다. 일반 적 10 HP에는 한 발이 치명적이고 보스 200 HP에는 10만 감소한다.

#### 2026-10-15 밸런스와 보스 등장 갱신

- 일반 몬스터 프리팹 4종의 최대 HP를 10으로, `Boss_SoundDuel`의 최대 HP를 200으로 설정했다. `DefenseMelee`는 일반 근접 프리팹의 10 HP를 상속한다.
- 보스 등장 위치는 `Arena`의 원형 경계 반경에서 2m 안쪽을 기준으로 탐색한다. 플레이어와 반대 방향부터 원주 32방향과 안쪽 2개 고리를 검사하고, NavMesh에서 플레이어에게 경로가 닿는 후보 중 수평 거리가 가장 먼 지점을 선택한다. 기존 시선 앞 10m 탐색은 사용하지 않는다.
- 경고 2초 뒤 보스를 활성화할 때 기존 `Wave/Wave` 링을 보스 위치에서 빨간색·반경 48m·1.5초로 세 번 재생하고 플레이어 카메라를 0.55초 동안 흔든다. 파동 반경·굵기·횟수·간격·색·지속 시간과 흔들림 크기·시간·주파수는 `BambooStage1Controller` Inspector에서 조정한다.
- 보스 사망은 완료 상태까지만 기록하며 스테이지 2 전환은 연결하지 않았다.

- 기능 설명: BambooDefense를 복제한 BambooStage1에서 근접 적 5명 처치 뒤 경고를 표시하고 기존 단일 보스를 등장시킨다.
- 동작 조건 및 처리 흐름: BambooDefenseDirector.Kills가 Inspector 설정 처치 수에 도달하면 일반 웨이브를 종료한다. 경고 표시가 끝난 뒤 원형 공터의 NavMesh 후보 중 플레이어에게 가장 먼 유효 위치에서 Boss_SoundDuel을 활성화한다. 보스 사망은 스테이지 완료 상태로 기록한다.
- 구현 상태: BambooStage1 씬 복제, 처치 5명 문턱, 일반 웨이브 정리, 2초 경고, 단일 보스 프리팹·체력바·NavMesh 등장, 보스 사망 완료 상태를 구현했다. Stage1 씬은 빌드 목록에 추가했다. 스테이지 2 씬 생성·전환은 이번 범위에서 제외한다.

#### 연결 및 협업

- 연결된 기능: 대숲 방어, 기존 사운드 중심 보스전, 게임 씬 공통 구성, 전투 HUD.
- 공유하는 코드 및 상태: 일반 적 처치 수는 BambooDefenseDirector, 스테이지 전환 단계는 BambooStage1Controller, 보스 체력·사망은 EnemyHealth가 소유한다.
- 중복 또는 충돌 사항: 기존 BambooDefense 씬·프리팹 동작은 변경하지 않는다. 스테이지 2 목적지와 전환은 연결하지 않는다.
- 승인 필요 사항 및 결과: 사용자가 보스 복귀와 BambooStage1 구현을 요청했다. 추가 선택값은 근접 적 5명, 경고 2초, 일반 웨이브 정리, 플레이어 앞 NavMesh 등장으로 정했다.

#### Inspector 설정과 진행 수명

- `BambooStage1Controller`의 Required Kills=5, Warning Duration=2초, Edge Inset=2m, Spawn Sample Radius=2m를 조정할 수 있다. 공터 가장자리부터 플레이어에게 가장 먼 유효 NavMesh 경로를 탐색한다. 유효 위치를 못 찾으면 오류를 남기고 보스를 켜지 않는다.
- 일반 적 웨이브 중에는 기존 Director가 근접 처치 수를 소유한다. 목표 처치 뒤 Director/Spawner가 새 스폰을 중단하고 살아 있는 근접 적·투척수·비행 수리검을 정리한다. 경고는 화면 중앙의 `BOSS WARNING`과 반투명 배경으로 표시하며 GameplayState가 Playing일 때만 보스를 활성화한다.
- 씬에 배치된 기존 `Boss_SoundDuel` 프리팹 인스턴스는 처음에는 비활성이다. 등장 시 활성화하며 `BossHealthBar`가 체력 표시를 제공한다. 보스 `EnemyHealth.Died`를 받으면 `BossDefeated=true`가 된다. 스테이지 2 씬 이동·새 게임 상태·씬 이름 문자열은 없다.
- IntroScene의 시작 버튼은 현재 BambooDefense 연결을 유지한다. Stage1 직접 Play와 빌드 목록 등록은 완료했으며 인트로 연결 선택을 사용자에게 문의했다.
