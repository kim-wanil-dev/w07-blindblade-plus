### 발소리 후보

#### 실제 적의 몸체 기준 화면 진입 (2026-10-25)

- 실제 적의 후보는 `EnemyFootstepVisibility`를 통해 활성 피격 캡슐이 있으면 그 경계로, 없으면 활성 메시·스킨 메시와 적 루트 위치로 화면 진입을 계산한다. 눈 섬광·연기·궤적 Renderer는 화면 진입의 근거로 사용하지 않는다. C 전용 미리보기 대상은 기존 Target.Snapshot 화면 분류를 유지한다.
- 기본 공급자 경로와 이 판정을 공유하므로 1·2스테이지 및 C 후보 연결 여부에 따라 이펙트 때문에 방향 UI가 숨겨지는 문제가 다시 생기지 않도록 했다. 구체적인 재현·2-1 실제 Play 검증은 [전투 HUD](전투_HUD.md)의 Beast 화면 판정 보정 절을 따른다.

#### 일반 스테이지 청각 반경 지정 (2026-10-18)

- `CreateSnapshot`은 활성 일반 웨이브의 `BambooDefenseDirector.TryGetSoundPerceptionDistance`가 거리를 제공하면 그 값으로 발소리 자격을 판정한다. 설정 거리와 같은 위치까지 포함하며, 옵션 해제·보스전·온보딩·담당자 없는 씬에서는 기존 `ThreatPresentationSettings.FootstepHearingRadius`를 사용한다.
- 실제 발걸음 사건만 후보를 만들고, 현재 적 위치·화면 진입·게임 시간 수명 규칙은 유지한다. 사운드 제한과 최종 HUD의 거리 검사는 같은 Director 설정을 사용한다. 설정 위치·동작·검증은 [대숲 방어](대숲_방어.md)의 일반 스테이지 소리 인지 거리 절을 따른다.

- 기능 설명: 실제 적 발걸음 사건을 적별 최신 후보 하나로 보관하고, 적의 현재 위치·청각 범위·게임 시간 수명으로 D에 표시 결과를 제공한다.
- 동작 조건 및 처리 흐름: EnemyFootsteps.Footstep → CombatThreatPresentationProvider.HandleFootstep → EnemyFootstepCandidates.RecordFootstep → 공통 FootstepPresentationSnapshot → 기존 CombatFootstepHud. 적 생성·등록만으로 후보를 생성하지 않는다.
- 구현 상태: feature/footstep-candidates에서 코드·설정·C 전용 실제 HUD 미리보기를 구현했다. 런타임·에디터 컴파일과 전용 환경의 핵심 사용자 Play 확인을 마쳐 커밋 인계 시점이다. 정식 씬·B 프리팹 연결과 정식 게임 화면 검증은 미확인이다.

#### 확정 동작

- 표시 위치는 사용자 후속 결정으로 D 방식인 적의 현재 위치를 사용한다. 이전 C 계획의 발생 위치 고정 표시는 이 결정으로 대체한다.
- Origin과 OccurredAt은 실제 발걸음의 발생 위치·공통 세션 시각을 고정 보존한다. 표시용 WorldPosition·방향·색·근접도·거리 판정만 현재 적 위치로 갱신한다.
- 적별 최신 후보 하나를 보관하고 별도 개수 상한을 두지 않는다. 새 걸음은 같은 Emitter의 이전 사건을 종료한 뒤 교체한다. 후보 상한과 D의 HUD 슬롯 24개는 별개의 제한이다.
- 후보는 실제 발걸음에서만 생긴다. 생성·등록·재활성화 때 임의 발걸음을 만들지 않는다. 별도 오디오 재생·FMOD 감쇠값 추정은 하지 않는다.
- 청각 범위 기본 20m, 플레이어 루트와 현재 적 루트의 XZ 수평 거리다. 정확히 20m는 범위 안이다. 0m 설정은 청각 표시를 끈다.
- 범위 밖에서는 후보를 유지하고 IsEligible=false, UiVisible=false, Alpha=0을 전달한다. 수명 안에 들어오면 같은 사건을 재표시할 수 있다.
- 적 외형이 카메라 화면 안에 있으면 월드 표시 여부와 무관하게 발소리 UI를 숨긴다. 화면 밖이고 청각 범위 안일 때만 UI를 허용한다.
- 실제 적의 화면 분류는 C 대상 연결 여부와 관계없이 공통 몸체·메시 판정을 사용한다. 실제 적이 아닌 C 전용 대상은 Target.Snapshot 화면 분류를 사용한다. 월드 표시의 ShowWorld·최종 가시성 및 기존 SensoryPerceptionMask.GetVisibility 조회는 기존 규칙을 유지한다.
- 색상과 근접도는 C 공통 거리 설정 3~12m를 사용한다. 색상 알파는 공통 Alpha에 한 번 합성하고 Color.a=1로 전달한다.
- 총수명 기본 0.8 게임 초, 마지막 0.3 게임 초 동안 선형 페이드한다. CombatSessionRuntime.CaptureTimestamp().GameplaySeconds를 사용하므로 슬로모션과 명시적 정지에 함께 느려지거나 정지한다.
- 사용자 결정: 총수명·페이드 길이는 새 발걸음에서 복사한다. 실행 중 설정을 바꿔도 이미 생긴 후보는 이전 값을 유지한다. 청각 범위·공통 색상은 다음 갱신부터 적용한다.
- 만료·사망·비활성화·세대 변경·세션 변경·후보 컴포넌트 중단 시 종료 스냅샷을 발행하고 후보를 정리한다. 다시 켜도 새 발걸음 전에는 후보가 없다.
- 동일 세션에서 후보 컴포넌트를 껐다 켜도 SourceSequence/Revision을 되감지 않는다. 실제 새 세션에서만 순번을 초기화한다.
- 음향을 꺼도 EnemyFootsteps.Footstep이 발생하면 후보를 생성한다. 기존 EnemyFootsteps는 SoundId.None일 때도 C# 사건을 발행한다. 실제 음소거 조건의 실행 확인은 별도다.

#### 전용 수동 확인

1. Play 종료 → Tools → Perception → Open or Create C Threat Sandbox → Add Footstep Candidate Preview.
2. Play → Start C Contract Preview Session → ThreatPresentation의 Enemy Footstep Candidates Inspector를 확인한다. 실제 아이콘·방향 원호는 Game 창에서 본다. Add Footstep Candidate Preview를 다시 실행하면 C 전용 Overlay HUD를 추가하며 기존 D 프리팹을 재사용한다.
3. 발걸음 발생 전 C 보관 후보 수와 D 전달 발소리 수는 0이다.
4. 정지 버튼으로 D 공통 시간을 정지한 뒤 Footstep_HearingEdge(19m)에서 새 발걸음을 발생시킨다. 후보 1개, 청각 범위/UI 켜짐, D 전달 값 일치가 기대값이다.
5. ThreatPresentation의 Enemy Footstep Candidates에서 발걸음 발생 대상 칸에 Footstep_OutsideHearing을 드래그하고 새 발걸음 버튼을 누른다. 아래 Footstep_OutsideHearing 이름의 후보 항목에서 표시 위치 z=21, 청각 범위/UI 꺼짐을 확인한다. 개별 적의 ThreatPresentationTarget Inspector는 적 외형 판정이므로 이 확인은 후보 컴포넌트에서 한다. 같은 적 두 걸음을 발생시켜도 해당 적의 보관 수는 하나다.
6. 후보를 정지한 상태에서 해당 적의 Transform을 바꾼다. 발생 원점·시각은 고정이고 현재 표시 위치·방향은 따라가야 한다. 20m 경계를 오가면 새 걸음 없이도 UI 자격이 바뀐다.
7. Footstep_Visible(약 5.1m)은 C 월드 표시가 있으므로 발소리 UI가 꺼지고, Footstep_Offscreen(약 11.31m)은 UI가 켜진다.
8. 재개 후 0.1배속을 사용하면 0.8 게임 초 수명은 약 8 실제 초, 마지막 페이드는 약 3 실제 초다. 정지 동안 남은 게임 시간은 변하지 않아야 한다. 기본 배속 복귀는 D의 요청 해제 API만 사용한다.
9. 설정 수명·페이드를 바꿔도 기존 후보의 복사값은 유지되고 다음 걸음에 새 값이 들어가야 한다. 수명 설정은 확인 후 0.8/0.3으로 되돌린다.
10. 대상 비활성화·재활성화, 세션 재시작, 후보 컴포넌트 중단 시 이전 후보가 지워지고 새 발걸음 없이 다시 나타나지 않아야 한다.

- 시간 관찰 버튼과 발걸음 입력은 C 전용 씬에서만 제공한다. 테스트 코드를 추가하거나 자동 성공 판정을 실행하지 않는다.
- 메뉴는 기존 전용 배치·프리팹을 보존하고 Editor에서 컴포넌트/참조를 추가·저장한다. 정식 BambooDefense 씬을 재생성하거나 저장하지 않는다.
- 초기 안내의 UI 표시는 Inspector의 표시 요청 값이었다. 사용자가 실제 UI 확인 위치를 물어 C 전용 씬에 실제 CombatFootstepHud와 D 마커 프리팹 풀 24개를 연결하는 메뉴 동작을 추가했다. HUD 컴포넌트·마커 원본은 수정하지 않는다. Overlay, 기준 1920×1080, Match 0.5이며 아이콘과 원호를 Game 창에 표시한다. Scene View나 게임 카메라 자체 렌더 캡처는 Overlay HUD 확인 근거로 사용하지 않는다.

#### 연결 및 협업

- 연결된 기능: 위협 표시 판정, D 공통 계약 v0.2.0, 기존 EnemyFootsteps, CombatFootstepHud.
- 공유하는 코드 및 상태: C는 후보·거리·수명·표시 결과를 소유하고, D는 기존 Image 24개와 원호·배치를 소유한다. B의 실제 발걸음 생성·소리·체력/세대는 읽기만 한다.
- 중복 또는 충돌 사항: 기존 D 공급자는 실시간 2초 수명으로 걸음마다 저장한다. 사용자 지시에 따라 C 후보 슬롯을 연결한 경로에 최신 하나·청각 범위·게임 시간 수명을 적용한다. 기존 D의 현재 위치 추적은 유지한다.
- 승인 필요 사항 및 결과: 사용자가 현재 위치 추적·청각 범위에서만 UI 표시를 선택했고 수명/페이드는 새 발걸음부터 설정을 적용하도록 확정했다.
- 실제 씬 인계: DefenseDirector에 C Resolver와 EnemyFootstepCandidates를 두고 관측자·카메라·공통 Settings·GameSceneInitializer의 Runtime을 연결한다. D 공급자의 Footstep Candidate Source를 후보 컴포넌트에 연결하면 기존 실제 EnemyFootsteps 구독이 C RecordFootstep으로 전달된다.
- 실제 C Target을 연결하면 적 월드 표시 판단을 그 스냅샷으로 사용한다. 정식 씬의 기존 모델·사운드·월드 발자국 효과·HUD 프리팹은 이번 단위에서 수정하지 않는다.

#### 검증 결과와 커밋 시점
