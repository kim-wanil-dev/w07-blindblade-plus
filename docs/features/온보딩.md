# 온보딩

### 온보딩

- 기능 설명: BambooDefense를 복제한 전용 씬에서 Intro 진입 뒤 기본 조작을 실제 전투 판정으로 연습하고 BambooStage1에 연결한다.
- 2026-10-16 7단계 재구성(현재 기준): 이동, 돌진, 근접 적 처치, 수리검 극한 회피, 근접 가드→패링, 원거리 가드→패링→검기, 수리검 패링→궁극기 순서로 7단계를 진행한다. 이전 6단계(근접 검기)와 8단계(원거리 검기)는 삭제하고 원거리 방어 단계에 검기 목표를 합쳤다. 아래 9단계 설명은 이전 기록이다.
  - 문구: 화면의 "퍼펙트 패링"은 모두 "패링"으로 표기한다(목표 문구·가드 게이지 판정). 코드·계약 이름은 바꾸지 않았다. 씬 `Onboarding.unity`의 `_prompts` 저장값도 7개로 맞췄다.
  - 원거리 방어 단계(`RANGED_STAGE` 5): 공터 중심 전방 5m에 플레이어, 전방 9m에 공격하지 않는 처치 가능 표적 2명(좌우 1.8m 간격), 12m에 투척수를 둔다. 토큰 0개로 시작해 가드 1회 → 가드를 놓고 패링 1회 → 검기 실제 발사로 완료한다. 반사 수리검 등으로 쓰러진 표적은 플레이어가 자유 상태일 때 원래 자리에 다시 생긴다. 가드 게이지는 가드·패링 목표에서만 보인다. 검기 전에 집중이 끝나거나 궁극기를 쓰면 패링 목표(`RANGED_PARRY_OBJECTIVE` 1)로 돌아간다.
  - 2026-10-16 근접 방어 목표 진행 수정: 사용자가 확인한 적 미공격 원인은 Onboarding 씬의 NavMesh bake 누락이다. Bake 후 적은 공격하지만 가드 성공은 진행하고 패링 성공은 진행하지 않는 문제가 남았다. 근접 공격은 전투 세션 `AttackId`를 `DefenseResolution`까지 전달하며, 퍼펙트 패링은 판정 이벤트 발행 전에 `EnemyAttackSelector.Stagger`로 현재 공격 참조를 지운다. 따라서 `DefenseResolved`에서 현재 공격을 조회하지 않고 훈련 적의 `AttackCommitted` 이벤트에서 실행 ID를 미리 저장해 판정 ID를 확인하도록 수정했다. 코드 빌드는 확인했으며 실제 Play에서 가드·패링 후 목표 전환은 미확인이다.
  - 안내: `OnboardingHud.Prompt`에 `Follow Up Objective`(후속 안내 시작 목표 순번, 기본 1)와 `Follow Up Note`(후속 안내 위 줄 설명)를 추가했다. 원거리 방어는 검기 목표부터 "좌클릭 - 검기"를, 궁극기 단계는 "좌클릭 홀드 - 궁극기" 위에 "기운 3개를 모으면 궁극기를 쓸 수 있습니다"를 표시한다.
  - 중앙 카드: 처음 시작(재시도 제외)은 첫 프레임부터 암전으로 덮고 "서막"을 표시한 뒤 제목과 암전을 0.6초(`OPENING_FADE_DURATION`)에 함께 걷고 입력을 연다. 각 단계 진입과 재시도 시작에는 "단계 n/7 시작"과 첫 목표 문구 카드를, 단계 안에서 목표가 바뀌거나 패링 목표로 돌아갈 때는 "목표 갱신"과 새 목표 문구 카드를 띄운다. 이 두 카드는 기다리지 않고 재생해 입력을 막지 않는다. 마지막 단계 완료 카드는 설명 없이 "1막"을 패널 가운데에 1.4배 크기로 표시하며 Stage1 이동 안내는 없앴다. 제목만 있는 카드("서막"·"1막")는 같은 배치를 쓴다. 기운 설명 줄과 제목만 있는 카드는 `Midline` 정렬을 쓴다.
  - 극한 회피 단계(`PERFECT_DODGE_STAGE` 3, 화면 4단계): 대나무가 드러나지 않도록 단계 진입 시 시작 파동을 재생하지 않고, 이 단계에서 재시작하면 `Start`에서 `PlayerPerfectPulse.SuppressStartPulse`로 게임 시작 자동 파동도 생략한다. 극한 회피 성공 뒤에는 입력을 잠그고 극한 회피 파동(`PlayerPerfectPulse.IsRunning`)이 다 퍼지고 사라질 때까지 기다린 다음 완료 카드를 표시한다. 이전 단계 파동 잔상과 지형 기억에 의한 대나무 표시 여부는 Play에서 미확인이다.
  - 공용 궁극기 안내: 본 게임용 `PlayerUltimateHint`는 같은 위치에 같은 문구를 띄우므로 `BeginWhenGameplayIsReady`에서 비활성화한다. 상세는 [퍼펙트 패링 토큰](퍼펙트_패링_토큰.md)을 따른다.
  - 관련 코드: `OnboardingFlowController` / `Start`, `BeginWhenGameplayIsReady`, `EnterStage`, `CreateTrainingEnemy`, `HandleTrainingEnemyAttackCommitted`, `IsCurrentStageAttack`, `HandleDefenseResolved`, `CreateSwordWaveTargets`, `MaintainSwordWaveTargets`, `GetParryObjective`, `IsFollowUpObjective`, `AdvanceToNextObjective`, `AdvanceAfterResolvedEvent`, `ReadyStageAndUnlockInput`, `RecoverWrongEmpowerUse`; `OnboardingHud` / `Prompt.GetNote`, `ShowObjective`, `PlayStageStart`, `PlayCard`, `CoverScreen`, `PlayOpening`, `ShowStageCompletion`, `ApplyCompletionLayout`, `RefreshDevicePrompt`.
  - 검증: `dotnet build Assembly-CSharp.csproj --no-restore` 오류 0개, 기존 경고 2개(CS0414). 실제 Play의 7단계 진행, 카드 표시·정렬, 서막 암전, 표적 재생성, 반사 수리검과 검기 목표는 미확인이다.
- 동작 조건 및 처리 흐름: 이동, Space 돌진·회피, 적 처치, 수리검 극한 회피, 근접 가드·퍼펙트 패링, 근접 검기, 원거리 가드·퍼펙트 패링, 원거리 검기, 궁극기 순서로 9단계를 진행한다. 돌진·회피 단계는 실제 회피 이동의 시작과 종료로 완료하고, 별도 일반 회피 목표는 두지 않는다. 극한 회피 단계에는 근접 적 대신 기존 투척수가 약 2초마다 플레이어를 향해 수리검을 발사하며, 그 수리검의 공격 ID에 연결된 실제 극한 회피 판정으로만 완료한다. 근접·원거리 일반 패링 목표도 두지 않는다. 가드 목표는 실제 접촉의 가드·일반 패링·퍼펙트 패링 중 하나면 완료하고, 퍼펙트 패링 목표는 가드를 놓고 다시 눌러 다음 공격에서 새로 성공해야 한다. 같은 단계에서 목표가 바뀔 때는 완료 카드를 띄우지 않고 목표 문구와 입력 안내를 바로 교체하며, 목표 상자를 가로지르는 짧은 광택을 한 번 재생해 전환을 강조한다. 중앙의 단계 완료 카드는 실제 다음 단계로 넘어갈 때만 표시한다. 판정 콜백이 끝난 프레임 말부터 단계 완료 카드·재배치 동안 게임플레이 입력과 유지 입력을 차단하고, 새 목표가 준비되면 이전 입력 허용 상태로 복원한다. 근접·원거리 검기와 궁극기 연계 단계는 진입 시 이전 집중·불릿 타임을 끝내고 시작한다. 검기 단계는 토큰 0개, 궁극기 단계는 토큰 2개로 시작하며, 세 단계 모두 해당 단계에서 발사된 수리검을 실제 퍼펙트 패링한 뒤에만 연계 공격 목표와 입력 안내를 보여 준다. 퍼펙트 패링 뒤에는 연계 공격 시도까지 집중 상태를 유지하고 투척수와 남은 수리검을 정리한다. 검기는 실제 SwordWave 발사로 완료한다. 궁극기는 실제 완료와 표적 8명 처치를 모두 확인한다. 궁극기 단계에서 검기를 사용하면 토큰 3개를 보존하고 다음 수리검 퍼펙트 패링 목표로 돌아가며 투척을 재개한다. 궁극기를 썼으나 8명을 모두 처치하지 못하면 토큰 2개와 8개 표적을 준비해 같은 패링 목표부터 다시 진행한다. 단계가 바뀔 때마다 게임 시작과 동일한 시야 파동을 새 단계 위치의 플레이어 발밑에서 재생하며, 재배치가 필요한 단계에서는 짧은 페이드가 끝난 뒤 파동을 낸다. 온보딩 동안 `GameOverUI`를 숨기고 구독을 해제한다. 사망하면 현재 단계를 저장하고 대기 화면 없이 씬을 다시 불러온다. 온보딩에서만 체력과 스태미너를 전투·피격·시간 배율에 관계없이 지속 회복하고, 튜토리얼 완료 시 `BambooStage1Progress.MarkBossCheckpointReached`로 1-1 완료 상태를 저장한 뒤 BambooStage1의 1-2 보스전을 연다.
- 구현 상태: `Assets/Scenes/Onboarding/Onboarding.unity` 생성, BambooDefense 복제 및 자동 웨이브 억제, Intro 연결, WAV 임포트, 빌드 목록 추가를 구현했다. 새 안내 Canvas는 Scale With Screen Size 1920×1080 기준을 코드로 사용하며, 단계별 키보드·마우스 및 게임패드 안내를 Inspector에서 바꿀 수 있다. 좁은 화면의 안내·목표 상자 폭을 조정하고 TMP 안내의 자동 글자 크기 축소와 줄바꿈 방지를 적용했다. 공용 SDF 폰트의 커닝 수치를 교정했으며 온보딩 TMP는 기본 커닝을 사용한다. 방어 단계의 목표 아래 막대는 플레이어가 가드를 누른 뒤 실제 판정 시계로 지난 시간을 표시한다. 퍼펙트·일반 패링 창 끝까지 차며, 길게 유지해 가드 구간에 들어가도 실제 유지 초와 현재 판정 문구를 계속 갱신한다. 적 공격 전조 진행도는 표시하지 않는다.
- 2026-10-16 패링 통합 영향: 일반 패링이 없어져 가드 게이지는 퍼펙트 패링 끝(0.1초)까지 차고 판정 문구는 퍼펙트 패링·가드만 표시한다(`OnboardingHud.SetGuardTiming`). 수리검을 퍼펙트 패링하면 이제 반사되어 훈련 적에게 맞을 수 있다. 목표·배치 조정은 같은 날 7단계 재구성에서 반영했다. Play 확인은 미확인이다. 상세는 [전투 판정 계약](전투_판정_계약.md)의 "2026-10-16 패링 통합" 절을 따른다.
- 2026-10-16 연계 공격 학습: 검기 단계(stage 5·7)는 0토큰, 궁극기(stage 8)는 2토큰·정상 시간으로 시작한다. 실제 발사된 수리검의 `AttackId`와 `DefenseResolved.PerfectParry`를 연결해 첫 목표를 완료한다. 패링 뒤에만 좌클릭 검기 또는 좌클릭 홀드 궁극기 안내로 바꾸고, 행동 시도까지 집중을 유지한다. 궁극기 중 검기를 잘못 쓰면 3토큰을 유지하고 재패링하도록 수리검 투척을 재개한다. 궁극기 시전 후 8명 처치에 실패하면 2토큰과 표적 8명을 다시 준비해 재패링 목표로 복귀한다.
- 2026-10-16 연출 보완: 이동 목표는 기존 Wave 프리팹을 유지하고 지름을 바꾸지 않은 원형 기본 선의 폭을 원본 링의 약 3배(0.0375m)로 표시한다. 검기 단계의 플레이어는 공터 중심에서 전방 5m에 배치해 18m 돌진 공간을 확보하고, 전방 9m에 공격하지 않는 처치 가능 근접 적 1명을 둔다. 궁극기 단계는 같은 시작 위치에서 전방 11m에 공격하지 않는 근접 적 8명을 좌우 1.8m 간격으로 균일하게 배치한다. 궁극기 완료와 8명 전원 처치를 함께 확인한다.

#### 온보딩 분석 로그

- `OnboardingFlowController`가 목표 시작·성공, 실제 방어 판정, 단계 사망 재시도, 전체 완료를 발행한다. `OnboardingTelemetryRecorder`만 이를 기록하며 복제 씬의 `CombatTelemetryRecorder`는 꺼져 있다.
- 기본 0-1은 단계 인덱스 0~3(이동, 회피, 적 처치, 수리검 극한 회피), 0-2는 4~8(근접 방어부터 궁극기)이다. 경계는 OnboardingFlow의 `_secondSectionStartStage`로 조정한다. 구간 전환·사망·종료 시 `stage_ended`, 진행 중에는 15초마다 `stage_summary`를 남긴다.
- `onboarding_step`은 HUD 목표 하나당 1건이다. 단계 4·6의 가드와 퍼펙트 패리는 목표 인덱스 0·1로 분리한다. `activeSeconds`는 실제 목표 입력이 열린 시간만 합산하며 완료 카드·일시정지·복구 대기는 제외한다. `firstInputSeconds`는 그 시간 중 처음 유효 이동/전투 입력까지의 시간이며 입력이 없으면 빈 값이다.
- `attempts`는 해당 목표에 필요한 입력의 고유 누름 수다. 이동 목표는 멈춘 뒤 다시 움직일 때 새 시도로 본다. `wrongAttempts`는 다른 전투 버튼 누름이다. `onboarding_attempt`는 각 입력 ID당 최종 Started/Rejected/BufferDropped/Buffered 상태 한 건과 연결 가능한 `defenseOutcome`을 남긴다. 누르고 있기, 놓기, 같은 버퍼 입력의 후속 Started는 중복 시도가 아니다. 목표의 최종 성공 여부는 `onboarding_step.reason`으로 판정한다.
- 사망하면 현재 목표·구간의 `reason=death`를 기록하고 같은 단계로 다시 진입할 때 `retryCount`를 1 올린다. Intro에서 다시 시작하면 새 `runId`와 0회로 초기화한다. `scene_unloaded`/`application_quit`의 `exitStepIndex`·`exitObjectiveIndex`로 이탈 지점을 확인한다. 강제 종료는 마지막 주기 요약까지만 남을 수 있다.
- 온보딩과 전투는 동일한 로컬 JSONL·자동 전송 서비스를 쓴다. Events는 사건, Sessions는 0-1/0-2/1-1/1-2 구간 도전, OnboardingSteps는 목표별 분석 행이다. 자세한 열 정의와 전처리는 [로그 설명](../../tools/combat_telemetry/README.md)을 따른다.
- Editor 짧은 실행에서 단계 0 목표 완료와 단계 1 이탈을 로컬 JSONL·OnboardingSteps·Sessions 전송으로 확인했다. 실제 입력 대신 플레이어를 목표점에 옮겨 완료 흐름만 확인했으므로 이동 시도 집계와 전체 9단계·사망 재시도·0-2 전환의 실전 검증은 남아 있다.
