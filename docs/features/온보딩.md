# 온보딩

### 온보딩

- 기능 설명: BambooDefense를 복제한 전용 씬에서 Intro 진입 뒤 기본 조작을 실제 전투 판정으로 연습하고 BambooStage1에 연결한다.
- 동작 조건 및 처리 흐름: 이동, Space 돌진·회피, 적 처치, 수리검 극한 회피, 근접 가드·퍼펙트 패링, 근접 검기, 원거리 가드·퍼펙트 패링, 원거리 검기, 궁극기 순서로 9단계를 진행한다. 돌진·회피 단계는 실제 회피 이동의 시작과 종료로 완료하고, 별도 일반 회피 목표는 두지 않는다. 극한 회피 단계에는 근접 적 대신 기존 투척수가 약 2초마다 플레이어를 향해 수리검을 발사하며, 그 수리검의 공격 ID에 연결된 실제 극한 회피 판정으로만 완료한다. 근접·원거리 일반 패링 목표도 두지 않는다. 가드 목표는 실제 접촉의 가드·일반 패링·퍼펙트 패링 중 하나면 완료하고, 퍼펙트 패링 목표는 가드를 놓고 다시 눌러 다음 공격에서 새로 성공해야 한다. 목표 줄과 단계가 완료될 때 중앙에 완료·다음 목표 또는 다음 단계 안내를 보여 준다. 판정 콜백이 끝난 프레임 말부터 완료 카드·재배치 동안 게임플레이 입력과 유지 입력을 차단하고, 새 목표가 준비되면 이전 입력 허용 상태로 복원한다. 검기 단계 진입 시 준비 상태가 사라졌으면 다시 시작하고 토큰을 검기 사용 가능한 1~2개로 맞추며, 궁극기 단계는 3개와 준비 상태로 들어간다. 두 단계 모두 히트스톱 뒤 실제 불릿 타임이 시작돼야 입력을 연다. 검기 단계에서 궁극기를 잘못 완료하거나 궁극기 단계에서 검기를 쓰면, 해당 행동이 끝난 뒤 현재 목표의 집중과 토큰을 복구해 다시 시도한다. 단계가 바뀔 때마다 게임 시작과 동일한 시야 파동을 새 단계 위치의 플레이어 발밑에서 재생하며, 재배치가 필요한 단계에서는 짧은 페이드가 끝난 뒤 파동을 낸다. 온보딩 동안 `GameOverUI`를 숨기고 구독을 해제한다. 사망하면 현재 단계를 저장하고 대기 화면 없이 씬을 다시 불러온다. 온보딩에서만 체력과 스태미너를 전투·피격·시간 배율에 관계없이 지속 회복하고, 완료 시 체크포인트를 지운 뒤 BambooStage1을 연다.
- 구현 상태: `Assets/Scenes/Onboarding/Onboarding.unity` 생성, BambooDefense 복제 및 자동 웨이브 억제, Intro 연결, WAV 임포트, 빌드 목록 추가를 구현했다. 새 안내 Canvas는 Scale With Screen Size 1920×1080 기준을 코드로 사용하며, 단계별 키보드·마우스 및 게임패드 안내를 Inspector에서 바꿀 수 있다. 좁은 화면의 안내·목표 상자 폭을 조정하고 TMP 안내의 자동 글자 크기 축소와 줄바꿈 방지를 적용했다. 공용 SDF 폰트의 커닝 수치를 교정했으며 온보딩 TMP는 기본 커닝을 사용한다. 방어 단계의 목표 아래 막대는 플레이어가 가드를 누른 뒤 실제 판정 시계로 지난 시간을 표시한다. 퍼펙트·일반 패링 창 끝까지 차며, 길게 유지해 가드 구간에 들어가도 실제 유지 초와 현재 판정 문구를 계속 갱신한다. 적 공격 전조 진행도는 표시하지 않는다.

#### 연결 및 협업

- 연결된 기능: [인트로 메뉴](인트로_메뉴.md), [대숲 방어](대숲_방어.md), [대숲 스테이지 1](대숲_스테이지1.md), [전투 판정 계약](전투_판정_계약.md), [패드 입력 안내](패드_입력_안내.md), [전투 HUD](전투_HUD.md).
- 공유하는 코드 및 상태: 플레이어 이동·전투 판정·스태미너·강화·검기, `BambooDefenseDirector`의 투척 예약과 실제 수리검 발사 사건, `BambooStage1Progress` 체크포인트.
- 중복 또는 충돌 사항: BambooDefense와 BambooStage1의 원본 씬 설정·회복 동작은 수정하지 않는다. 복제 씬에서만 자동 웨이브·기존 회복·게임오버 UI를 끈다.
- 승인 필요 사항 및 결과: 사용자가 단계 순서, 판정 기준, 연습 적·투척수 재사용, 회복·재시도, 입력 표기, 체크포인트 초기화와 전환 시점을 확정했다.

#### 확인 결과

- Unity 6000.3.22f1 격리 프로젝트에서 최종 스크립트 컴파일과 씬 작성 완료를 확인했다. 새 코드 오류는 없으며 기존 `KatanaDebugOverlay._showCombatFeedback` 미사용 경고 1건만 남는다.
- 2026-10-16 사용자 플레이에서 단계 전환 인지, 일반 회피 판정, 일부 TMP 문구 잘림, 온보딩 스태미너 부족이 확인됐다. 단계·목표 완료 카드, 일반 회피와 일반 패링 목표 제거, 안내 상자 높이·폭과 한 줄 자동 축소, 온보딩 전용 스태미너 지속 회복을 적용했다. 최신 파일 복사본을 Unity 6000.3.22f1 배치 모드로 컴파일해 오류 0건과 정상 종료를 확인했다. 기존 미사용 필드 경고만 남았다.
- 2026-10-16 극한 회피의 연습 공격원을 근접 적에서 2초 주기 수리검으로 바꿨다. 극한 회피 목표는 `ShurikenLaunched.AttackId`와 같은 `DefenseResolved`의 `DodgeAvoided` 및 `DodgeChanged.PerfectDodge`를 함께 확인한다. 수정 후 실제 수리검 접촉과 성공 UI는 아직 플레이로 확인하지 않았다.
- 2026-10-16 근접 적의 기존 `DamageContext`는 AttackId와 HitId가 0이므로, 이를 같은 타격으로 중복 제거하면 첫 접촉 이후의 가드·패링이 진행에 반영되지 않았다. ID가 부여된 수리검 타격만 ID로 중복 제거하고, 근접 방어는 실제 새 접촉마다 판정한다. 가드 목표에서 일반·퍼펙트 패링도 성공으로 받아들이되, 퍼펙트 패링 목표는 별도의 실제 접촉을 요구한다. 단계 전환에는 기존 시작 파동을 다시 사용한다. 사용자가 막대의 의도를 플레이어의 가드 유지 시간과 판정으로 명확히 했으므로 공격 전조 표시를 제거하고 실제 가드 시계에 연결했다. 최종 파일 복사본을 Unity 6000.3.22f1 배치 모드로 임포트·컴파일해 C# 오류 0건과 정상 종료를 확인했다. 기존 `KatanaDebugOverlay._showCombatFeedback` 경고만 남았다. 실제 플레이의 파동·가드 진행·표시 확인은 미실시다.
- 수리검 극한 회피 변경을 포함한 복사본은 Unity 6000.3.22f1 배치 모드에서 C# 오류 0건으로 컴파일하고 정상 종료했다. 기존 `KatanaDebugOverlay._showCombatFeedback` 미사용 경고만 확인했다. 이후 공용 폰트 교정과 온보딩 기본 커닝 복원에 대한 재컴파일 결과는 아래 공용 폰트 명세에 기록한다.
- `ChosunCentennial_otf.otf`의 `WA` GPOS 간격은 −115/1000em인데 공용 SDF 에셋에는 90pt 환산값 −10.35가 저장돼 있었다. 21pt 글리프에 맞는 −2.415로 교정했다. 같은 배율이 확인된 커닝 550쌍을 공용 에셋에서 교정하고 온보딩 전용 커닝 해제를 제거했다. [공용 TMP 폰트](공용_TMP_폰트.md)에 검증 범위를 기록한다.
- Unity Editor API 감사에서 온보딩·Intro 씬 누락 스크립트 0개, Intro 전환 컴포넌트 1개, 필수 프리팹·씬 참조, 기록·준비 텍스트 숨김, 활성 빌드 목록의 Intro·BambooDefense·BambooStage1·Onboarding, 새 HUD와 보존 HUD의 지정 폰트를 확인했다.
- 횃불 WAV는 PCM·Preload Audio Data로 임포트됐고 길이 약 4.17초다. 실제 버튼 클릭 재생과 끝까지 들리는 런타임 확인은 미실시다.
- 수정 후 전체 Intro→온보딩→BambooStage1 진행, 9단계 입력·전투 판정, 사망 후 단계 재시작 및 GameOverUI 억제, 집중·토큰 상태는 다시 플레이해 확인하지 않았다. 1920×1080·1280×720·1024×768·1680×720 화면 캡처도 미실시다. UI는 앵커·화면 비율 조건으로 배치했지만 네 해상도의 실제 화면은 아직 확인하지 않았다.
- 지정된 PDF와 클릭 PNG 파일은 현재 작업 환경의 파일 경로에서 찾지 못했다. 사용자가 직접 적은 단계 흐름으로 구현했으며 Sprite 필드는 비워 두어 Inspector에서 교체할 수 있다.
- 테스트 코드는 작성하지 않았다.
- 2026-10-16 단계·목표 완료 카드와 재배치 중 `InputManager`로 게임플레이 입력을 잠그고 새 단계 준비가 끝난 뒤 복원한다. 검기·궁극기 단계는 준비와 불릿 타임을 확인하고, 잘못 쓴 기술 뒤 현재 목표의 토큰과 준비를 복구한다. Unity 6000.3.22f1 격리 프로젝트에서 C# 오류 0건과 배치 모드 정상 종료를 확인했다. 기존 `KatanaDebugOverlay._showCombatFeedback` 미사용 경고 1건만 남는다. 실제 플레이에서 전환 중 입력 차단, 검기·궁극기 오사용 후 복구와 시간 배율 반환은 미확인이다.
