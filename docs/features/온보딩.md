# 온보딩

### 온보딩

- 기능 설명: BambooDefense를 복제한 전용 씬에서 Intro의 시작 버튼을 누를 때마다 다섯 단계의 기본 조작·전투를 실제 판정으로 연습하고 BambooStage1에 연결한다.
- 2026-10-19 최종 거합 후 전환: 거합으로 표적 8명을 모두 처치하면 투척수의 예약 발사를 즉시 중단하고 비행 중인 연습 수리검을 제거한다. 마지막 완료 카드는 표시하지 않고 입력을 잠근 채 0.8초 기다린 뒤 0.5초 암전으로 BambooStage1을 연다. `1막`은 BambooStage1 씬 시작에 표시한다. 실제 Play에서 마지막 투사체 차단과 전환 시점은 미확인이다.
- 2026-10-19 일섬 학습 안내·투척 연사: 원거리 방어 단계의 첫 실제 수리검 쳐내기 성공으로 일섬 목표에 진입하면 화면 중앙 하단 안내를 `일섬 - 마우스 왼쪽 버튼 클릭`으로 바꾸고, 기존 금색 테두리 설명판에 `쳐내기 성공 시 공격 대신 일섬을 사용할 수 있습니다. 경로상의 투사체를 없애는 검기를 날리며 돌진합니다. 마우스 왼쪽 버튼 클릭으로 계속 진행`을 표시한다. 패드는 `일섬 - RB 버튼`과 `RB 버튼으로 계속 진행`을 쓴다. 설명을 닫는 입력은 소비해 일섬이 즉시 발동하지 않게 한다. 이 단계의 투척수는 2초마다 한 발을 예약하던 방식에서 한 번의 전조 뒤 게임 시간 0.3초 간격 3발 연사로 바꾼다. 후속 발사도 기존 동시 비행 3발·최소 예약 간격 0.25초 제한을 지킨다. 극한 회피·거합 단계는 단발 투척을 유지한다. 마지막 거합 설명판의 진행 문구는 `마우스 왼쪽 버튼 홀드로 계속 진행`이다. HUD 기본값, 씬 저장값, SceneBuilder 기본값을 맞췄다. Unity Play에서 설명판 배치, 클릭 소비, 실제 연사·투사체 소거는 미확인이다.
- 2026-10-17 5단계 재구성(현재 기준): 기존 이동·발도 처치 단계를 이동·발도 3명 처치로 합치고 회피 안내를 함께 표시한다. 이후 수리검 극한 회피, 근접 막기→쳐내기, 원거리 막기→쳐내기→일섬, 수리검 쳐내기 3회→거합·표적 8명 처치 순서로 진행한다. Inspector 프롬프트, 씬 저장값, SceneBuilder 기본값, 텔레메트리의 단계 인덱스를 0~4로 맞춘다.
- 첫 단계 시작 파동만 0.35초 페이드로 짧게 하고, 이후 길잡이 파동은 기본 페이드를 쓴다. 3초간 움직이지 않으면 시간 정지 안내로 이동을 요구하고, 현재 입력 장치가 패드면 왼쪽 스틱 문구를 쓴다. 플레이어의 실제 걸음 파동은 2걸음마다 1회 발생하므로 첫 발걸음 시각이 아니라 `FootstepRipple.PlayerRippleEmitted`의 실제 파동 설정과 시작 시각을 사용한다. 바닥 링이 충분히 퍼져 화면 중앙 부근에 닿을 때 시간을 멈추고 안내선만 보이는 링 위치에 연결해 파동을 한 번 설명한다. 카메라 각도 때문에 링이 화면 정중앙을 지나지 않으면 반지름이 절반 이상 퍼지고 화면 중앙 열의 보이는 바닥에 나타났을 때 설명한다. 발도 실 안내는 이동 파동 안내를 마친 뒤에만 보여 두 설명이 겹치거나 순서가 뒤바뀌지 않게 한다. 연결된 발도 실이 처음 생기면 검 쪽 실 시작점에 안내선을 잇고 같은 좌클릭을 기존 공격 입력으로 전달한다. 처치가 10초간 없으면 길잡이 파동을 다시 낸다. 안내 중 정지 시간은 두 타이머에서 제외한다.
  - 근접 단계의 첫 실제 쳐내기 뒤에는 납도·구슬 위치 안정까지 기다린 다음 시간을 멈춰 거합 토큰 HUD와 검의 실제 구슬을 차례로 강조한다. 거합 단계는 토큰 0개로 시작하고, 해당 단계에서 발사된 서로 다른 수리검 3개의 실제 퍼펙트 패링으로 3칸을 채운다. 완료 설명에서 시작된 동일한 홀드 입력으로 실제 차징을 시작한다. 일섬을 잘못 사용해도 모은 칸은 보존하고 집중을 자동 시작하지 않으며, 거합 실패 시 표적·토큰을 0으로 초기화해 세 번 쳐내기부터 다시 시도한다.
- 2026-10-17 거합 게이지 누적 진행 보완: 첫째·둘째 수리검 쳐내기 뒤에는 목표 문구를 바꾸고 입력을 다시 허용한다. 집중을 무기한 유지하지 않으므로 자연 만료되거나 일섬 사용으로 끝낼 수 있고, 이때 이미 얻은 게이지와 쳐내기 횟수는 유지된다. 투척수가 다음 수리검을 발사해 남은 횟수를 계속 채우며, 세 번째 쳐내기 뒤 거합 안내에서만 집중을 유지한다. 이 경로의 실제 Play 확인은 미확인이다.
- 2026-10-17 거합 목표 수치: 5단계 시작 게이지 0칸에서 쳐내기 목표를 `0/3`으로 표시하고, 실제 쳐내기마다 `1/3`, `2/3`으로 바꾼다. 세 번째 쳐내기로 게이지 3칸이 되면 거합 목표와 게이지 안내로 전환한다. HUD 기본값, 씬 저장값, SceneBuilder 기본값을 일치시켰다.
- 2026-10-17 연습 배치·연계 수정: 근접 연습 적, 일섬 표적, 거합 표적, BambooThrower를 경기장 중심의 월드 방향에 고정한다. 재생성할 때 플레이어의 현재 위치·시선으로 배치를 다시 계산하지 않으며, 투척수도 플레이어를 따라 순간 이동하지 않는다. 첫 적은 시작 지점에서 약 9.9m 앞으로 옮겨 첫 화면의 발도 연결 거리 9m 밖에 둔다. 발도 실 안내는 이동 파동 안내 다음에 실제 실이 연결될 때 표시한다. 원거리 막기 목표에서 쳐내기를 먼저 성공하면 별도의 쳐내기 1회 목표를 건너뛰고 일섬 목표로 바로 진행한다. 거합 표적 간격은 2.4m로 넓혀 중앙의 일섬 돌진 통로를 확보한다. 실제 Play의 투척 범위·돌진 거리와 화면 내 표적 배치는 미확인이다.
- 2026-10-17 거합 재안내 입력 복원: 거합 설명을 본 뒤 홀드하지 않아 일섬이 나간 경우, 다음 수리검 쳐내기로 집중을 회복하면 거합 설명을 다시 보여준다. 재안내를 닫은 뒤에는 단계 목표 준비를 확인하고 전투 입력 잠금을 해제해 그 클릭의 홀드가 거합 차징으로 이어지게 한다. 실제 Play에서 재시도 동작은 미확인이다.
- 2026-10-17 거합 목표 집계 보완: 목표 교체 중 입력 잠금이 걸려도 이미 예약된 투척수의 수리검은 발사될 수 있다. 발사 사건의 공격 ID는 이때도 기록해 두고, 잠금 해제 후 그 수리검을 실제 쳐내면 거합 게이지와 목표 횟수가 함께 증가하게 한다. 중복 공격 ID는 기존처럼 한 번만 센다. 수정 후 실제 Play 재현 확인은 미확인이다.
- 판정은 `ShurikenLaunched.AttackId`, `DefenseResolved`, `DodgeChanged`, `SwordWaveLaunched`, `EmpowerChanged` 및 적 `Died` 사건으로 연결한다. 안내 시간 정지는 `CombatSessionRuntime.SetFrozen`을 사용해 다른 시간 배율 요청을 보존한다. 안내 입력은 게임 시간이 0이어도 감지하고, 패드에서 현재 장치별 문구로 전환한다. 발도·거합 설명을 닫는 입력은 실제 공격 경로로 한 번 전달하고, 이동 파동·보상 설명을 닫는 입력은 버튼을 놓을 때까지 소비해 공격으로 새지 않게 한다. 액션 재활성화로 생길 수 있는 중복 입력을 막고, 거합은 물리 버튼을 놓을 때까지 동일 입력으로 차징을 유지한다.
- 막기 목표에서는 `우클릭 - 막기`와 `쳐내기 - 적의 공격 시점에 맞춰 막기`를 별도 줄로 안내한다. 근접·원거리 쳐내기 목표는 `공격 쳐내기 0/1`로 표시한다. 일섬 안내는 34pt로 `일섬 - 마우스 왼쪽 버튼 클릭`을 표시하고, 기능 설명은 별도 금색 테두리 설명판에 넣는다. 패드 문구도 대응해 둔다. HUD·Inspector·씬의 저장 문구를 같은 값으로 맞춘다.
- 2026-10-17 1단계 조작 안내와 3초 정지 시 이동 안내는 하단 중앙에 놓인 불투명도가 높은 검은 판과 밝은 글자를 공유한다. 화면 비율에 따라 하단 여백은 기본 62px, 좁은 화면 42px로 조절한다. 금색 테두리는 이 조작판에 사용하지 않는다. 설명판 배경은 제공된 화면 표본의 회베이지 `#CAC5B0`을 사용하고 금색 테두리와 어두운 글자를 유지한다. 발도 실 설명에서는 실 전체 범위를 감싼 금색 사각형을 그리지 않고 설명판의 연결선만 실제 검 쪽 실 시작점에 잇는다. 온보딩 Canvas는 집중 비네트 Canvas(정렬 순서 100)보다 높은 순서 102로 그려 안내와 목표판이 가려지지 않으며, 씬 전환 암전은 기존 최상위 Canvas를 유지한다. 실제 Play 배치는 미확인이다.
- 2026-10-17 거합 게이지 강조 프레임: HUD와 검 구슬을 가리던 반투명 노란 채우기와 채워진 이미지의 Outline 효과를 제거했다. 대상 RectTransform의 네 변을 기본 UI 선으로만 그려 내부가 그대로 보이게 하고, 설명판과 대상 사이의 안내선은 유지한다. 검 구슬 설명은 세 구슬의 평균점 대신 손잡이에 가장 가까운 첫 구슬의 실제 위치를 사용하며 프레임을 76×76으로 줄여 아래 화면 경계보다 위의 첫 구슬을 강조한다. 실제 Play에서 선 두께와 시인성은 미확인이다.
- 2026-10-17 극한 회피 파동 안내: 실제 극한 회피 파동이 확산을 마치면 시간을 멈춰 파동이 밝힌 시야와 안내판을 함께 보여 준다. 클릭은 안내만 닫고 입력을 소비하며, 이후 파동이 사라진 뒤 단계 완료 카드로 진행한다. 안내선은 설명판과 목표 프레임의 각 바깥쪽 가장자리에서 끝나도록 계산해 상자 내부를 가로지르지 않는다. 프레임이 없는 파동·발도 실 대상에는 실제 화면 위치까지 연결한다. 실제 Play 시점과 배치는 미확인이다.
- 2026-10-17 지면 시인성 시험: 온보딩 씬의 `Ground`에만 `OnboardingGroundGuide`를 연결했다. 실제 지면 깊이·위쪽 노멀·높이로 바닥을 식별해 먼 쪽에 옅은 회색 명암을 입히고, 지면과 하늘이 만나는 곳에 연한 회색 선을 표시한다. 색상, 지면 높이 허용 오차, 명암 시작·끝 거리는 Ground의 Inspector에서 조절한다. 다른 씬에는 컴포넌트가 없고 비활성화 때 셰이더 전역 활성값을 지운다. 에디터의 기존 SceneBuilder에도 같은 기본 연결을 추가했으나 전체 Build는 실행하지 않았다. 실제 Play 화면의 밝기·시야 파동과의 균형은 미확인이다.
- 2026-10-16 표시 용어: 온보딩의 키보드·패드 안내, 목표 카드, 막기 유지 시간·판정 문구와 씬 직렬화 문구를 발도·막기·쳐내기·회피·일섬·거합으로 통일했다. 실제 전투 판정과 단계 구성은 변경하지 않았다. Unity 번들 Roslyn 컴파일은 오류 0건, 기존 미사용 필드 경고 2건이며 화면에서의 실제 배치 확인은 미확인이다.
- 2026-10-16 7단계 구성(이전 버전 기록): 이동, 회피, 발도로 적 처치, 수리검 극한 회피, 근접 막기→쳐내기, 원거리 막기→쳐내기→일섬, 수리검 쳐내기→거합 순서로 구성했다. 아래 7·9단계 설명은 이전 버전의 구현·검증 기록이며 현재 구성은 위 2026-10-17 절을 따른다.
  - 문구: 화면의 기술명은 [공통 표시 용어](../FEATURE_SPEC.md#게임-내-표시-용어)를 따른다. 전투 코드의 `PerfectParry` 등 판정·사건 이름은 유지한다. 씬 `Onboarding.unity`의 `_prompts` 저장값은 7개다.
  - 원거리 방어 단계(`RANGED_STAGE` 5): 공터 중심 전방 5m에 플레이어, 전방 9m에 공격하지 않는 처치 가능 표적 2명(좌우 1.8m 간격), 12m에 투척수를 둔다. 토큰 0개로 시작해 막기 1회 → 정확한 시점에 막아서 공격 쳐내기 1회 → 일섬 발동으로 완료한다. 반사 수리검 등으로 쓰러진 표적은 플레이어가 자유 상태일 때 원래 자리에 다시 생긴다. 막기 유지 시간 막대는 막기·쳐내기 목표에서만 보인다. 일섬 전에 집중이 끝나거나 거합을 쓰면 쳐내기 목표(`RANGED_PARRY_OBJECTIVE` 1)로 돌아간다.
  - 2026-10-16 근접 방어 목표 진행 수정: 사용자가 확인한 적 미공격 원인은 Onboarding 씬의 NavMesh bake 누락이다. Bake 후 적은 공격하지만 가드 성공은 진행하고 패링 성공은 진행하지 않는 문제가 남았다. 근접 공격은 전투 세션 `AttackId`를 `DefenseResolution`까지 전달하며, 퍼펙트 패링은 판정 이벤트 발행 전에 `EnemyAttackSelector.Stagger`로 현재 공격 참조를 지운다. 따라서 `DefenseResolved`에서 현재 공격을 조회하지 않고 훈련 적의 `AttackCommitted` 이벤트에서 실행 ID를 미리 저장해 판정 ID를 확인하도록 수정했다. 코드 빌드는 확인했으며 실제 Play에서 가드·패링 후 목표 전환은 미확인이다.

#### 확인 결과

- 이전 버전은 Unity 6000.3.22f1 격리 프로젝트에서 스크립트 컴파일과 씬 작성 완료를 확인했다. 이번 5단계 변경은 기존 프로젝트에서 Unity 컴파일과 Play를 확인하지 못했다. 현재 Editor 프로세스가 프로젝트 잠금을 보유 중이고, 독립 `dotnet build`에는 복원된 `project.assets.json`이 없어 컴파일이 진행되지 않았다.

- 2026-10-16 극한 회피의 연습 공격원을 근접 적에서 2초 주기 수리검으로 바꿨다. 극한 회피 목표는 `ShurikenLaunched.AttackId`와 같은 `DefenseResolved`의 `DodgeAvoided` 및 `DodgeChanged.PerfectDodge`를 함께 확인한다. 수정 후 실제 수리검 접촉과 성공 UI는 아직 플레이로 확인하지 않았다.

ID가 부여된 수리검 타격만 ID로 중복 제거하고, 근접 방어는 실제 새 접촉마다 판정한다. 가드 목표에서 일반·퍼펙트 패링도 성공으로 받아들이되, 퍼펙트 패링 목표는 별도의 실제 접촉을 요구한다. 단계 전환에는 기존 시작 파동을 다시 사용한다. 사용자가 막대의 의도를 플레이어의 가드 유지 시간과 판정으로 명확히 했으므로 공격 전조 표시를 제거하고 실제 가드 시계에 연결했다. 최종 파일 복사본을 Unity 6000.3.22f1 배치 모드로 임포트·컴파일해 C# 오류 0건과 정상 종료를 확인했다. 기존 `KatanaDebugOverlay._showCombatFeedback` 경고만 남았다. 실제 플레이의 파동·가드 진행·표시 확인은 미실시다.

#### 온보딩 분석 로그

- `OnboardingFlowController`가 목표 시작·성공, 실제 방어 판정, 단계 사망 재시도, 전체 완료를 발행한다. `OnboardingTelemetryRecorder`만 이를 기록하며 복제 씬의 `CombatTelemetryRecorder`는 꺼져 있다.
- 현재 온보딩 단계 인덱스 0~4는 `stageId=0-1~0-5`에 각각 대응한다. 각 세션은 온보딩 단계 하나를 나타내며 `runId`로 전체 흐름을 연결한다. 단계 전환·사망·종료 시 `stage_ended`, 진행 중에는 15초마다 `stage_summary`를 남긴다.
- `onboarding_step`은 HUD 목표가 완료·사망·이탈로 닫힐 때 1건이다. 현재 2·3·4단계의 순차 방어 목표는 각 목표 인덱스로 분리한다. `activeSeconds`는 실제 목표 입력이 열린 시간만 합산하며 완료 카드·일시정지·복구 대기는 제외한다. `firstInputSeconds`는 그 시간 중 처음 유효 이동/전투 입력까지의 시간이며 입력이 없으면 빈 값이다.
- `attempts`는 해당 목표에 필요한 입력의 고유 누름 수다. 이동 목표는 멈춘 뒤 다시 움직일 때 새 시도로 본다. `wrongAttempts`는 다른 전투 버튼 누름이다. `onboarding_attempt`는 각 입력 ID당 최종 Started/Rejected/BufferDropped/Buffered 상태 한 건과 연결 가능한 `defenseOutcome`을 남긴다. 누르고 있기, 놓기, 같은 버퍼 입력의 후속 Started는 중복 시도가 아니다. 목표의 최종 성공 여부는 `onboarding_step.reason`으로 판정한다.
- 사망하면 현재 목표·구간의 `reason=death`를 기록하고 같은 단계로 다시 진입할 때 `retryCount`를 1 올린다. Intro에서 다시 시작하면 새 `runId`와 0회로 초기화한다. `scene_unloaded`/`application_quit`의 `exitStepIndex`·`exitObjectiveIndex`로 이탈 지점을 확인한다. 강제 종료는 마지막 주기 요약까지만 남을 수 있다.
- 온보딩과 전투는 동일한 로컬 JSONL·자동 전송 서비스를 쓴다. Events는 사건, Sessions는 현재 `0-1~0-5` 및 `1-1`/`1-2` 도전, OnboardingSteps는 목표별 분석 행이다. 목표 행을 닫을 때 업로드를 즉시 요청하며, 자세한 열 정의와 전처리는 [로그 설명](../../tools/combat_telemetry/README.md)을 따른다.
- 빌드는 CSV를 생성하지 않는다. 로컬 JSONL은 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/w07-blindblade+/CombatTelemetry`에 저장하며, [로그 설명](../../tools/combat_telemetry/README.md)의 `Export-Telemetry.ps1`로 `OnboardingSteps.csv`를 만든다.
- 이전 7단계 구현의 Editor 짧은 실행에서 단계 0 완료와 단계 1 이탈을 로컬 로그·전송으로 확인했다. 실제 입력 대신 플레이어를 목표점에 옮긴 검증이며, 현재 5단계 흐름에는 적용되지 않는다.
- 2026-10-16 빌드 실행 진단에서 `0-1` 완료와 `0-2` 이탈 `onboarding_step`이 로컬 JSONL에 기록됐지만 최신 세션의 서버 ACK 커서는 없었다. 종료 시 Player.log에 `Curl error 42: Callback aborted`가 있어 목표 행을 닫을 때 즉시 업로드를 요청하도록 보완했다. 새 빌드에서 Google Sheets 적재를 다시 확인해야 한다.
