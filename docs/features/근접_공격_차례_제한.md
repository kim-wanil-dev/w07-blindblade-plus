# 근접 공격 차례 제한

### 근접 공격 차례 제한 (2026-10-22)

- 기능 설명: 일반 웨이브에서 플레이어를 둘러싼 근접 적(일반 검객·Beast)이 한꺼번에 공격하지 않도록 공격 차례(토큰)를 나눠 준다. 다크소울3의 교차 공격처럼 차례를 가진 적만 다가와 공격하고, 차례가 없는 일반 근접 적은 거리를 두고 좌우로 움직이며 기다린다.
- 동작 조건 및 처리 흐름:
  - 대상: `DefenseEnemySpawner`가 생성한 근접 적과 Beast(BambooStage1, RainyStage_JH, RainyTwinBoss 보스전 앞 웨이브). 스포너가 생성 때 `EnemyController.SetAttackGate`로 연결한다. 보스(`BossController`, `TwinBossController`), 온보딩이 직접 생성한 적, 투척수는 대상이 아니다. 투척수는 기존 `DefenseThrowBudget` 동시 투척 상한을 그대로 쓴다.
  - 포위 수 N: 플레이어와 수평 거리 `포위 반경 (m)`(기본 10m) 안의 생존 근접 적과 Beast 수다.
  - 동시 공격 수: `내림(동시 공격 계수 × N^동시 공격 지수)`를 최소·최대 동시 공격 수로 제한한다. 기본값은 계수 1.0, 지수 0.6, 최소 1, 최대 6이다. N 1~3 → 1, 4~6 → 2, 7~10 → 3, 11~14 → 4, 15~19 → 5, 20 이상 → 6이다. 처음에는 계수 1.13·지수 0.5였으며 사용자 요청으로 조금 더 가파르게 바꿨다.
  - 대기열: 포위 반경 안에서 공격하려는 적은 매 프레임 차례를 요청하고, 처음 요청한 순서(FIFO)대로 지급한다. 0.2초 넘게 요청하지 않은 적(예: 원을 도는 Beast)은 순서만 유지한 채 건너뛰며, 5초 넘게 요청하지 않으면 대기열에서 뺀다.
  - 지급 간격: 연속한 두 차례 지급 사이에 `차례 지급 간격 (초)`(기본 0.4초)를 둔다. 빈 차례가 여러 개여도 같은 순간에 공격을 시작하지 않는다.
  - 반납: 차례 하나로 공격 한 번을 한다. 차례로 시작한 공격의 후딜이 끝나거나 취소·경직되면 다음 Update 첫머리에서 반납하고 대기열 맨 뒤로 간다. 비활성화·대상 변경·게이트 교체 때도 반납한다. 반납한 적이 바로 다시 요청할 때 빈 차례와 지급 간격이 허락하면 그 자리에서 다시 받으므로, 혼자 남은 적은 공격마다 물러나지 않는다.
  - 회수: 차례를 받고 `미사용 차례 회수 시간 (초)`(기본 3초) 안에 공격을 시작하지 못하면 회수한다.
  - 대기 행동(일반 근접 적): Chasing·Attacking 상태에서 차례가 없으면 대상과의 수평 거리를 3.5~5m로 제한한 대기 원 위에서 0.8~1.6초 구간마다 왼쪽·오른쪽 이동(앞선 각도 12°) 또는 멈춤(30%)을 고른다. 막힌 쪽이면 방향을 뒤집으며, 도착하면 대상을 바라본다. 포위 반경 밖의 적은 대기열에 들지 않고 대기 원 바깥 끝(5m)까지 다가온다. 이동 속도는 기존 `EnemyMotor` 속도를 그대로 쓴다.
  - 대기 행동(Beast): 기존 `DefenseBeastProwl` 원 그리기·물러나기를 유지하고, 돌진 준비(`IsReadyToAttack`)가 된 뒤에만 차례를 요청한다. 차례를 받아야 물기 돌진을 시작한다.
  - Director의 `공격 차례 제한 사용`을 끄면 이후 생성되는 적은 기존처럼 제한 없이 공격한다. 웨이브 종료(`StopWave`)와 Director 파괴 때 모든 차례를 초기화한다.
- 구현 상태: 코드 구현 완료. 새 Inspector 항목은 씬·프리팹에 저장값이 없어 코드 기본값을 사용한다. 임시 csproj로 `dotnet build` 오류 0개(기존 경고 4개)를 확인했다. Unity Play에서의 체감·대기 이동·Beast 차례 대기는 미확인이며, 새 스크립트 두 개의 `.meta`는 Unity 임포트 때 생성된다(미확인).

#### 연결 및 협업

- 연결된 기능: [적 추적](적_추적.md)의 `EnemyController` 추적·공격 상태, [적 공격 패턴](적_공격_패턴.md)의 `EnemyAttackSelector`·`EnemyAttackBehaviour`, [일반 Beast 적](DefenseBeast.md)의 `DefenseBeastProwl`, [대숲 방어](대숲_방어.md)의 `BambooDefenseDirector`·`DefenseEnemySpawner`.
- 공유하는 코드 및 상태: `EnemyController.Update`의 Attacking·Chasing 분기와 `_nextRepathTime`, `EnemyAttackSelector.IsBusy`, `IEnemyEngagementMovement.IsReadyToAttack`.
- 중복 또는 충돌 사항: 기존 근접 전조 중 투척 보류(`_deferDuringMeleeTelegraph`)와는 독립적으로 동작한다. 공격 텔레메트리 `stage_config`에는 새 설정을 기록하지 않는다(미반영).
- 승인 필요 사항 및 결과: 동시 공격 수 곡선(완만한 포화형, 이후 지수 0.6으로 조정), 대기 행동(거리 두고 좌우 이동), 지급 간격 0.4초, FIFO 순서를 사용자가 선택했다.
