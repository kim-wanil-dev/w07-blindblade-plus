### 특수 스킬과 독립 게이지

- 기능 설명: 패링 집중은 실시간 3초 동안 유지되며 좌클릭으로 게이지 소모 없는 일섬을 한 번 사용할 수 있다. 극한 회피 집중은 실시간 1초이며 대상 돌진·일섬 없이 일반 공격을 허용한다. 거합은 기존 독립 100% 자원과 Q 홀드 차징(2026-10-24, 아래 Q 홀드 거합 절)을 사용한다.
- 2026-10-24 온보딩 행동 설명 입력 전달: 일섬·거합 설명 중에만 `InputManager.BeginOnboardingActionPrompt`로 별도 새 입력을 기다린다. 일섬의 좌클릭/RB는 본편과 같은 `RequestAttack` 경로에서 `swordWaveOnly`로 제한해 패링 집중이 사라졌을 때 일반 공격으로 바뀌지 않게 한다. 거합 Q/Y는 본편 `RequestSkill` 경로로 전달하며 실제 처리 시 아직 홀드 중인지 확인한다. 설명에서 처리 전에 놓인 Q/Y는 늦은 차징을 시작하지 않고 거부 입력으로 기록한다. `OnboardingFlowController`가 시간을 재개하고 전환 잠금을 푼 뒤 요청하므로 입력 텔레메트리는 현재 목표에서 기록된다. 설명 중 시점 입력만 `PlayerMotor.ApplyOnboardingLookInput`으로 직접 반영한다. 이 경로는 온보딩 프롬프트가 켜졌을 때만 활성화되며 본편 좌클릭·Q/Y 입력, 차징 취소와 게이지 소비 규칙은 바꾸지 않는다. Unity 컴파일·Play 검증 결과는 [온보딩 명세](온보딩.md)의 최신 행동 안내 기록을 따른다.
- 2026-10-24 패링 좌클릭 일섬 복구(현재 규칙):
  - 패링 집중 중 좌클릭은 `TryBeginParrySwordWave`로 일섬을 시작한다. 일섬 게이지가 0이어도 사용할 수 있고 현재 잔량을 소비하지 않는다. 실제 시전이 시작되면 해당 패링 집중 기회를 사용하며, 기존 일섬 돌진·검기·피해·시전 집중 연출을 적용한다.
  - Shift/패드 전용 일섬 입력은 비활성화했다. 패링 집중 밖에서는 좌클릭 일섬을 사용할 수 없다. 좌클릭 일섬 입력은 `PlayerInputKind.SwordWave`로 기록하며 실제 사용 횟수는 기존 스킬 시작 로그를 따른다.
  - 극한 회피 집중 중 좌클릭은 제자리 일반 공격만 요청한다. 일반 공격을 해도 집중을 즉시 끝내지 않으며 남은 1초를 유지한다. 집중 중 대상 돌진·반격 대상 대시와 실의 적 연결은 금지한다.
  - `Player.prefab`의 `PlayerEmpower`에서 `_readyDuration=3`, `_dodgeReadyDuration=1`을 사용한다. `PlayerController._enableBulletTimeDashAttack=false`이며 대상 선택 경로도 집중 중에는 후보를 반환하지 않는다.
  - 일섬 게이지 획득 데이터와 칼 구슬 표시는 유지하고, `BambooDefenseHud.prefab/PerfectParryTokens` 오브젝트를 비활성화해 화면의 세 칸 게이지를 숨겼다. 거합 HUD·자원·Q 입력은 유지한다. 온보딩 안내 문구·단계 개편은 이번 범위에 포함하지 않는다.
  - 이 항목은 아래 기록의 Shift 일섬·집중 대상 돌진·집중 중 일반 공격으로 즉시 종료하는 규칙보다 우선한다. 실제 Play 입력과 연출은 미확인이다.
  - 검증: Unity 재컴파일 오류 0건·경고 0건. Editor에서 저장된 Player 프리팹의 패링 3초·극한 회피 1초·집중 대상 돌진 false와 HUD 프리팹의 `PerfectParryTokens.activeSelf=false`를 재조회했다. 현재 열린 BambooStage1의 게이지 인스턴스도 비활성 상태였고, Defense 씬들에 이 설정을 덮어쓰는 별도 속성은 없었다. 테스트 코드는 추가하지 않았다.
- 2026-10-24 수리검 제거 연출: 일섬 돌진·검기와 거합에 제거되는 일반·보스 수리검은 현재 위치에서 두 조각으로 갈라진 뒤 중력으로 낙하하고 바닥 접촉 시 사라진다. 원본 비행·공격은 즉시 종료한다. 상세는 [수리검 절단과 낙하](수리검_절단_낙하.md)를 따른다.
- 2026-10-24 피해량 조정: Shift 일섬의 돌진·검기는 `PlayerSwordWaveLauncher`가 참조하는 `Assets/Resources/Prefabs/Effects/PlayerSwordWave.prefab`의 `DefenseSwordWave._damage` 20을 사용한다(기존 명세 30). Q 거합은 `PlayerEmpowerStrike._damage`를 사용하며 코드 기본값과 `Player.prefab` 값을 50에서 100으로 변경한다. `EnemyCombatService`의 `IaidoFinisher`는 대상 돌진 발도이며 Q 거합이 아니다. 일반·대시 공격 피해량 `_normalDamage`는 10이다.
- 2026-10-24 일섬 집중 변경: Shift 입력 후 출발 대기 0.08초부터 실제 돌진 종료까지 세계는 0.1배, 플레이어는 1배로 진행한다. `PlayerEmpower.Update`는 `PlayerSwordWaveLauncher.IsDashSequenceActive`가 끝날 때 집중을 해제하므로 거리 비율이나 최대 유지 시간으로 돌진 도중 감속을 풀지 않는다. 벽 충돌로 돌진이 일찍 끝나거나 취소·사망하면 집중도 종료한다. 돌진 거리가 0인 설정에서만 `_swordWaveFocusDuration`을 사용한다. 기존 타격 정지와 집중 페이드 연출은 유지한다. 아래 2026-10-23의 앞 1/4 거리·플레이어 0.5배 설명은 이전 설정이다. 출발 대기 시간과 집중 해제 시점은 아래 2026-10-24 일섬 돌진 조정이 대체한다.
- 2026-10-24 일섬 돌진 조정(사용자 요청, 이 절이 위 집중 변경의 대기·해제 설명보다 우선): 순서는 감속 → 제자리 멈춤 → 적은 느린 상태에서 플레이어만 돌진 → 해제 거리 이후 원래 시간이다.
  - 돌진: `PlayerSwordWaveLauncher._dashDistance` 24m(기존 18m), `_dashDuration` 0.123초로 평균 약 195 m/s다. 18m/0.3초(60 m/s)에서 5배(300 m/s)로 올린 뒤 그 속도의 65%로 조정했다. 감속 곡선 1-(1-t)²은 그대로다.
  - 멈춤: `_dashStartDelay` 0.1초는 집중 페이드 인(`PlayerEmpower._swordWaveFocusFadeIn` 0.04초)이 끝난 뒤부터 센다. `PlaySkill`이 두 값을 더해 Shift 입력 후 0.14 실시간 초에 돌진을 시작한다.
  - 해제: `PlayerEmpower._swordWaveFocusReleaseDistance` 18m를 새로 두었다. `PlayerEmpower.Update`는 `DashProgress × DashDistance`가 이 거리를 지나거나 돌진 순서가 끝나면 집중을 푼다. 세계 시간 요청은 즉시 해제되고 화면·소리는 기존 페이드 아웃 0.06초로 빠진다. 계산상 돌진 시작 후 약 0.06초에 풀리고 남은 6m는 원래 시간으로 간다.
  - 적 몸 무시: 일섬 돌진은 `PlayerMotor.ApplyCombatPush(..., ignoreEnemyBodies: true)`로 시작한다. 밀림 동안 코드 몸 막힘(`MoveCharacter`의 캡슐 자르기·밀어내기)을 건너뛰고, 몸 충돌체가 있는 적(투척수·쌍둥이 보스)은 `Physics.IgnoreCollision`으로 CharacterController와의 충돌을 끈다. 밀림 종료·벽 충돌·`ClearInput`·다음 밀림 시작·비활성화 때 다시 켠다. 벽과 지형에서만 멈춘다. 빠른 돌진에서 몸이 판정보다 먼저 적에 닿아 중간에 멈추던 문제를 고친 것이다. 막기·보스 공격 밀림 등 다른 호출은 기존처럼 적에게 막힌다. 살아남은 적 몸 안에서 돌진이 끝나면 다음 이동에서 밀려난다.
  - 타격 정지: `_hitStopDuration` 0.01초(기존 0.02), `_hitStopBulletTimeMaxDuration` 0.015초(기존 0.03)로 절반이다. 집중 중 실제 정지는 0.015초, 집중 해제 뒤는 0.01초다.
  - 값은 코드 기본값과 `Player.prefab`에 함께 적었다. 검증: C# 프로젝트 빌드 오류 0개·기존 경고 16개. Unity Play 체감·벽 충돌·보스 통과·IgnoreCollision 복구는 미확인이다.
- 2026-10-24 Q 홀드 거합(사용자 요청, 이 절이 아래 Q/패드 Y 설명보다 우선):
  - 입력: Q/패드 Y를 누르면 기존 `TryBeginAutomaticCharge` 조건(거합 100%, 사망·일시정지·다른 스킬·회피 아님)으로 차징을 시작한다. 이름은 유지했지만 `IsAutomaticCharging`은 이제 홀드 차징 중을 뜻한다. `InputManager.Update`는 차징 중 `_ultimateInput.IsPressed()`가 거짓이면 `PlayerEmpower.CancelCharge`를 호출한다. 다 차기 전에 떼면 감속·준비를 끝내고(`Cancelled`) 게이지를 소비하지 않는다. 끝까지 누르면 `_ultimateChargeDuration` 1.5 실시간 초(아래 홀드 시간 2배 조정, 처음 구현은 0.75초)가 지나는 순간 `TryBeginStrike`로 자동 발동하며 이때 게이지를 전부 소비한다.
  - 누르는 시간 = 감속 시간: `_chargeSlowDuration`(0.7초) 필드를 지우고 세계 감속 곡선(`UpdateChargeSlow`, 0.2배→0.1배 SmoothStep)과 `ChargeSlowProgress`도 `_ultimateChargeDuration`을 쓴다. 다 누른 순간 목표 배율에 닿는다. `Player.prefab`의 `_chargeSlowDuration` 직렬화 값도 지웠다. `ChargeSlowDuration` 속성은 남겨 `_ultimateChargeDuration`을 반환하므로 쌍둥이 보스 자동 역거합(`TwinHumanIai`) 감속도 같은 값을 따른다(현재 1.5초).
  - 일시정지: 기존처럼 차징 타이머가 멈춘다(`ClearHeldInput`은 홀드 차징을 취소하지 않음). 재개 후 첫 입력 프레임에 Q가 눌려 있지 않으면 취소한다. 창 포커스를 잃어 입력이 풀려도 같은 검사로 취소한다. 게이지가 차기 전부터 누르고 있던 Q는 100%가 되어도 차징을 시작하지 않으며 다시 눌러야 한다.
  - 진행 표시: `UltimateHoldProgressRing`(MaskableGraphic)이 수리검 방향 인디케이터 원(마커 반지름 230·두께 4)의 안쪽 외곽을 따라 반지름 223·두께 6의 흑백 원형 진행 바를 그린다. 검은 바탕 위에 흰 진행 구간이 12시부터 시계 방향으로 `ChargeProgress`만큼 차오르며 `IsAutomaticCharging` 동안만 보인다. 기능 구현용 임시 외형이다. 하단 원형 거합 게이지는 기존처럼 차징·시전 중 숨긴다.
  - 온보딩: 같은 `InputManager`를 쓰므로 온보딩 거합도 홀드로 동작한다. 홀드 취소는 `Ended(Cancelled)`라 거합 실패 복구로 처리되지 않는다. 2026-10-24에는 설명을 Q/Y 홀드로 맞추고 중앙 원형 진행 바를 공용 HUD에서 재사용했다. 온보딩 단계와 Inspector 문구는 [온보딩 명세](온보딩.md)를 따른다. 본편 게이지·피해·보상은 변경하지 않았다.
  - 검증: 새 스크립트를 포함한 임시 csproj 복사본 `dotnet build` 오류 0개·기존 경고 16개. Unity Editor 재컴파일·Play(홀드·취소·감속 체감·링 표시·차징 비네트 아래 가독성)는 미확인이다.
- 2026-10-24 거합 홀드 시간 2배(사용자 요청): `PlayerEmpower._ultimateChargeDuration`을 코드 기본값과 `Player.prefab` 모두 0.75초에서 1.5초로 늘렸다. 이 값 하나가 누르고 있어야 하는 시간, 세계 감속(0.2배→0.1배) 시간, 원형 진행 바가 차는 시간을 함께 정하므로 모두 1.5초가 된다. `ChargeSlowDuration`을 읽는 쌍둥이 보스 자동 역거합 감속도 1.5초에 걸쳐 내려가며, 반격 연출 길이(`CounterChargeDuration` 1.5초)는 바뀌지 않는다. 검증: `Assembly-CSharp.csproj` `dotnet build` 오류 0개·기존 경고 16개. Unity Play 체감은 미확인이다.
- 동작 조건 및 처리 흐름:
  - 패링: 일섬 +1칸, 거합 최대량의 정확히 1/3. 극한회피: +0.5칸/+20%p.
  - 일반 적 처치: 일반 공격 또는 대시 공격으로 처치하면 일섬 +0.1칸(한 칸의 10%)/거합 +2%p. 일섬으로 처치하면 거합만 +2%p.
  - 보스 일반 공격 또는 대시 공격 유효 적중: 거합만 +5%p.
  - 게이지 상한에서 초과분을 버린다. 자원은 새 플레이어에서 0이며 같은 인스턴스의 일반전→보스전에서는 유지한다.
  - Shift/패드 RT: 자유 상태에서 일섬 1칸 이상일 때 예약 없이 시전하고 1칸 소비한다. 돌진·검기는 기존 순서를 따르며 종료·사망에서 시간 요청/FOV를 해제한다. 일섬 집중 연출은 아래 2026-10-23 조정을 따른다.

#### 연결 및 협업

- 사용자 승인: 리메이크 계획 실행, luna-max 구현·어려운 통합은 sol 조정자가 직접 수행. 최신 보상 조건은 패링당 정확히 1/3, 일반 적 일반/대시 처치 일섬 +0.1칸·거합 +2%p, 일섬 처치 거합 +2%p, 극한회피 거합 +20%p, 보스 일반/대시 적중 거합 +5%p다.
- 최초 M1·M2 작업과 거합 HUD 프리팹 이전 작업에서는 온보딩 입력·목표 개편을 제외했다. 2026-10-23 본편 입력·게이지 규칙 동기화에 이어 2026-10-24에는 온보딩 4단계 목표와 일섬 입력, 5단계 홀드 안내를 갱신했다. 온보딩의 `OnboardingFlowController`는 `BambooDefenseHud.prefab`의 `PlayerUltimateHint`와 활성 `UltimateHoldProgressRing`을 사용한다. 온보딩 전용 진행은 [온보딩 명세](온보딩.md)를 따른다. 2026-10-24 동기화 작업은 Unity 배치 컴파일의 라이선스/WMI 초기화 실패와 .NET 프로젝트 복원 실패로 컴파일 확인을 마치지 못했고, 편집기 UI 자동 조작이 자동 승인 검토에서 거부되어 실제 Play 동작은 미확인이다.
- 현재 브랜치는 feature/skill이며 Git CLI·커밋·푸시는 수행하지 않는다. Sites/Apps Script 배포는 포함하지 않는다.
- 이전 토큰·홀드 규칙의 날짜별 기능명세는 과거 기록이며 정식 전투의 현재 규칙은 이 문서를 우선한다.
- 2026-10-24 Q 홀드 거합: 진행 바는 [대숲 방어](대숲_방어.md) HUD의 `ShurikenDirectionCanvas`에 자식 `UltimateHoldProgress`로 추가했다. `ShurikenDirectionIndicator`·`DefenseDirectionMarker` 코드와 마커 값은 바꾸지 않았고, 진행 바는 `ShowShurikenIndicators` 설정과 무관하게 차징 중 표시된다. 이 캔버스는 정렬 3이라 차징 비네트(`EmpowerOverlay`, 정렬 100) 아래에 그려진다.
- 2026-10-23 불릿 타임 발도(feature/bullet-time-dash-attack 병합): 패링·극한회피 집중 중 실이 연결된 적이 있으면 좌클릭은 일반 공격 대신 발도 돌진을 요청한다. 돌진이 시작되면 집중을 끝내고 실제 시간으로 돌진·베기하며(Player.prefab `_dashBulletTimeRatio` 0) 게이지는 바꾸지 않는다. 돌진 중 일반 공격 부채꼴 휩쓸기 피해도 `Normal` 문맥이라 보스 적중 보상 대상이다. 일섬 집중·거합 자동 차징 중에는 발도를 허용하지 않는다. 도착 베기(`IaidoFinisher`)의 보스 적중도 현재 거합 +5%p 대상이다. 상세는 [1인칭 근접 교전](1인칭_근접_교전.md)의 2026-10-23 절을 따른다.
