### 1인칭 근접 교전 1차 구현

#### 2026-10-23 불릿 타임 발도 돌진

- 기능 설명: 좌클릭 대상 돌진을 꺼 둔 상태(아래 2026-10-22 시험 1)에서도 불릿 타임(쳐내기·극한 회피 성공 집중) 중 첫 좌클릭은 [돌진 대상 실](돌진_대상_실_표시.md)이 연결된 적에게 발도 돌진을 사용한다. 실이 연결된 적이 없으면 정식 전투에서는 제자리 부채꼴 일반 공격이다. 같은 날 main에서 병합한 [특수 스킬 게이지](특수스킬_게이지.md)로 일섬은 Shift/RT, 거합은 Q/Y 전용 키가 됐고, 쳐내기 집중의 좌클릭 일섬은 레거시 온보딩에만 남았다. 돌진이 시작되면 불릿 타임이 끝나 실제 시간으로 돌진하고 벤다(돌진 전 예고 감속 0.12초는 유지). 돌진하는 동안 일반 공격 사거리의 1.5배 부채꼴로 경로의 적을 계속 판정해 피해를 준다. 불릿 타임 밖의 좌클릭은 계속 제자리 부채꼴 공격이다.
- 동작 조건 및 처리 흐름:
  1. 허용 조건: `PlayerController._enableBulletTimeDashAttack`(코드 기본 true, Player.prefab 1)이 켜져 있고 `PlayerEmpower.IsReady`(쳐내기 히트스톱 포함)이며 일섬 집중(`IsSwordWaveFocusing`)과 거합 자동 차징(`IsAutomaticCharging`)이 아니면 `IsBulletTimeDashReady`가 참이다. 두 스킬도 같은 준비 단계를 쓰므로 따로 제외한다. `TryGetTargetedDashCandidate`는 이때만 `TrySelectIaidoTarget(..., targetedAttack: true, bulletTimeDash: true)`로 후보를 내므로 실도 불릿 타임 동안만 적에게 연결된다. 대상 규칙(생존·화면 중앙 영역의 공개 콜라이더·대상 돌진 최대 거리·돌진 경로)은 기존 대상 돌진과 같다. 중앙 영역은 `PlayerController._targetedCenterScreenRatio`(코드 기본 1/3, Player.prefab 0.2)의 가로·세로 비율이고, 최대 거리 `_targetedIaidoMaxDistance`는 Player.prefab 16m(이전 8m)다. 실 표시도 같은 값을 쓴다.
  2. 입력: `InputManager.RequestAttack`이 `HasBulletTimeDashTarget`(허용 조건과 실 후보)으로 판단해 `RequestNormalAttack(..., bulletTimeDash)`에 넘긴다. 참이면 `KatanaCombatCoordinator.RequestBulletTimeAttack`을 호출하며, 레거시 온보딩의 좌클릭 일섬보다 우선한다. 이 메서드는 `_bulletTimeDashRequested`를 켠 채 `RequestAttack`을 실행해 `RequestTargetedIaidoAttack(strike, true)`·`TryChainTargetedIaidoAttack(..., true)`가 대상 돌진을 허용하게 한다. 공격이 예약되면 예약 공격이 시작되거나 버려질 때까지 플래그를 유지하고, 그 뒤 입력에는 이어지지 않는다. 따라서 돌진은 첫 타만이고 이후 연계는 제자리 부채꼴 공격이다.
  3. 거합 차징과의 관계: 정식 전투의 거합은 Q/Y 자동 차징이라 좌클릭과 겹치지 않는다. 레거시 온보딩에만 남은 좌클릭 홀드 차징을 일찍 떼면 `ResolveUltimateCharge`가 차징을 멈추기 전에 대상을 확인해 발도를 요청한다. 극한 회피 준비는 차징 취소와 함께 감속이 끝나므로 이 경우 아래 불릿 타임 유지는 없다.
  4. 납도 중 입력: 쳐내기 모션이 끊기지 않고 끝난 뒤나 가드를 놓은 뒤의 납도(0.3초) 중이면 `RequestAttack`이 납도를 끊고 바로 `RequestTargetedIaidoAttack(1, true)`를 시도한다. 그 순간 대상이 없으면 기존처럼 1타를 예약한다. 이전에는 예약된 동안 불릿 타임이 먼저 끝나고 납도 뒤 정상 속도에서 대상을 다시 골랐다.
  5. 회피 중 입력: `PlayerController.BeginTargetedDashAttack`이 `PlayerMotor.CancelDodge`로 남은 회피 이동을 끊고 현재 위치에서 방향·거리를 정해 돌진한다. 이전에는 회피 이동이 끝날 때까지 돌진이 미뤄지고 클릭 위치 기준 방향·거리를 그대로 써 빗나갔다. 회피 무적·잔상 판정은 회피 시작 시각 기준이라 바뀌지 않는다. 모든 대상 돌진에 적용되며, 반격 대시는 회피가 반격 기회를 지우므로 해당하지 않는다.
  6. 불릿 타임 유지: 공격이 수락되면 `PlayerEmpower.CompleteReadyWithDash`가 플레이어가 돌진 중일 때 `_dashHeld`를 켠다. `_dashBulletTimeRatio`(코드 기본 0.5)의 거리까지 불릿 타임(세계 0.2배·플레이어 0.5배)을 유지한다. 현재 Player.prefab 값은 0이라 돌진 시작 때 바로 끝나 실제 시간으로 돌진한다(이전 0.5). 대상 돌진 속도 `PlayerMotor._iaidoSpeed`는 Player.prefab 36.4m/s(이전 28m/s, 1.3배)이고 최대 16m를 약 0.44초에 지난다. 출발 전 `PlayerMotor` 돌진 예고 감속(세계 0.35배, 0.12초)은 그대로다. `UpdateDashHold`가 `PlayerMotor.DashProgress`가 비율에 닿거나 돌진이 끝나면(도착·벽·회피·사망) 준비를 `Attack`으로 끝낸다. 예약되거나 일반 공격으로 바뀌었으면 바로 끝낸다. 비율 0이면 돌진 시작 때 끝낸다. 스킬 게이지는 바꾸지 않으며, 도착 베기(`IaidoFinisher`)의 보스 적중은 기존 규칙대로 거합 보상 대상이다.
  7. 유지 중 상태: `IsReady`는 거짓이라 실 후보·준비 비네트가 없고 준비 만료 시간도 흐르지 않는다. Shift 일섬·Q 거합은 플레이어가 자유 상태가 아니라 거부된다. `IsBulletTimeActive`는 참이라 플레이어 시계 배율·피격 무적·퍼펙트 파동 공개·비·윤곽 강조는 유지된다. `PlayerBulletTimeAudio`는 `IsDashBulletTimeHeld`로 불릿 타임 소리를 유지한다. 쳐내기 히트스톱 중 입력이면 히트스톱을 바로 끝내고 불릿 타임 배율로 바꾼다. 유지 중 새 쳐내기·극한 회피·보스 받아치기는 유지를 먼저 끝낸 뒤 시작한다(같은 소유자 시간 요청은 중복 등록되지 않음).
  8. 돌진 중 휩쓸기: `PlayerController._sweepDuringTargetedDash`(코드 기본 true, Player.prefab 1)가 켜져 있으면 대상 돌진 동안 `Update`의 이동 뒤와 `HandleDashEnded`의 도착 직후에 `SweepTargetedDash`가 `EnemyCombatService.SweepDashFanAttack`을 호출한다. 기준은 시점 원점과 돌진 방향, 사거리는 일반 공격 사거리(Player.prefab 4.5m)에 `_targetedDashSweepRangeMultiplier`(코드 기본 1, Player.prefab 1.5)를 곱한 6.75m이고 각도·근접 반경은 일반 공격 부채꼴(120°, 1.5m)과 같다. 돌진 시작 예고 감속 중에도 판정한다. 같은 돌진 행동 ID 동안 적(공유 체력 묶음)마다 일반 피해 10을 한 번만 주고, 같은 호출의 묶음 상대는 혈흔만 낸다. 무적인 적은 건너뛰어 다음 프레임에 다시 검사한다. 도착 베기 대상과 그 묶음은 빼서 도착 베기만 맞는다. 피해 문맥은 `Normal`이라 보스 적중이면 거합 보상 대상이다. 플레이어 타격음·이펙트를 내는 `AttackContactResolved`는 행동당 한 번만 처리되므로 휩쓸기에서 알리지 않고 도착 베기에 남겨 둔다. 반격 대시에는 적용하지 않는다.
- 구현 상태: 코드와 Player.prefab 설정 완료. main(특수 스킬 게이지)을 병합하며 Player.prefab·InputManager.cs·PlayerEmpower.cs 충돌을 해결했다. Player.prefab은 `_dashBulletTimeRatio` 0.5와 main의 거합 자동 차징 0.75초를 함께 둔다. 자동 병합으로 생긴 `PlayerEmpower._motor` 중복 선언은 main 쪽만 남겼다. 병합 뒤 C# 빌드 오류 0개, 경고 16개는 변경 파일 밖이다. #### 2026-10-22 일반 공격 시험 1: 대상 돌진 끄기와 수평 부채꼴 판정

- 기능 설명: 좌클릭 대상 돌진(발도 돌진)을 끄고, 좌클릭은 항상 제자리 일반 공격을 사용한다. 일반 1·2타 피해 판정은 칼날 궤적 대신 시점 수평 정면의 부채꼴로 처리해 범위 안의 적 전원에게 피해 10을 준다. 사용자 시험 요청이며 두 번째 시험(돌진 후 범위 베기)은 별도 브랜치에서 진행한다.
- 대상 돌진 끄기: `PlayerController._enableTargetedDashAttack`(코드 기본 true, Player.prefab 0)이 꺼져 있으면 `TrySelectIaidoTarget(..., targetedAttack: true)`가 바로 false를 반환한다. 따라서 `RequestTargetedIaidoAttack`·`TryChainTargetedIaidoAttack`이 대상 돌진을 시작하지 않아 `KatanaCombatCoordinator.RequestAttack`이 일반 공격으로 이어지고, `TryGetTargetedDashCandidate`도 후보를 내지 않아 [돌진 대상 실 표시](돌진_대상_실_표시.md)가 숨는다. 쳐내기 반격 대시(`RequestCounterDashAttack`)는 손대지 않았다(현재 반격 기회 시간 0).
- 수평 부채꼴 판정: `EnemyCombatService._useNormalAttackFan`(Player.prefab 1)이 켜져 있으면 `ResolvePlayerBladeAttack`이 `ResolveFanAttack`으로 대신 판정한다. 기준은 `PlayerMotor.ViewOrigin`과 `ViewForward`의 수평 방향, 사거리는 `PlayerController._normalAttackRange`다.
  - 대상 수집(`CollectFanTargets`): 같은 씬의 생존 적마다 피격 콜라이더에서 시점 원점에 가장 가까운 점을 구해 수평 거리·각도를 잰다. 사거리 안이고 부채꼴 반각(`_normalAttackFanAngle` 120도의 절반) 안이면 대상이다. 근접 반경(`_normalAttackNearbyRadius` 1.5m) 안이면 정면 반원(좌우 90도) 안에서 각도와 관계없이 대상이다. 시점 원점이 콜라이더 안이면 항상 대상이다.
  - 차폐(`IsFanTargetBlocked`): 시점 원점에서 그 점까지 `_attackMask` 장애물(플레이어·적 제외)이 있으면 제외한다. 바닥에 닿아 빗나감으로 끝나던 칼날 궤적 판정의 문제를 없앴다.

#### 4단계: 짧은 전후·좌우 회피

- Space + W/A/S/D 입력으로 전후·좌우 및 대각선 회피를 시작한다. W + Space는 앞으로 돌진하고 W+A/D + Space는 전방 대각선으로 이동한다. 방향 입력이 없으면 후방 회피를 사용한다. 대각선도 정규화해 이동 거리를 동일하게 유지한다. 방향은 시작 시점의 플레이어 수평 방향으로 고정하고 시점 회전은 허용한다.
- 현재 기본 거리 4.8m·지속 0.18초·시작 기준 재사용 간격 0.6초다. PlayerMotor Inspector의 Dodge Distance·Dodge Duration·Dodge Cooldown으로 조절한다. 빠르게 시작해 감속하며 CharacterController.Move로 중력·벽·적 충돌을 유지한다. 벽 충돌·접지 상실·시간 종료에서 회피를 마친다. 실제 이동 거리는 충돌에 따라 줄어들 수 있다.
- 자유·가드·일반 공격 중 사용하며 공격과 가드를 강제 취소하지 않는다. 충전·발도·회복·사망·일시정지·공중에서는 시작하지 않는다. 피격으로 회복에 진입하거나 입력 포커스를 잃으면 진행 중인 회피를 취소한다. 별도 무적·피해 면제·스태미나·밀치기 행동은 추가하지 않는다. 2026-10-14부터 회피 허용 상태·공격 취소·무적은 [전투 판정 계약](전투_판정_계약.md)을 따른다.
- InputManager가 Space 액션을 관리하고 PlayerController.RequestDodge가 행동 상태를 제한하며 PlayerMotor가 실제 이동과 재사용 시간을 담당한다. 새 스크립트·애니메이션·씬 객체는 추가하지 않고 Player 프리팹에 기본값을 저장했다.
- 컴파일 성공. CombatTest Play에서 실제 Space+A 바인딩 입력으로 회피 활성과 수평 이동 (-1.20,0,0), 종료 후 재사용 대기 약 0.42초 및 즉시 재요청 거부를 확인했다. 기존 적의 추적만 런타임에서 잠시 꺼 이동 검증에 집중했고 씬에 저장하지 않았다. 벽·공중·가드·공격 중 회피의 개별 체감 검증은 수행하지 않았다. 테스트 파일은 작성하지 않았다.

#### 2026-10-11 회피 거리 확장

#### 6단계: FMOD 청각 신호

- 사용자가 기존 FMOD 이벤트·SoundManager·사운드 시스템을 활용한 구현과 이벤트 선택을 승인했다. 기존 Player·근접 적 3종의 프리팹을 수정하며 씬 배치·검기 Transform·HP·판정·가드·패링·회피 시간은 유지한다. 5단계의 동시 공격 제어·적 역할 분화는 이번 단계에 포함하지 않는다.

- PlayerCombatAudio는 일반·반격·발도 베기의 공통 Strike Window 시작에 스윙을 한 번 재생한다. 적중 여부와 독립이며 기존 헛스윙 결과 뒤 재생은 제거했다. 실제 적 피해음은 EnemyDamageAudio가 처리하며 근접 적 3종에 기존 컴포넌트를 연결했다. 실제 플레이어 DamageReceived에만 PlayerDamaged를 연결하므로 막힌 공격에는 피격음이 중복되지 않는다.

FMOD 프로젝트·Bank·Bus 설정은 변경하지 않았다.

#### 공격 규칙

- 플레이어는 부채꼴 대신 실제 칼날 판정 높이에서 회전 박스 기즈모를 표시한다. 현재 OverlapCapsule과 직전·현재 칼날의 다섯 지점 SphereCast 영역을 포함하는 외접 박스다. 구체·캡슐과 박스 모서리는 정확히 같지 않으며 BoxCollider를 피해 판정에 추가하지 않는다. 공격 도중 최근 검사 한 구간만 표시하고 종료 후 Gizmo Duration 동안 유지한다. 초록은 적중, 빨강은 피해 없는 접촉, 청록은 접촉 없는 검사다. 편집 모드 선택 미리보기는 현재 칼날·사거리·두께의 노란 외접 박스다. 기존 누적 궤적과 접촉점 표시는 제거했다. Player 프리팹의 Show Attack Gizmos는 true다.
- 적의 부채꼴 요약은 발 기준 높이 +0.02m에 유지하고, 상세 칼날 박스 표시는 기존 Show Blade Trajectory Gizmos 설정을 따른다. 이번 플레이어 기즈모 변경에서는 적의 설정과 실제 피해 판정을 변경하지 않는다.
- 플레이어 판정은 매 타격 샘플마다 OverlapCapsule 1회와 칼날의 다섯 지점에 대한 SphereCastAll 최대 5회다. 이동 없는 지점은 캐스트를 생략한다. 플레이어의 실제 판정은 변경하지 않았다.
- 적은 전조 시작에 대상이 보는 좌상단→우하단 또는 우상단→좌하단 내려치기를 각각 50% 확률로 선택한다. 선택한 방향은 해당 공격 동안 유지하며 실제 Box Trigger와 EnemySlash가 같은 대각선 궤적을 사용한다. 전조 중에는 시각 효과를 재생하지 않는다. 전조·베기·가드·패링 시간은 유지한다.

- 2026-10-16 오프라인 계산(Player 프리팹 계층과 `Player@KatanaSlash_1·2` 클립 곡선을 직접 샘플링, 카메라 수평·이동 흔들림 없음 가정): 1·2타 클립은 칼이 화면 가운데를 경과 약 0.2초에 지나는데 판정 구간은 0.22초에 시작한다. 그래서 칼날 중심선 기준으로 1타는 정면에서 오른쪽(약 -8°~68°), 2타는 왼쪽(약 -96°~-34°)만 지난다. 2타는 정면 가까운 적을 칼날 중심선이 지나지 않으므로 적 몸 크기에 따라 놓칠 수 있다. 사용자 결정으로 적 판정 구간은 그대로 두었다(대나무 베기만 앞당김, [대나무 베기](대나무_베기.md)).

- 적 근접은 전조 0.45초 → 베기 0.24초 → 회복 0.55초다. 적 몸 기준 높이 1.6m, 사거리 2m, 시작 -70도~종료 +70도다. 칼날 크기의 BoxCollider Trigger 하나를 베기 구간에만 활성화하고 FixedUpdate마다 위치·회전을 갱신한다. 두께는 0.24m이며 EnemySlash 및 박스 기즈모가 같은 좌표를 사용한다. 반복 SphereCast와 각도별 세부 검사는 제거했다.
- 세 근접 적 프리팹 내부에 MeleeHitbox 자식을 연결하고 루트에 Kinematic Rigidbody를 추가했다. 중력과 물리 이동은 사용하지 않으며 기존 NavMeshAgent가 이동을 담당한다. OnTriggerEnter/Stay에서 최초 접촉만 처리하고 종료·취소·가드·패링 즉시 판정 박스를 끈다. 대상 접촉 시 차폐 확인용 RaycastAll은 한 번만 수행한다. 플레이어의 기존 칼날 경로 검사는 유지한다.
- Enemy_SingleMelee와 Enemy_DeflectableMelee의 Melee Only를 켰다. 기존 씬에 추가된 돌진 컴포넌트를 삭제하지 않고 첫 프로토타입 교전에서는 근접 패턴만 선택한다. 다른 적 유형·MultiPattern의 돌진·원거리는 이전 계약을 유지한다.
- 공격 시작 쿨다운은 근접 프리팹에서 0.4초이며 실제 준비·베기·회복 동안 재공격할 수 없다. 피격 반응은 위 2단계의 타수별 경직·밀림·중단 제한 규칙을 따른다. 피격이 기존 패링 회복 시간을 단축하지 않도록 남은 회복을 보존한다.

#### EnemySlash와 시야

- 최종 사용자 지시에 따라 굵은 LineRenderer·TrailRenderer와 EnemySlashBlade 재질을 제거했다. Resources/Prefabs/Effects/EnemySlash의 원래 ParticleSystem 6개·텍스처·내부 회전을 사용한다. 전조의 시각 표시는 없다. 피해는 별도 BoxCollider만 담당한다.
- Enemy_SingleMelee·Enemy_DeflectableMelee·Enemy_MultiPattern 프리팹의 자식 SlashEffect_UpperLeft·SlashEffect_UpperRight에 EnemySlash를 중첩 프리팹으로 연결했다. 이름은 적을 마주 보는 플레이어 기준의 시작 방향이다. 각 자식의 Transform Position·Rotation·Scale을 Prefab Mode Inspector에서 직접 편집한다. EnemyCombatEffects의 Upper Left Slash·Upper Right Slash 슬롯은 각 자식 루트 ParticleSystem이다. 기존 씬 컴포넌트의 슬롯이 비어 있으면 같은 이름의 프리팹 자식을 찾아 연결한다.
- EnemyCombatEffects는 실제 AttackCommitted에서 선택된 방향의 자식만 활성화·재생한다. 코드에서 Transform을 변경하거나 카메라를 향하도록 자동 보정하지 않는다. Local 시뮬레이션 파티클은 적과 함께 이동한다. 원본 Slash17·Slash16·A35에서 만든 EnemySlash 전용 재질의 강화된 농도와 원본 텍스처·색조·소멸 곡선을 유지한다.
- 실제 방출 시간·Burst·입자 수명을 합산한 원본 표시 시간을 베기 0.24초에 맞춰 simulationSpeed만 보정한다. 공격당 한 번 재생하고 공격 종료 시 방출을 중단하며 최대 0.15초 잔광 후 비활성화한다. 취소·적 비활성화는 즉시 정리하고 원래 속도를 복원한다. 근접 검기를 런타임 생성·풀링하는 전용 추적 API는 제거했다. 기타 공격의 기존 EffectManager.Play는 유지한다.
- Melee Only 모드에서는 기존 돌진용 걷기 금지 설정이 있어도 플레이어에게 접근한다. 중복 씬 override는 첫 표현 컴포넌트만 실행한다.
- 일반 시야 옵션과 Play 모드 Outline 비활성화 분기를 제거했다. MainMapSession은 SensoryPerceptionMask를 활성화하고 감각 효과를 표시한다. ScreenSpaceOutlineFeature는 원래 감각 마스크 기반 패스를 계속 실행한다. TerrainMemory는 기존 Use Terrain Memory 설정을 따른다. URP 프로젝트 설정·렌더러 에셋은 수정하지 않았다.

#### 연결 및 협업

- 기존 Player·적·EnemySlash·SwordClash·Initializer 프리팹을 수정한다. 씬 파일이나 사용자 배치를 덮어쓰지 않는다. 단일 피해·방어 결정 후 표현이 따라가는 구조를 유지한다.
- 팀원이 새 공격을 추가할 때 실제 칼날 GetBladePose와 피해 구간을 먼저 정의하고 표현·기즈모에 같은 값을 전달해야 한다. 사운드는 기존 SwordHit 이벤트를 재사용했다. 별도 방어 전용 FMOD 이벤트는 추가하지 않았다.
- 직접 조정할 값은 PlayerActionDriver의 타격 시간·동작 길이·Strike Window, EnemyMeleeAttack의 사거리·높이·두께·베기 각도·전조·회복, Coordinator의 Parry Window, PlayerMotor의 Recoil Return Speed다.
- 현재 가드는 방향·시간 기반 방어 영역이다. 실제 두 검 Mesh Collider 사이의 물리 충돌, 스태미나, 적 가드 AI, 다방향 공격, 돌진·원거리의 추가 방어 규칙은 1차 범위에 포함하지 않는다.

#### 검증과 한계

- Unity C# 컴파일 성공. 현재 사용 중인 Animator에 방어 상태 3개와 기존 Motion·ActionProgress 연결을 확인했다. 편집 모드 클립 샘플로 실제 칼날 뷰모델 길이와 가드 위치를 확인했다.
