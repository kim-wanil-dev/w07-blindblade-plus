### 기능 이름

- 기능 설명: 1인칭 플레이어의 이동, 시점, 가드, 기 모으기, 일반 공격, 발도 강공격, 행동 상태 및 회복을 처리한다.
- 동작 조건 및 처리 흐름:
  - PlayerInputCommandAdapter가 프로젝트 입력 액션에서 명령으로 변환해 PlayerController에 전달한다.
  - PlayerController가 행동 상태, 기 모으기 1초, 타겟 선택, 공격 결과 및 회복을 관리한다.
  - PlayerMotor가 CharacterController 이동, 발걸음 발생, 발도 대시, 벽·적 충돌을 처리한다.
  - 발도 타겟은 현재 감지된 생존 대상 중 화면 앞쪽과 최대 거리 조건을 만족하는 가장 가까운 대상을 선택한다. 거리가 같으면 중앙에 가까운 대상, 식별자 순으로 고정한다.
  - 대상이 없으면 카메라 수평 정면으로 최대 거리 대시를 수행하며 자동 타겟을 새로 고르지 않는다.
  - 발도 대시가 적 앞에 도착하면 애니메이션/테스트 드라이버가 베기 적중 시점을 호출한다. 실제 적중과 발도 즉사는 전투 계약의 결과로만 확정한다.
  - 대시 충돌은 전투 계약으로 적인지 먼저 확인하고, 적이 아니면 맵 계약에 벽 파괴와 통과 판정을 요청한다.
  - 공격 동작이 끝난 뒤 결과별 Recovery를 적용한다. 게임 시간에 따라 남은 시간이 감소하며 일시정지 중에는 상태와 시간이 유지된다.
- 구현 상태: 플레이어 계약, 이동·상태 제어, 입력 연결, 전투 및 이동 서비스 연결을 구현했다. 테스트 전용 월드 어댑터, 테스트 대상·벽, 플레이어 디버그 씬과 HUD는 현재 프로젝트에서 제거되었다. 실제 청각 기반 자동 타겟 연결은 미확인이다.

#### 연결 및 협업

- 연결된 기능: 발자국/사운드 감지, 적 전투, 맵 파괴, 게임 일시정지·사망, 애니메이션·이펙트·사운드 이벤트.
- 공유하는 코드 및 상태: 기존 InputSystem_Actions 액션 에셋을 읽어 쓰되 수정하지 않는다. 외부 시스템은 플레이어 계약과 PlayerActionEvent, PlayerFootstepEvent를 통해 연결한다.
- 중복 또는 충돌 사항: 적중 판정·적 사망은 적 시스템 소유, 벽 파괴는 맵 시스템 소유, 감지 결과·파동은 사운드/발자국 시스템 소유다. 플레이어 코드는 이를 중복 구현하지 않는다.
- 승인 필요 사항 및 결과: 기존 팀 시스템 또는 공유 씬을 수정하지 않았다. 다른 팀의 실제 API는 미구현이라 런타임 연동은 미확인이다.

#### 현재 플레이어 접근점

- PlayerController.Awake가 Game.Instance.RegisterPlayer(this)를 호출하고 OnDestroy가 Game.UnregisterPlayer(this)를 호출한다. Game.Player는 현재 플레이어를 반환하는 읽기 전용 static 프로퍼티이며 조회·해제 과정에서 Game을 새로 생성하지 않는다.
- 생존 플레이어가 이미 등록되어 있으면 다른 플레이어의 등록은 오류로 거부한다. 플레이어 자체의 씬 수명은 유지하며 같은 인스턴스에 대해서만 참조를 해제한다.
- StageDoor와 StageSwordNoise는 Start에서 Game.Player를 받아 사용한다. 검 소음은 해당 인스턴스의 ActionEvent를 구독하며 비활성화 시 해제하고 재활성화 시 다시 구독한다. 두 클래스에 대한 플레이어 수동 인스펙터 연결은 제거했다.
- GameSceneInitializer가 입력 어댑터, 공통 세션·게임 상태·UI 연결을 초기화한다. CorridorRoundController는 복도 규칙 옵션이 켜진 씬에서 초기화한다.
- Assembly-CSharp.csproj의 MSBuild 컴파일은 종료 코드 0으로 완료했다. 참조 버전 충돌 및 Unity 소스 생성기 로드 경고가 있어 Unity 에디터 컴파일·Play 검증을 대신하지 않는다. 씬 전환·문·검 소음 실행은 미확인이다.

#### 메인맵 피격 연결 갱신

- MainMap 플레이어에 PlayerHealth를 추가하여 기존 적 공격의 IDamageable 계약을 받는다. 가드 성공, HP 감소 및 SetDead 연결은 [플레이어 피격 및 체력](플레이어_피격_체력.md)을 따른다.
- 플레이어 입력·상태·검 표현 및 적 공격 코드를 변경하지 않았다. 사용자가 A 자동 구현 모드로 연결을 승인했다.
- 메인맵의 Combat Service Source는 EnemyCombatService이며 Perception Provider Source와 Map Service Source는 여전히 비어 있다. 실제 청각 자동 타겟·벽 파괴 연결 완료를 뜻하지 않는다.

#### 2026-10-10 웅크리기와 강공격 입력 비활성화

- `KatanaInputCommandAdapter`가 좌·우 Ctrl 홀드와 C 토글을 합쳐 `PlayerController.SetCrouchInput(bool)`으로 전달한다. 두 입력 중 하나라도 유지되면 웅크리고, 둘 다 해제되면 일어난다. 이 어댑터는 Player 프리팹에서 제거됐고, 정식 입력인 InputManager의 웅크리기 입력은 2026-10-14 제외했다([전투 판정 계약](전투_판정_계약.md)).
- `PlayerMotor`는 기본 키 설정에서 카메라 높이 1.60→1.325, `CharacterController` 높이 2.0→1.6을 0.15초에 걸쳐 낮춘다. 이전 하강량(카메라 0.55m, 캡슐 0.8m)의 절반만 낮추는 값이다. 캡슐 바닥을 유지하며 일어설 때 공간이 막혀 있으면 높이 복귀를 멈춘다.
- 웅크린 보행은 `PlayerLocomotionMode.CrouchWalking`과 0.7m/s를 사용한다. 발걸음은 기존 계약을 사용하되 `PlayerFootstepType.Quiet`, NoiseStrength 0.12로 발행한다. 정지 중에는 발걸음을 발행하지 않는다.
- 감지 구독자는 `PlayerSenseContext.LocomotionMode`에서 `Crouching` 또는 `CrouchWalking`을 확인할 수 있다. 실제 발자국 자극은 기존 `PlayerFootstepEvent`를 구독한다.
- 웅크리기 입력이 켜지는 순간 `PlayerController.EmitCrouchPulse`가 `SensoryManager.Emit`을 한 번 호출한다. 원형 파동은 `Wave.prefab`의 반경 8m·확산 0.8초 설정을 사용하고, 주변 윤곽선은 `SensoryPerceptionMask`의 반경 12m·수명 1.2초 설정으로 잠깐 드러난다. 두 거리는 각 프리팹 Inspector에서 조절하며, 웅크린 채 입력을 유지해도 반복 생성하지 않는다.
- `PlayerController._enableChargeAttack` 기본값은 false다. 끄면 BeginCharge/RequestIaidoAttack이 거부되며, 기존 전투 판정 코드는 유지한다. 정상 공격과 쳐내기 입력은 유지한다.
- 이 구현은 1인칭 카메라와 CharacterController를 낮춘다. 플레이어 전신 모델의 crouch 애니메이션은 현재 모델이 없어 구현하지 않았다.

#### 2026-10-10 일반 공격 Recovery 후 이동 입력 복귀

- `PlayerController`는 `_requestedMoveInput`에 마지막 이동 방향을 보관한다. Recovery 동안 실제 `_moveInput`과 PlayerMotor 입력은 0으로 두어 이동은 멈추지만, W를 계속 누르면 그 요청 방향을 유지한다.
- `EndRecovery()`에서 보관한 방향을 PlayerMotor에 다시 전달한다. 회복 중 W를 놓으면 입력 어댑터가 0을 보내므로 이동은 재개되지 않는다. 공격 입력을 예약하는 큐는 추가하지 않았다.

#### 게임 씬 공통 구성 전환 (2026-10-10)

- Game.Player가 현재 플레이어 접근점이며 문·검 소음·세션·라운드가 이를 사용한다. 내부 컴포넌트 참조는 유지한다. 일반/카타나 어댑터의 명령 전달은 Game 하위 InputManager가 관리하며 게임오버 중 UI 입력은 유지한다.
- 상세 계약과 검증 결과는 [게임 씬 공통 구성](게임_씬_공통_구성.md)을 따른다.

### 수평 시점 제한 (TASK_0048)

- 상하 시점 입력과 초기 카메라 기울기를 제거하고 좌우 회전을 유지한다. `ViewForward`는 수평 방향을 반환한다.
- 전투 반동은 위치 이동만 적용하며 카메라 회전은 적용하지 않는다. 웅크리기·이동의 높이 변화는 유지한다.
- 검증: 대상 프로젝트 Unity 컴파일 오류 0, 격리된 Player 프리팹에서 초기 pitch 30도와 입력 (100, 200), 반동 적용 후 yaw 12도·카메라 회전 0도·ViewForward.y 0을 확인했다. 실제 플레이 입력은 최종 통합 검증에서 확인한다.

#### 공격 중 이동 잠금

- 일반 공격 동안 PlayerController의 이동을 잠그고 PlayerMotor의 평면 속도·걸음 누적을 초기화한다. 공격 종료 시 기존 상태에 따라 이동을 재개하며 시점 회전은 유지한다. 실제 입력 플레이 확인은 미실시다.

#### 2026-10-12 계단 하강 중 스페이스 회피

- PlayerMotor는 마지막 접지 시각을 저장하고, 접지 상태이거나 접지 후 0.12초 이내면 스페이스 회피 시작을 허용한다.
- 회피 중에는 CharacterController.Move의 CollisionFlags.Below 또는 isGrounded 접촉을 기록한다. 접지가 잠깐 끊겨도 유예 시간이 끝나기 전까지 회피를 유지하며, 벽 충돌·유예 시간 초과·회피 시간 종료는 기존처럼 회피를 끝낸다.
- _dodgeGroundGraceDuration 기본값은 0.12초이며 공용 Player.prefab에서 조정한다. 계단 Play Mode 검증은 아직 미실시다.


### 카메라 상하 회전 복원 (TASK_0106)

- PlayerMotor의 수평 고정을 해제하고 상하 입력을 pitch에 반영한다. 초기 카메라 기울기를 유지하고 LateUpdate에서도 상하 회전을 유지한다. ViewForward에 상하 방향을 포함해 논리 조준과 화면을 맞춘다.
- Vertical Look Limit은 기본 89도로 위아래 각각 89도까지 허용한다. 추가 Inspector 연결은 없다. TASK_0048의 수평 고정은 이전 동작이다.
- Unity 컴파일 오류·경고 0을 확인했다. 실제 마우스 입력 플레이는 미검증이다.
