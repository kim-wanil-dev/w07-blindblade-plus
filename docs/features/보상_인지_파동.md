### 보상 인지 파동

- 기능 설명: A의 실제 패링·극한 회피 파동을 재사용하고, 같은 공개 영역을 C의 근접 적 월드 표시와 D 공통 표시 결과에 반영한다.
- 동작 조건 및 처리 흐름: A의 성공 판정 → PlayerPerfectPulse.Begin / BeginPerfectDodge → SensoryPerceptionMask.SetPulseRegion → C Resolver의 거리/파동 최대 가시성 → 공통 계약 어댑터 → 기존 D 공급자·HUD. 파동 요청 사건을 다시 구독해 중복 재생하지 않는다.
- 구현 상태: feature/reward-reveal-pulse에서 구현·C# 컴파일과 사용자 핵심 Play 확인을 마쳤다. C/D 고정 영역 판정·공개 제거·실제 회피 시간 동작을 확인해 현재 커밋 인계 시점이다. 정식 B/D 연결과 아래에 명시한 세부 시나리오는 미확인이다.

#### 확정 동작 및 이전 계획과의 차이

- 2026-10-14 사용자가 최신 A 구현을 확인한 뒤 재확인을 요청했고, 최종적으로 ②를 선택해 수정 시작을 승인했다. 패링은 A 규칙, 회피는 C의 12m·실제 시간 1.2초 확산·게임 시간 0.6초 페이드다.
- 패링: 새 강화 준비 시작에서만 발동한다. 40m까지 실제 시간 1초 확산, 강화 준비·공격 동안 공개 유지, 종료 후 실제 시간 0.8초 페이드다. 패링 링은 확산 완료 후 별도 실제 시간 0.3초 페이드이며 공개 영역보다 먼저 사라질 수 있다.
- 극한 회피: A가 회피 한 번의 첫 극한 회피 성공에서 직접 호출한다. 12m까지 실제 시간 1.2초 확산 후 유지 시간 없이 게임 시간 0.6초 페이드다. 공개 영역과 링이 함께 흐려지며 최대 반경을 축소하지 않는다.
- 극한 회피 자체는 불릿타임을 만들지 않는다. 다른 시간 요청이 0.1배이면 확산은 실제 1.2초, 이후 페이드는 실제 약 6초다. 정지 중에는 두 종류의 확산·페이드가 모두 멈춘다. C는 Time.timeScale을 쓰지 않는다.
- A의 단일 영역·우선순위를 채택한다. 패링 파동의 확산·유지·페이드 중 회피 파동은 생략되고 요청 사건도 발행되지 않는다. 회피 파동 중 패링이 발생하면 패링으로 교체하며, 회피 파동 중 새 회피 파동은 처음부터 재생한다. 기존 C의 독립 파동 16개 계획은 이 단위에 적용하지 않는다.
- 중심·지면 정렬·확산 곡선은 A 구현을 채택한다. 발동 때 발밑 지면을 찾고 중심을 고정하며, 0m에서 시작해 감속 곡선으로 퍼진다. 기존 C의 사건 Center·시작 반경 0.25m 계획을 대체한다.
- 링 기본색은 두 종류 모두 흰색이고 따로 수정할 수 있다. 반경·확산·종료 페이드·링 색상·패링 링 페이드 시간은 발동 때 복사하여 다음 파동부터 수정값을 적용한다.
- 파동 판정은 CPU와 셰이더 모두 XZ 수평거리다. 공간 경계는 마스크의 Edge Fade(기본 0.75m)를 공유하며 현재 프레임부터 반영한다. 일반 소리·상시 영역의 기존 3D 거리 계산은 유지한다.
- 근접 적 Alpha = Max(기존 개별 거리 가시성, 파동 가시성). 개별 인지 반경 0 또는 거리 밖이어도 파동으로 공개한다. 비활성·외형 없는 대상은 공개하지 않는다. 파동이 끝나면 거리 인지만 남는다.
- 색상·근접도는 기존 플레이어와 적의 거리 설정을 사용한다. 파동 중심과의 거리로 적 색상을 바꾸지 않는다. 투사체 표시·반사/통과 UI 규칙은 유지한다.
- 화면 안 적은 월드, 화면 밖 적은 방향 UI 자격을 얻는다. 적이 월드에서 공개되면 기존 C 발소리 후보가 같은 Target 결과를 읽어 발소리 UI를 숨긴다. 파동 자체가 발걸음 후보를 생성하지 않는다.
- A의 기존 지형 기억 기록과 빛줄기·비네트를 사용한다. 지형 기억은 남고 적의 위치·외형은 기억하지 않는다. PlayerPerfectPulse의 사망·비활성화·발동 당시 세션 종료/교체와 Resolver 세션 종료에서 영역을 정리한다.

#### 연결 및 협업

- 연결된 기능: 전투 판정 계약, 감각 표현, 화면 공간 윤곽선, 위협 표시 판정, 발소리 후보, D 공통 표시 계약.
- 공유하는 코드 및 상태: A가 SetPulseRegion(center, radius, visibility)을 갱신한다. C는 파동만의 가시성을 GetPulseVisibility로 읽는다. D의 DTO·Revision·HUD 코드는 변경하지 않는다.
- 필드 매핑: 기존 C Alpha에 파동 결과를 합친 뒤 Adapter가 IsEligible/WorldVisible/UiVisible/Alpha를 그대로 공통 결과로 전달한다. Position·UiDirection·Proximity·Color·식별자·세대는 기존 매핑을 유지한다.
- 중복 또는 충돌 사항: A가 이미 패링·회피 표현을 직접 재생하므로 별도 RewardRevealPulseController나 사건 구독 재생기를 추가하지 않는다. C Resolver 슬롯만 연결해도 실제 B Target 입력 연결까지 자동 생성되는 것은 아니다.
- 승인 필요 사항 및 결과: 사용자가 최신 A 구현과 C 계획 차이를 확인한 뒤 ② 및 수평거리·Inspector 링 색상 수정 범위를 승인했다. A 파일과 Player 프리팹의 변경은 위 파동 설정·수명·색상·정리에 한정한다.
- 인계: B는 실제 모델 Target과 Resolver 연결, D는 실제 Resolver의 Reward Pulse Mask와 공급자 연결을 확인한다. Player 프리팹에는 회피 12/1.2/0.6과 링 색상 필드만 추가했다. 각 팀은 씬/프리팹 override가 기본값을 가리지 않는지 확인한다.

1. Play 종료 후 C_ThreatPresentation.unity를 다시 연다. 현재 저장된 씬에는 대상 5개와 마스크가 연결돼 있다. 외부 씬 변경을 다시 읽을지 안내가 나오면 Reload를 선택한다.

5. Threat Presentation Contract Adapter Inspector에서 해당 대상의 D 전달 값 일치를 확인한다. 파동 영역 제거 후 위 파동 전용 대상들의 공개가 꺼지는지 확인한다. Near_Normal처럼 원래 거리 안인 적은 유지된다.
6. 가시성 0.5를 적용하면 거리 밖 대상 Alpha는 0.5다. 반경 10에서는 수평거리 약 10.2m인 두 ZeroRadius 대상 모두 공개되지 않는다. 마스크 비활성화 또는 세션 재시작 후 이전 파동이 다시 나타나지 않아야 한다.
7. 실제 A 시간 확인은 Assets/Scenes/Test/PlayerCombatTest.unity 등 게임 초기화가 있는 씬에서 Play하고 Hierarchy의 실제 Player → Player Perfect Pulse Inspector를 선택한다. 극한 회피 파동 표현 재생 버튼으로 반경 12·확산 1.2·페이드 0.6과 종료를 확인한다. 이 버튼은 성공 판정·환불·불릿타임을 만들지 않는다.
8. 같은 Player Inspector에서 0.1배속으로 시간 차이 관찰 → 극한 회피 파동 표현 재생을 누른다.
