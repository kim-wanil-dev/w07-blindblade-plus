# 패드 입력 및 장치별 안내

- 기능 설명: 키보드·마우스 조작을 유지하며 게임패드 입력을 기존 플레이어 행동 명령에 연결하고 마지막 실제 입력 장치에 맞게 안내 문구를 표시한다.
- 동작 조건 및 처리 흐름: InputManager가 Playing 상태에서 오른쪽 범퍼 공격, 왼쪽 범퍼 막기, A 회피, 오른쪽 트리거 일섬, Y 거합, Start 메뉴, X 상호작용을 전달한다. 왼쪽·오른쪽 스틱은 이동·시점 입력이다. Menu는 커서와 유지 입력을 정리하며 별도 일시정지 메뉴를 열지 않는다.
- 구현 상태: InputManager가 생성된 `InputSystem_Actions`의 Player 맵에서 실제 사용하는 9개 액션만 읽는다. 구형 입력 어댑터 코드는 제거했다. UI 탐색은 InputSystemUIInputModule의 기본 UI 액션을 사용한다.

## 설정 및 학습

- InputManager의 Gamepad Look Degrees Per Second 기본 180은 스틱을 끝까지 밀었을 때 초당 회전 각도다. 기존 InputManager 프리팹에서 조절한다. 마우스 감도와 별개이며 프레임 시간에 비례한다.
- 스틱은 기존 Input System 액션 및 Gamepad 스틱의 deadzone 처리를 사용한다. 장치 표시 전환은 Vector2 크기 0.25 미만, 마우스 델타 크기 0.5 미만을 무시한다. 표시 전환 임계값은 실제 이동 제한이나 추가 쿨타임이 아니다.
- Lessons의 Keys는 기존 키보드 원문이다. Gamepad Keys가 비어 있으면 현재 정식 입력에 대응하는 좌클릭→RB, 우클릭→LB, SPACE→A, WASD→왼쪽 스틱, F→X, ESC→Menu만 바꾼다. Ctrl/C 웅크리기 표기는 패드 입력이 없으므로 키보드 표기를 유지한다. 별도 패드 문구가 필요하면 Gamepad Keys를 작성한다.
- Keyboard·Mouse·Gamepad 입력 장치를 액션의 activeControl.device로 구분한다. 입력 확인과 전투 판정은 분리하며 기존 상태·피해·패링·회피 규칙을 호출한다.
- Input Actions 에셋과 동기화된 C# 래퍼를 런타임 정의의 기준으로 사용한다. 실제 Player 입력은 아래 표의 9개 액션으로 한정한다. 에셋의 미사용 UI 맵은 제거했으며, UI 모듈은 패키지 기본 액션을 자동으로 할당한다.

| 입력 | 키보드·마우스 | 게임패드 |
| --- | --- | --- |
| 이동 / 시점 | WASD·방향키 / 마우스 이동 | 왼쪽 스틱 / 오른쪽 스틱 |
| 공격 / 막기 | 좌클릭 / 우클릭 | RB / LB |
| 회피 | Space | A |
| 일섬 / 거합 | Shift / Q | RT / Y |
| 메뉴 / 월드 상호작용 | Esc / F | Start / X |

대사 진행은 `MonologueController`가 Enter 키를 직접 확인하므로 패드 바인딩이 없다. 웅크리기는 액션 맵에서 제외됐고, 옛 `TutorialGuide`의 Ctrl 기반 대기 코드에도 패드 바인딩이 없다. 현재 정식 게임의 9개 플레이어 액션에는 게임패드 바인딩 누락이 없다.

## 연결 및 협업

- 사용자 지정 매핑 및 입력 장치별 튜토리얼·문 표시 작업으로 관련 입력·문 UI 수정이 승인되었다. 적·맵 판정·애니메이션 및 튜토리얼 씬 배치는 변경하지 않는다.
- 입력 표시가 필요한 팀원은 InputDeviceDisplay.IsGamepad 또는 DeviceChanged(bool)를 읽고 FormatKeys로 표기한다. 구독한 객체는 비활성화 시 이벤트를 해제한다.
- PlayerInteraction은 InputManager의 WorldInteract 액션을 사용한다. 문 표시 문구는 OpenDoorPromptUI에서 중앙 변환한다. 메뉴 패드 UI 조작은 기존 InputSystemUIInputModule 바인딩에 따른다.
- Menu를 일시정지로 표시하거나 일시정지 메뉴가 구현됐다고 안내하면 안 된다. 차징 입력은 추가하지 않는다.

#### 2026-10-23 입력 액션 에셋 정렬

- Player 맵에 Guard, Dodge, SwordWave, Ultimate, Menu, WorldInteract 액션을 추가하고 각 키보드·마우스·게임패드 바인딩을 현재 InputManager 및 상호작용 입력에 맞췄다. Attack 게임패드 바인딩은 RB로 변경했다.
- 사용하지 않는 Interact, Crouch, Jump, Previous, Next, Sprint와 XR·Joystick·Touch 바인딩을 제거했다.

#### 2026-10-23 스크립트 연결 및 래퍼 갱신

- InputManager는 생성 래퍼의 Player 맵 액션을 사용한다. 런타임 액션 생성과 Attack 바인딩 덮어쓰기는 없다. PlayerInteraction과 온보딩 입력도 같은 액션을 읽는다.
- 미사용 입력 어댑터 두 개와 GameSceneInitializer의 초기화 경로를 제거했다. `InputDeviceDisplay`의 Ctrl/C→B 치환도 제거해 게임패드 미지원 입력을 잘못 표시하지 않게 했다.
- 입력 에셋은 Player 맵 9개 액션과 Keyboard&Mouse·Gamepad 스킴만 보유한다. UI 모듈의 기본 UI 액션과 대사 Enter 입력은 별도로 동작한다.

## 검증

- `dotnet build Assembly-CSharp.csproj --no-restore` 성공, 오류 0개. 변경하지 않은 Telemetry·Debug 파일에서 경고 16개가 보고됐다.
- `InputSystem_Actions.cs`의 내장 JSON과 `.inputactions`를 비교해 액션 9개와 바인딩 27개의 ID·이름·경로가 모두 일치함을 확인했다.
- 관리 환경의 Unity는 프로젝트를 읽기 전용으로 판정했고 별도 생성 시도는 라이선스 서비스 초기화에 실패했다. 따라서 래퍼는 에셋 정의와 일치하도록 동기화했으며, Unity Editor 공식 재생성·Console 확인과 실물 패드 조작은 미검증이다. 실제 문 개방과 튜토리얼 Play도 에디터에서 확인해야 한다. 테스트 코드·테스트 씬은 추가하지 않았다.
