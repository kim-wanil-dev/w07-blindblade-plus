# 패드 입력 및 장치별 안내

- 기능 설명: 키보드·마우스 조작을 유지하며 게임패드 입력을 기존 플레이어 행동 명령에 연결하고 마지막 실제 입력 장치에 맞게 안내 문구를 표시한다.
- 동작 조건 및 처리 흐름: InputManager가 Playing 상태에서 RB 공격, LB 가드·패링, A 회피를 전달한다. B 웅크리기 토글은 2026-10-14 제외했다([전투 판정 계약](전투_판정_계약.md)). 왼쪽 스틱은 이동, 오른쪽 스틱은 시점, X는 상호작용이다. Menu는 기존 ESC와 같은 유지 입력 정리·커서 해제이며 일시정지 메뉴를 추가하지 않는다.
- 구현 상태: 관련 스크립트 연결 완료. 공유 입력 액션 에셋과 생성 C# 및 씬·플레이어 프리팹은 변경하지 않았다. 활성 게임 입력은 InputManager이며 현 Player 프리팹과 BossBattle 플레이어의 구형 입력 어댑터 2종은 꺼져 있다.

## 설정 및 학습

- InputManager의 Gamepad Look Degrees Per Second 기본 180은 스틱을 끝까지 밀었을 때 초당 회전 각도다. 기존 InputManager 프리팹에서 조절한다. 마우스 감도와 별개이며 프레임 시간에 비례한다.
- 스틱은 기존 Input System 액션 및 Gamepad 스틱의 deadzone 처리를 사용한다. 장치 표시 전환은 Vector2 크기 0.25 미만, 마우스 델타 크기 0.5 미만을 무시한다. 표시 전환 임계값은 실제 이동 제한이나 추가 쿨타임이 아니다.
- Lessons의 Keys는 기존 키보드 원문이다. Gamepad Keys가 비어 있으면 좌클릭→RB, 우클릭→LB, SPACE→A, CTRL / C→B, F→X로 단축키 부분만 바꾼다. 예: 좌클릭 / 2연→RB / 2연. 빈 문구는 계속 비어 있다. 별도 패드 문구가 필요하면 Gamepad Keys를 작성한다.
- Keyboard·Mouse·Gamepad 입력 장치를 액션의 activeControl.device로 구분한다. 입력 확인과 전투 판정은 분리하며 기존 상태·피해·패링·회피 규칙을 호출한다.
- 공통 InputSystem_Actions 원본은 수정하지 않았다. Gamepad 공격 X 바인딩은 InputManager 인스턴스에서만 RB로 Override한다. 다른 코드가 생성 입력 액션을 별도로 사용하면 이 Override는 공유되지 않는다.

## 연결 및 협업

- 사용자 지정 매핑 및 입력 장치별 튜토리얼·문 표시 작업으로 관련 입력·문 UI 수정이 승인되었다. 적·맵 판정·애니메이션 및 튜토리얼 씬 배치는 변경하지 않는다.
- 입력 표시가 필요한 팀원은 InputDeviceDisplay.IsGamepad 또는 DeviceChanged(bool)를 읽고 FormatKeys로 표기한다. 구독한 객체는 비활성화 시 이벤트를 해제한다.
- 문 두 경로는 InputDeviceDisplay.InteractPressed를 사용한다. 표시 문구는 OpenDoorPromptUI에서 중앙 변환한다. 메뉴 패드 UI 조작은 기존 InputSystemUIInputModule 바인딩에 따른다.
- Menu를 일시정지로 표시하거나 일시정지 메뉴가 구현됐다고 안내하면 안 된다. 차징 입력은 추가하지 않는다.

## 검증

- Unity 스크립트 컴파일 후 Console 오류 0건 확인. 현재 씬/공유 Player 프리팹의 구형 어댑터 비활성 상태를 에디터에서 확인했다.
- 실물 패드 버튼·스틱 이동·시점 속도, 게임 도중 장치 전환 표시, 실제 문 개방 및 튜토리얼 전체 Play는 미확인이다. 별도 테스트 코드·테스트 씬을 추가하지 않았다.
