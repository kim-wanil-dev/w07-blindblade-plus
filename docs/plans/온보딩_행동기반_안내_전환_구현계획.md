# 온보딩 행동 기반 안내 전환 구현 계획

- 작성일: 2026-10-24
- 상태: 코드·HUD·씬 저장값·Builder·기능명세 반영 완료. .NET 컴파일은 참조 자산 파일 부재로 시작하지 못했고, Unity 배치 실행은 로그를 만들지 않아 Editor 컴파일 성공을 확인하지 못했다. 실제 Play 검증은 미확인.
- 목적: 설명을 닫기 위한 별도 좌클릭/RB 5회를 제거하고 실제 학습 행동으로 설명과 연습을 연결한다.
- 선행 기준: `온보딩_패링일섬_Q홀드_동기화_구현계획.md`의 5단계·실제 패링 집중·Q/Y 홀드 구현.
- 우선 규칙: 이 계획은 선행 계획의 ‘설명 클릭 소비 후 다음 클릭으로 일섬’, ‘거합 설명을 좌클릭으로 먼저 닫기’, ‘계속 진행 문구 유지’를 대체한다. 나머지 성공 조건과 본편 전투 규칙은 유지한다.

## 1. 범위와 완료 기준

- 1단계 이동 파동과 5단계 첫 거합 게이지 설명은 플레이를 막지 않는 안내로 바꾼다.
- 2단계 극한 회피 성공 설명은 완료 카드의 복습에 통합한다.
- 4단계는 설명 화면의 새 좌클릭/RB 한 번으로 실제 일섬을 요청한다.
- 5단계는 설명 화면의 새 Q/Y 누름으로 실제 차징을 시작하고, 같은 누름을 유지해 거합을 발동한다.
- 일섬·거합 첫 설명은 읽을 시간을 보장하기 위해 실제 세션 정지를 유지한다. 시점 조준은 허용하고, 이동·방어·회피·다른 공격은 차단한다.
- 단계 시작·목표 갱신의 자동 카드는 유지한다. 단계 완료의 다음 단계/다시 연습 선택도 유지한다. 자동 다음 단계나 새 단축키는 이번 범위에 넣지 않는다.
- 목표 성공은 실제 방어·발사·시전·처치 사건으로만 판정한다. 안내가 닫혔거나 키를 눌렀다는 이유로 목표를 완료하지 않는다.
- 실제 시간 1초 완료 대기, 극한 회피 수리검 정리, 단계 반복 시 자원 복원, 내부 일섬 자원·검 구슬, 본편 피해·보상·집중 길이·멀티킬은 유지한다.
- 테스트 코드 작성 금지. 가능한 런타임/Editor 컴파일 및 아래 수동 Play 검증을 수행한다.

## 2. 현재 코드에서 확인한 제약

- `InputManager`는 실행 순서 -40이다. Flow가 뒤에서 잠금을 풀기만 하면 해당 프레임의 입력은 이미 지나갔을 수 있다. 같은 프레임의 `WasPressedThisFrame`을 다시 읽는 우연에 의존하지 않는다.
- 기존 `ApplyOnboardingAttackInput`은 실제 RequestAttack을 호출하지만 이동 전달·버튼 소비까지 포함한다. 목적을 확인하고 필요한 부분만 재사용한다. 이를 거합 입력 인계나 일반적인 설명 종료 API처럼 무조건 호출하지 않는다.
- 선행 작업의 Unity 컴파일/Play는 미확인으로 기록돼 있다. 기존 기록을 이번 검증 성공으로 간주하지 않는다.

## 3. 단계별 동작

### 3.1 1단계 이동 파동

1. 기존 실제 `PlayerRippleEmitted` 사건을 안내 시작 근거로 유지한다.
2. 최초 파동이 보일 때 짧은 설명을 표시하되 세션 정지·전투 입력 잠금·확인 클릭을 사용하지 않는다.
3. 기본 표시 시간은 실제 시간 4초, 사라지는 시간은 0.2초로 두고 Inspector에서 편집한다. 메뉴 일시정지/앱 비활성 중에는 읽기 시간을 소모하지 않는다.
4. 기존 기본 조작 HUD는 계속 남긴다. 플레이어가 공격하거나 이동해도 안내를 닫기 위한 입력 소비가 없어야 한다.
5. 정지된 파동 위치를 가리키던 연결선은 움직이는 화면에서 잘못된 위치에 남기지 않는다. 추적이 불필요한 정보 안내에서는 연결선을 숨기는 방식을 우선한다.
6. 단계 완료·재시작·씬 전환 시 안내와 타이머를 정리한다.

### 3.2 2단계 극한 회피

- 성공 판정 직후 기존 수리검 무해화·정리를 유지한다.
- 별도의 정지 설명과 `WaitForTutorialClick`을 제거한다. 파동·감속의 의미는 완료 카드의 기존 Inspector 복습 문구로 전달한다.
- 기존 파동 종료 대기와 씬이 움직이는 실제 시간 1초 대기를 유지하고 완료 선택을 표시한다. 새 설명 읽기용 대기를 추가하지 않는다.
- 제거되는 설명 필드의 문구가 완료 카드와 다르면 필요한 의미만 통합한다. 완료 카드의 사용자 문구를 통째로 기본값으로 덮어쓰지 않는다.

### 3.3 3단계 막기·쳐내기

- 실제 막기→쳐내기 두 목표, 주변 힌트와 가드 타이밍 표시를 유지한다.
- 새 확인창이나 행동 대기 상태를 추가하지 않는다.

### 3.4 4단계 일섬

1. 실제 훈련 수리검 쳐내기 성공으로 일섬 목표를 열고 표적을 준비한다.
2. 첫 설명 동안 실제 패링 집중을 세션 정지로 보존한다. 가짜 준비 상태·추가 게이지·무한 집중 API는 사용하지 않는다.
3. 설명이 표시된 뒤 새로 누른 좌클릭/RB만 수락한다. 설명 진입 전에 이미 누른 버튼은 먼저 놓아야 한다. 설명을 띄운 프레임의 이전 입력을 재사용하지 않는다.
4. 조준은 허용한다. 중앙 표적을 가리는 큰 패널은 기존 글꼴·색상을 유지하면서 하단 설명 영역으로 배치한다. 마우스/패드 감도와 수직 시야 제한을 재사용한다.
5. 새 입력을 받으면 설명을 닫고, 설명이 소유한 정지와 전환 입력 잠금을 해제한 뒤 같은 입력을 실제 일섬 요청으로 한 번 전달한다. 페이드가 끝날 때까지 입력 실행을 지연하지 않는다.
6. 실제 패링 준비가 유효하지 않으면 일반 공격으로 대체하지 않는다. 같은 목표에서 기존 재투척·재패링 경로로 복귀한다.
7. 실제 요청이 일시적 행동 불가로 거부되면 같은 목표를 유지하고 입력 잠금이 남지 않게 한다. 새 클릭으로 재시도할 수 있어야 한다. 무기한 자동 재요청은 하지 않는다.
8. 첫 설명 이후에는 다시 정지 설명을 띄우지 않는다. 집중 만료 후 재패링과 좌클릭은 본편 입력 그대로 진행한다.
9. 실제 `SwordWaveLaunched`만 목표를 완료한다.

### 3.5 5단계 게이지와 거합

- 첫 게이지 설명은 게이지 강조와 4초 비정지 보조 안내로 바꾼다. 안내 표시 중에도 투척·방어·게이지 증가·목표 판정이 진행돼야 한다.
- `_ultimateMeterTutorialRunning` 같은 기존 설명 플래그가 Update/방어 판정/완충 전환을 막지 않게 조정한다.
- 게이지가 안내 도중 완충되면 낮은 우선순위 안내를 닫고 즉시 거합 목표와 첫 거합 설명으로 전환한다. 4초 타이머를 기다리지 않는다.
- 첫 거합 설명에서는 세션 정지와 조준 허용을 사용한다. 새 Q/Y 누름으로 설명을 닫고 정지를 해제한 다음 본편 차징을 한 번 요청한다.
- Q/Y를 다시 누르게 하지 않는다. 요청 후에는 기존 `IsPressed`와 해제 취소 경로가 같은 누름을 이어받는다.
- 설명 정지 중 경과한 시간은 홀드 진행도로 넣지 않는다. 실제 차징 시작 시각부터 본편 길이로 계산한다.
- 요청 처리 전에 이미 버튼을 놓았다면 뒤늦은 자동 차징을 시작하지 않는다. 게이지·표적·목표를 유지하고 다시 홀드할 수 있게 한다.
- 차징 중 중앙 `UltimateHoldProgressRing`을 그대로 사용한다. 안내 패널과 강조 프레임이 링·표적을 가리지 않게 정리한다.
- 조기 해제는 같은 목표에서 바로 재시도한다. 정지 설명 재표시·표적 초기화·게이지 소비·`RecoverFailedUltimate` 호출을 하지 않는다.
- 실제 시전 완료와 표적 8명 처치 조건을 유지한다. 실제 시전했지만 처치가 부족한 경우에만 기존 게이지 재충전 흐름을 따른다.

## 4. 입력 전달과 정리 설계

### 4.1 제한된 행동 대기 상태

- 온보딩 전용 대기 종류를 없음/일섬/거합으로 명시한다. 완료 선택 화면은 별개 상태로 유지한다.
- InputManager가 기존 InputAction으로 새 누름과 홀드 상태를 읽는다. 키보드/패드 키를 Flow에서 직접 하드코딩하거나 별도 InputAction을 복제하지 않는다.
- 대기 진입 시 목표 입력이 눌려 있는지 기록하고, 이미 눌린 상태는 해제 이후의 새 누름부터 수락한다.
- 기대 입력을 받으면 대기를 먼저 닫고 한 번짜리 요청을 저장한다. 기대하지 않은 공격/가드/회피/거합 입력은 실행하거나 안내 종료에 사용하지 않는다.
- 입력 시각은 실제 누름 시각을 보존한다. 요청은 기존 RequestAttack/RequestSkill의 전투 판정과 입력 기록 경로를 공유한다. 직접 Empower만 호출해 텔레메트리를 우회하지 않는다.

### 4.2 요청 실행 순서

1. 현재 씬·단계·목표·게임 상태·생존·앱 포커스와 대기 종류를 확인한다.
2. 요청 하나를 저장하고 대기 입력을 비활성화한다.
3. Flow가 설명 표시를 닫고 자신이 소유한 정지/입력 잠금을 해제한다. 완료 선택이나 메뉴가 소유한 잠금은 해제하지 않는다.
4. 시간 정책이 정상 반영됐고 실제 행동 가능 상태가 됐는지 확인한다. 필요하면 다음 정상 InputManager 처리 시점까지 요청을 보관한다. `Time.timeScale`을 직접 1로 지정하지 않는다.
5. Flow의 목표 입력 가능 상태를 복원한 뒤 입력 요청을 한 번 실행한다. 같은 프레임의 일반 입력 분기는 해당 누름을 다시 처리하지 않게 한다.
6. 거합 요청 직전에는 실제 홀드 상태도 재확인한다. 일섬은 새 클릭 한 번을 저장해 전달하므로 처리 전에 손을 뗐다는 이유만으로 정상 클릭을 잃지 않는다.
7. 요청은 실행 또는 명확한 취소 후 비운다. 다음 클릭/홀드를 소비하거나 목표 완료 UI로 전달하지 않는다.

- 기존 `ConsumeOnboardingAttackUntilRelease`를 기대 행동 실행 전에 호출해 첫 입력을 버리지 않는다. 실제 전달 이후 동일 누름의 중복 실행만 막는 처리와 구분한다.
- 요청을 저장한 뒤 재시작·사망·씬 변경·다른 목표 진입·앱 포커스 상실이 발생하면 취소한다. 다음 세션에서 실행하면 안 된다.
- 메뉴 일시정지 중에는 행동을 실행하지 않는다. 메뉴에서 돌아온 뒤 이전 누름으로 자동 실행하지 말고 새 입력을 받는다. 설명 정지와 메뉴 정지의 소유권이 섞이지 않도록 확인한다.

### 4.3 설명 중 조준

- InputManager의 온보딩 행동 대기 상태에서 시점 입력만 허용한다.
- PlayerMotor의 실제 회전 적용 경로가 정지 중 차단되는지 확인하고, 필요할 때만 온보딩에 한정한 시점 적용 메서드를 추가한다. 이동/중력/전투 Tick 전체를 실행하지 않는다.
- 마우스 델타에는 시간을 중복 곱하지 않는다. 패드 시점에는 설명 대기에서만 unscaled delta를 사용한다. 일반 플레이 시점 계산은 유지한다.
- 설명 종료·포커스 상실·비활성화 시 남은 시점 델타를 정리해 복귀 순간 시점이 튀지 않게 한다.

## 5. 안내 HUD와 문구 저장

- 정보 안내와 행동 대기 안내의 수명·입력 차단 여부를 구분한다. 정보 안내는 기존 보조 설명 영역과 스타일을 재사용한다.
- 표시 우선순위: 단계 완료/재시작 정리 > 행동 대기 설명 > 비정지 정보 안내. 이전 안내 타이머가 새 설명을 숨기지 않도록 소유 식별 또는 코루틴 취소로 보호한다.
- 단계 시작 카드와 정보 안내가 겹치면 정보 안내를 잠시 뒤에 표시하되 게임 진행은 막지 않는다. 목표 완료/상위 안내 전환 시 대기 중인 정보 안내는 폐기한다.
- 기본 정보 안내 표시 4초·페이드 0.2초는 Inspector 설정으로 둔다. 새 강제 최소 읽기 시간은 넣지 않는다.
- 모든 문구는 Inspector에서 편집한다. 짧은 `~합니다/~집니다/~됩니다` 말투와 기존 폰트·색상·크기를 유지한다. 행동 설명의 표적/진행 링 겹침을 피하기 위한 배치 조정만 허용한다.

| 위치 | 키보드 문구 초안 | 패드 문구 초안 |
| --- | --- | --- |
| 이동 파동 정보 | 움직이면 파동이 생겨 주변을 밝힙니다. | 동일 |
| 극한 회피 완료 복습 | 공격에 맞춰 회피하면 시야가 밝혀지고 시간이 느려집니다. | 동일 |
| 거합 게이지 정보 | 화면의 원형 표시가 거합 게이지입니다.\n극한 회피보다 쳐내기가 많은 양을 채웁니다. | 동일 |
| 일섬 행동 설명 | 쳐내기에 성공하면 시간이 느려집니다.\n집중 중 좌클릭으로 일섬을 발동합니다. | 쳐내기에 성공하면 시간이 느려집니다.\n집중 중 RB로 일섬을 발동합니다. |
| 거합 행동 설명 | 거합 게이지를 모두 채운 뒤\nQ를 홀드해 거합을 발동합니다. | 거합 게이지를 모두 채운 뒤\nY를 홀드해 거합을 발동합니다. |
| 거합 보조 안내 | 중앙의 원이 다 차면 거합이 발동합니다.\n도중에 버튼을 떼면 취소됩니다. | 동일 |
| 일섬 집중 만료 | 다시 쳐낸 뒤 집중 중 좌클릭으로 일섬을 발동합니다. | 다시 쳐낸 뒤 집중 중 RB로 일섬을 발동합니다. |

- 현재 `_followUpNote`는 단일 문자열이다. 입력 장치를 언급하는 재시도 문구에는 패드용 Inspector 필드와 빈 값 fallback을 최소 추가한다. 키보드 사용 중 장치를 바꿔도 현재 안내가 갱신돼야 한다.
- 씬의 실제 문구를 기준으로 폐기되는 ‘마우스 좌클릭으로 계속 진행’/‘RB 버튼으로 계속 진행’ 마지막 줄만 제거한다. 사용자 문장 전체를 초안으로 바꾸지 않는다.
- Builder는 새 정보 안내 설정과 장치별 문구를 보존한다. 기존 사용자 문구에 대한 광범위한 Contains 기반 기본값 교체를 피하고, 정확히 식별한 기존 기본값 또는 폐기 마지막 줄만 이관한다.
- 제거한 설명 필드가 Builder·씬에 남아 다시 살아나지 않게 한다. 새 필드 기본값과 실제 씬 저장값을 함께 반영한다.

## 6. 로그와 성공 판정

- 단계/목표 수는 그대로 유지한다. 4단계 목표 0 쳐내기, 1 일섬이며 재패링은 같은 목표의 시도다.
- 일섬/거합 설명에서 시작한 첫 실제 행동이 입력 가능 상태 검사 때문에 기록에서 빠지지 않아야 한다.
- 실제 요청이 동기적으로 성공 사건을 발행할 수 있다. 목표 완료가 입력 기록보다 먼저 닫히는 순서가 있는지 확인하고, 필요하면 해당 요청의 기록을 마친 뒤 목표 완료를 처리하는 최소 조정을 한다.
- 한 물리적 입력에 InputId·시도 횟수가 중복 생성되지 않아야 한다. 기존 계약상 동일 InputId의 상태 갱신은 중복 시도로 취급하지 않는다.
- 정보 안내를 읽으며 플레이한 시간은 활성 시간에 포함한다. 실제로 정지된 행동 설명 시간은 제외한다. 첫 행동 요청은 제외하지 않는다.
- 안내/입력 시간 해석이 바뀌므로 온보딩 configVersion을 새 값(예: `onboarding-2026-10-24-action-guides`)으로 구분하고 코드·씬·Builder의 관련 저장값을 맞춘다. 이전 로그/분석 계약을 재작성하지 않는다.
