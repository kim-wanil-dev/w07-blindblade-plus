## 1. 목표와 완료 정의

### 사용자 관점의 목표

1. 플레이어가 체력·스태미너와 화면 밖 위협을 빠르게 구분한다.
2. 월드와 HUD의 색상·표시 전환이 일치하며, 발소리가 적의 실시간 위치 추적기로 변하지 않는다.
3. 실제 피해를 받았을 때만 짧은 피격 비네팅이 나타난다.
4. 강화 준비·게임오버·재도전에서 시간 배율이 의도대로 동작한다.
5. 개발자가 실제 입력과 전투 결과를 로그로 분석하고, 다음 담당자가 연결 구조를 이해할 수 있다.

### D 완료 조건

- HUD는 A/B/C의 확정 상태를 표시하며 전투 결과를 결정하지 않는다.
- 공식 플레이 경로에서 시간 배율을 쓰는 주체가 하나다.
- 사망·재도전·Play 종료 후 이전 세션의 구독, 시간 요청, 마커가 남지 않는다.
- 로그가 비활성화되거나 저장에 실패해도 전투가 계속된다.
- 공용 씬·프리팹 참조, Inspector 설정, 수동 확인 결과, 기능명세가 함께 전달된다.
- 단순 컴파일 성공과 실제 입력·시각·음향 확인을 구분해 기록한다.

## 4. 기능 요구사항

### HUD-01 — 체력·스태미너

- HP는 `PlayerHealth.CurrentHealth`, `MaxHealth`, `HealthChanged`를 사용한다. 스태미너는 A가 제공하는 동등한 읽기 전용 계약을 사용한다.
- 연결 직후 현재 값을 한 번 읽고 이후 변경 사건으로 갱신한다. 구독 전에 발생한 변화를 놓치지 않는다.
- 논리 값은 사건 수신 시 갱신한다. 시각 보간을 쓰더라도 표시 중인 값과 목표 값을 구분하고, 보간 종료 시 목표와 일치해야 한다.
- 최대치 변경·회복·소모·0·최대값·재도전을 처리한다. UI는 비용·회복량·행동 허용 여부를 계산하지 않는다.
- 먹물 외형은 D 소유 UI 이미지로 구성한다. 진행 방향·배치·색·간격·보간 시간은 Inspector에서 수정한다.
- 기존 생존 시간·처치 수 기록은 유지한다. 새 UI가 기존 기록 텍스트 연결을 바꾸지 않는다.

### HUD-02 — 수리검 방향 표시

- C의 `ThreatPresentationSnapshot`에 있는 UI 표시 여부·방향·색상·투명도를 적용한다. 거리 자격·차폐·인지 색상을 D가 다시 계산하지 않는다.
- 반사·통과·제거 시 C의 최신 결과와 B의 종료 정보로 해당 마커를 정리한다. 이전 상태의 지연 전달로 다시 나타나지 않게 세션·세대·갱신 순서를 확인한다.
- 화면 밖 방향을 UI 좌표로 옮기는 배치 계산은 D 책임이다. 월드 표시 자격 판단은 C 책임이다.
- 텔레그래프를 유지할지 D0에서 확정한다. 유지한다면 B/C가 발사 전 위협 ID와 실제 ProjectileId의 연결을 제공한다.
- 현재 12개 마커를 무조건 충분한 상한으로 가정하지 않는다. B의 최대 동시 위협 수를 받아 용량을 정한다. 초과 시 C의 우선순위대로 표시하고 초과 건수를 진단 기록한다.

### HUD-03 — 발소리 표시

- C가 기존 `EnemyFootsteps.Footstep`으로 만든 후보를 사용한다.
- 사건의 발생 위치·시각·이벤트 ID·적 생성 세대를 보존한다. 적이 움직여도 소리 원점은 이동하지 않는다.
- 카메라 회전에 따른 화면 방향은 갱신할 수 있지만, 새로운 적 위치로 원점을 덮어쓰지 않는다.
- 수명·중첩·풀 반환 규칙을 정하고 적 재사용/세션 종료에서 이전 세대의 마커를 제거한다.

### HUD-04 — 실제 피격 비네팅

- 게이지는 `HealthChanged`, 피격 연출은 실제 `DamageReceived` 또는 A가 보장하는 동등한 실제 피해 사건을 구독한다.
- 초기화·회복·가드·패링·회피 무적·추가타 무적에는 피격 비네팅을 재생하지 않는다.
- 저체력만으로 계속 표시하지 않는다. 연속 피격은 타이머를 다시 시작하는 방식을 권장하며, 불투명도 무한 누적은 하지 않는다.
- 표시 시간·강도·두께·색·감쇠 곡선을 Inspector에 둔다. 머티리얼 값을 바꾸면 인스턴스 소유권과 해제 책임을 명시한다.
- 권장안: UI 연출은 unscaled 시간으로 감쇠하고, 게임오버 화면이 최상위에 표시된다. 치명타 펄스의 표시/생략은 UI 정책으로 정하되 실제 피해 로그는 반드시 남긴다.

### TIME-01 — 시간 제어

- `SessionTimeController`만 공식 플레이 경로의 `Time.timeScale`을 쓴다.
- A는 요청 토큰을 받고 상태 종료 시 해당 토큰을 해제한다. 동일 토큰의 반복 해제는 영향이 없고 이전 세션 토큰은 거부한다.
- 권장 우선순위: 게임오버/명시적 일시정지 → 활성 슬로모션 요청 → 기본 배율 1.
- 중첩 슬로모션은 유효 요청 중 가장 작은 배율을 선택하는 안을 권장한다. 곱셈 중첩이나 저장된 과거 배율 복원은 하지 않는다.
- GameStateManager는 게임 상태·커서를 관리하고 시간 제어기에 상태를 전달한다. A는 PlayerMotor의 직접 timeScale 쓰기를 요청/해제로 이관한다.
- 새 세션과 재도전은 요청을 비우고 기본 배율로 시작한다. GameOver 중 A의 늦은 해제 사건이 정지를 풀지 못해야 한다.
- `fixedDeltaTime`은 일단 기존 기준값 유지안을 사용한다. 변경이 필요하면 B의 물리·고속 투사체 요구와 함께 별도 결정하고 초기화/복원까지 같은 제어기가 맡는다.
- 별도 플레이어 시간 배율은 기획 합의 전 구현하지 않는다. 선택되면 A의 이동·Animator·공격·무적까지 같은 기준으로 묶는 추가 작업이 필요하다.

### LOG-01 — 수집·저장

- 세션별 새 SessionId와 순차 EventSequence를 부여한다. InputId/ActionId/AttackId/HitId/ProjectileId/DodgeId는 사건 발생 담당자가 만들고 D는 전달받는다.
- `SourceEventId` 또는 동등한 사건 고유 키를 계약에 넣는다. AttackId만으로 중복 제거하면 다단 공격이 사라지므로 금지한다.
- 최소 필드: SchemaVersion, ConfigVersion, SessionId, EventSequence, SourceEventId, EventType, 관련 ID, SpawnGeneration, 실시간, 게임시간, 입력 원본 시각(해당 시), 실제 결과, 위치·수치 값.
- 입력 원본 시계와 공통 시계의 변환 기준을 세션 메타데이터에 저장한다. 실시간·게임시간을 단순히 서로 빼서 판정 오차로 사용하지 않는다.
- B의 접촉 사건과 A의 판정 사건은 다른 종류로 기록한다. 피해/보상 통계의 권위 있는 결과는 A/B의 확정 사건이다.
- 파일 형식 권장: 세션 메타데이터 JSON + 사건 JSONL. 저장 위치는 `Application.persistentDataPath` 아래의 전용 폴더로 한다.
- 메모리 버퍼와 주기적 묶음 저장을 사용한다. 용량·주기·보관 한도는 Inspector 설정으로 제공하며, 매 프레임 동기 파일 저장을 피한다.
- 버퍼 초과·저장 실패 시 누락 건수와 오류 상태를 노출한다. 파일이 완전한 것처럼 보고하지 않는다. 오류 반복 메시지는 제한한다.
- 백그라운드 저장을 쓰면 메인 스레드에서 값 스냅샷을 만든 뒤 전달한다. Unity 객체·Transform을 저장 스레드나 종료 콜백에서 조회하지 않는다.
- 로그 비활성화/디스크 오류가 전투 명령의 성공·실패를 바꾸지 않는다. 로그 경로와 오류 상태는 개발용 진단으로만 노출한다.

### LOG-02 — 전처리

- 게임 런타임과 별도의 도구로 원본 로그를 읽고 분석 파일을 출력한다. 원본 로그는 수정하지 않는다.
- 권장 구현: Python 3 표준 라이브러리 기반 CLI. D0에서 팀 실행 환경을 확인하고 버전·실행 명령을 README에 고정한다.
- 출력: 사건 정리표, 입력-공격 연결 후보표, 세션 요약, 누락/중복/모호함 보고서. 분석 버전·파라미터·입력 파일 식별값을 함께 보존한다.
- 공통 시계로 정규화 → 사건 고유 키 중복 확인 → 명시적 ID 연결 → ID 없는 early/late 후보 생성 → 모호함/제외 표시 → 집계 순서로 처리한다.
- 하나의 입력이 여러 공격의 후보가 되면 후보를 보존하고 임의로 독립 성공 두 건으로 만들지 않는다. 실제 확정 판정과 분석상 후보 연결을 분리한다.
- 다른 패링 창으로 재분류한 결과는 가상 분석이다. 실제 패링 보상·피해 이력과 별도 열에 둔다.
- 중도 종료로 마지막 JSONL 줄이 불완전하면 해당 줄을 오류로 보고하고 앞선 정상 기록을 처리한다. 스키마 미지원은 명시적으로 실패한다.

## 5. 먼저 확정할 계약과 기획 결정

### 계약 배포표

| 계약 | 공급자 → 소비자 | D가 확인할 내용 |
| --- | --- | --- |
| DefenseResolution | A → B, 확정 사건 → C/D | Hit/Guard/NormalParry/PerfectParry/DodgeAvoided/Invulnerable 구분, 접촉당 결과 횟수 |

| 강화 준비·시작·종료 | A → D | ActionId, 종료 이유, 시간 토큰 해제 지점 |
| 시간 요청/해제 | D 제공, A 사용 | 배율, 요청자, 세션 세대, 토큰, 반복 해제 규칙 |
| 투사체/적 lifecycle | B → C/D | ID·세대·소유권·마지막 위치·종료 이유, 발행 순서 |
| ThreatPresentationSnapshot | C → D | 대상 키·표시 여부·방향·색·alpha·순서 정보, 초기 전체 조회 방식 |
| Footstep presentation | C → D | 사건 키·고정 원점·발생 시각·수명·표시 결과 |
| Telemetry envelope | A/B/C → D | 원본 사건 키, 관련 ID, 공통 시각, 값 스냅샷 |

공통 타입의 단일 원본은 `BlindBlade.Combat.Contracts`다. 이번 v0.2.0은 사용자의 통합 지시에 따라 현재 공유 저장소의 A/B/C 공급자까지 적용했다. 소유권·변경 이유·이관 API는 계약 문서에 기록하며, 외부 팀원 검토 결과는 별도로 기록한다. 새 resolver 경로에서는 A의 피해 적용 뒤 호출자가 다시 피해를 적용하지 않는다.

아래 권장안은 원본 계획과 이번 PRD의 제안이다. 과거 리팩토링에서 사용한 권장안 승인을 이번 새 전투 기획의 확정으로 간주하지 않는다. 해당 결정 전에도 프리팹 외형·로그 형식 등 독립 작업은 진행할 수 있다.

## 7. Inspector와 에셋 관리 기준

| 소유 설정 | Inspector에 노출할 값 | 외부에서 받아야 할 값 |
| --- | --- | --- |
| D HUD | 바 배치·크기·이미지·보간 시간, 마커 반경·크기·용량, 발소리 표현 수명 | HP/스태미너, 인지 결과·색상·표시 우선순위 |
| D 피격 연출 | 지속 시간·강도·폭·감쇠 곡선·UI 색상 | 실제 피해 발생 사실 |
| D 시간 | 기본 배율, 허용 요청 범위, 진단 표시 | A의 상태별 요청/해제, 게임 상태 |
| D 로그 | 활성 여부·상대 폴더·버퍼 한도·저장 주기·보관 한도 | A/B/C의 원본 사건·ID·설정 버전 |
| A/B/C 설정 | 각 담당자의 기존/신규 설정 에셋 | D가 별도 사본을 만들지 않음 |

- 공통 대형 설정 파일 대신 역할별 설정을 사용한다. ScriptableObject를 사용하더라도 현재 세션 상태·요청 토큰을 저장하지 않는다.
- 새 수치의 확정값은 아직 없다. 현재 HUD의 1920×1080, Match 0.5와 기존 방향 마커를 출발점으로 사용하고 새 값은 초기 튜닝값으로 기록한다.
- 표시 전용 Graphic은 포인터 입력을 가로채지 않는다. 게임오버 UI와 Canvas 정렬 우선순위를 확인한다.
- 기존 스크립트/에셋 GUID를 유지하고 이동 시 `.meta`를 함께 보존한다. 직렬화 필드 변경이 필요하면 이전 이름·새 이름·값 이관 방법을 기록한다.
- 씬/프리팹 편집은 Unity의 에셋 편집 절차로 진행한다. 저장 전후 Missing Script, UnityEvent, 참조 및 override를 확인한다.
- C#은 AGENTS.md의 주석·필드·접근자·using 규칙을 따른다. 요청 범위 밖 이름 변경이나 정리를 섞지 않는다.

## 9. 협업 제출과 중단 후 재개

### A/B/C가 D에게 넘길 연결 요청서

```text
담당 / 기능 / 계약 버전:
변경 파일 및 소유자:
추가할 컴포넌트 타입 / 대상 GameObject:
필수 참조의 경로와 GUID:
Inspector 값 및 단위:
Initialize / Shutdown / 사건 발행 순서:
기존 연결에서 제거하거나 교체할 항목:
수동 확인 결과 / 아직 확인하지 않은 항목:
```

### D progress 기록 양식

```text
현재 단계: Dn (미착수 / 진행 / 공급자 대기 / 완료)
현재 계약 버전 / 작업 기준선:
실제 변경 파일과 에셋:
완료한 작업과 근거:
확인 결과: 컴파일 / 실제 입력 / 화면 / 소리 / 종료·재도전
확인하지 않은 항목:
A/B/C에게 요청한 항목과 답변:
현재 열린 씬·미저장 에셋 상태:
다음 작업: 파일·메서드·참조·구체적 행동
되돌릴 때의 단위와 보존할 GUID:
```

각 단계 직후 progress를 갱신한다. 작업을 재개하는 사람은 AGENTS.md → FEATURE_SPEC → 이 PRD → progress → 해당 기능명세 순서로 읽는다. 완료 체크는 실제 구현·연결·확인 근거가 있을 때만 한다. 계약 변경이 생기면 관련 공급자와 소비자 버전을 함께 갱신한다.

현재 `feature/ui`에서는 AGENTS.md에 따라 Git CLI와 자동 커밋을 사용하지 않는다. 다른 작업 공간에서 재개할 때는 실제 브랜치와 해당 지침을 다시 확인한다. 공용 에셋이나 다른 담당자의 변경과 충돌하면 덮어쓰지 말고 소유자 조정 및 필요한 승인을 먼저 받는다.

## 10. 추가로 계획에 포함한 항목

1. **치명타 로그의 순서 보존:** GameOver 이전/이후 사건 순서 때문에 마지막 피해를 잃지 않도록 종료 시점을 구체화했다.
2. **명시적 HUD 연결:** 새 텍스트·마커 추가로 기존 자동 연결이 잘못된 대상을 잡는 문제를 선행 작업으로 올렸다.
3. **시간과 입력 시계의 구분:** 불릿 타임에서 입력 오차 분석이 왜곡되지 않도록 시계 변환 메타데이터를 포함했다.
4. **불완전 로그와 용량 제한:** 저장 실패·버퍼 초과·중도 종료를 완료 조건에 넣었다.
5. **세대와 초기 스냅샷:** 풀 재사용·늦은 구독·이전 세션 이벤트가 새 HUD에 영향을 주지 않게 했다.
6. **공용 에셋 인수 양식:** 타입·GUID·Inspector 값·종료 순서가 함께 전달되도록 했다.
7. **현재 상태와 역사 기록 구분:** 과거 명세의 삭제된 씬·없는 클래스·예전 검증을 현재 구현 근거로 재사용하지 않는다.
