# 온보딩 패링 일섬·Q 홀드 동기화 구현 계획

- 작성일: 2026-10-24
- 상태: 코드·온보딩 씬·Builder·기능명세 반영 완료. Unity 배치 컴파일은 라이선스 클라이언트 연결 거부와 WMI 초기화 오류로 컴파일 전에 중단됐다. 생성된 .NET 프로젝트도 `project.assets.json` 부재로 빌드되지 않았고 복원은 종료 코드 1로 끝났다. Unity 편집기 UI 자동 조작은 자동 승인 검토에서 허용되지 않아 실제 Play 검증은 미확인이다.
- 목적: 현재 본편의 패링 집중 중 좌클릭 일섬, Q 홀드 거합, 일섬 자원 HUD 숨김, 집중 대상 발도 제거를 온보딩에 반영한다.
- 기준: `docs/features/온보딩.md`, `docs/features/특수스킬_게이지.md`, 실제 입력·온보딩 코드와 저장된 HUD/씬. 날짜가 오래된 Shift 일섬·자동 차징 설명보다 본편 최신 동작을 우선한다.

## 1. 확정 범위

- 5단계 구성과 Intro → Onboarding → BambooStage1 진행을 유지한다.
- 일섬은 실제 쳐내기 성공으로 생긴 집중 중 좌클릭/패드 RB로 한 번 사용한다. Shift/RT, 게이지 한 칸 충전·소비 안내를 제거한다.
- 본편은 일섬 자원 HUD를 이미 숨겼다. 온보딩도 이에 맞추며 내부 일섬 자원·호환 API·검 구슬 구조를 전면 삭제하는 작업은 포함하지 않는다.
- 거합은 게이지 완충 후 Q/패드 Y를 끝까지 누른다. 현재 본편의 0.75초 홀드와 중간 해제 취소, 중앙 원형 진행 바를 재사용한다.
- 검의 기운이 적과 연결되는 대상 발도 안내를 제거한다. 일섬 자체의 돌진·검기 연출과 일반 회피는 유지한다.
- 사용자 추가 결정: 4단계의 수리검 막기 목표를 제거한다. 3단계에서 막기를 학습하고, 4단계는 수리검 쳐내기 → 일섬 발동의 두 목표만 둔다.
- 이전에 요청한 Inspector 문구 편집, 완료 전 실제 시간 1초 대기 동안 씬 진행, 다음 단계/다시 연습, 극한 회피 성공 후 수리검 정리를 보존한다.
- 보상량·피해량·본편 집중 길이·보상음·멀티킬 동작은 바꾸지 않는다. 테스트 코드는 작성하지 않는다.

## 3. 단계별 수정안

| 단계 | 목표와 흐름 | 안내 수정 |
| --- | --- | --- |
| 1. 기본 조작 | 이동·회피·일반 공격으로 전방 적 3명 처치. 이동 파동 설명 유지 | 실 연결·좌클릭 발도·완료 복습의 발도 설명 제거. `좌클릭으로 공격합니다.` |
| 2. 극한 회피 | 실제 수리검 극한 회피 성공, 남은 수리검 정리 | 파동·잠시 느려짐을 설명. 일섬 반 칸 등 보상 설명 제거. 거합 보상이 필요하면 수치 대신 `극한 회피에 성공하면 거합 게이지가 차오릅니다.` |
| 3. 근접 방어 | 기존 막기 → 쳐내기 목표 유지 | 막기와 쳐내기를 구분한다. 4단계에서 배울 일섬을 미리 성공 조건으로 요구하지 않는다. |
| 4. 일섬 | 수리검 쳐내기 1회 → 그 집중 중 좌클릭/RB 일섬 1회 | 목표는 `수리검 쳐내기 1회`, `일섬 발동 1회`. 설명은 `쳐내기에 성공하면 시간이 느려집니다.\n집중 중 좌클릭으로 일섬을 발동합니다.` 일반 막기는 성공으로 집계하지 않는다. |
| 5. 거합 | 거합 게이지 완충 → Q/Y 홀드로 실제 거합 시전 → 기존 표적 8명 처치 | `거합 게이지를 모두 채운 뒤\nQ를 홀드해 거합을 발동합니다.`와 진행·취소 설명을 기존 설명 카드 형식으로 표시한다. |

- 키보드·패드 문구를 모두 수정한다. 4단계 후속 조작은 좌클릭/RB, 5단계는 Q/Y 홀드다.
- 거합 보상 비교는 현재 씬의 `화면의 원형 표시가 거합 게이지입니다.\n극한 회피보다 쳐내기가 많은 양을 채웁니다.`를 유지한다. 15%·33% 등 고정 보상 수치를 새 안내에 넣지 않는다. 실제 거합 게이지의 백분율 표시는 유지한다.
- 단계 시작·완료 복습 문구도 같은 규칙으로 수정한다. 5단계 완료 카드는 현재 표시되지 않지만 저장된 문구는 정합성을 맞춘다.

### 3.1. 기존 안내 스타일 유지 (사용자 추가 요청)

- 문구 기준은 코드 기본값보다 현재 `Onboarding.unity`의 Inspector 저장값이다. 사용자가 이미 고친 문구를 구형 기본값으로 되돌리지 않는다. 현재 1단계 완료 문구는 이미 일반 공격 설명이므로 그대로 유지한다.
- 설명·완료 복습은 기존과 같은 짧은 서술형 `~합니다`, `~됩니다`, `~집니다`를 쓴다. `~하세요`, `~누르고 계세요`처럼 새 말투를 섞지 않는다.
- 목표는 `수리검 쳐내기 1회`처럼 짧은 행동명과 횟수로, 조작판은 `일섬: 좌클릭`, `거합: Q 홀드`처럼 기술명·입력으로 표시한다. 조건 설명을 조작판 한 줄에 길게 넣지 않는다.
- 시작 제목 `단계 N/5 시작`, 완료 제목 `단계 N/5 완료`, 시작 설명 `강력한 기술 - 일섬/거합`과 버튼 명칭을 유지한다.
- 설명 카드 마지막 줄은 키보드 `마우스 좌클릭으로 계속 진행`, 패드 `RB 버튼으로 계속 진행`을 유지한다. 이 줄은 안내 확인이며 실제 스킬 입력과 구분한다. 완료 복습에는 계속 진행 문구를 붙이지 않는다.
- 줄바꿈은 의미 단위로 넣고 기존 설명 영역에 맞춘다. 아래 표의 `\n`은 실제 줄바꿈이다. 긴 설명은 조작·완료 복습에 모두 반복하지 않고 설명 카드와 기존 보조 안내 영역에 나누어 배치한다.
- 기존 폰트·글자 크기·색상·정렬·패널 배치를 유지한다. 새 텍스트 스타일이나 강조색을 추가하지 않는다. 문구 변경으로 넘침이 생기면 먼저 문장 길이와 줄바꿈을 조정한다.

| --- | --- | --- |

- 위 문구는 구현 시 각 Inspector 필드에 저장할 초안이다. 현재 사용 중인 문구와 대조해 바뀐 규칙에 해당하는 부분만 수정한다.

## 4. 4단계 상태 전환과 재시도

1. 입장 시 수리검 쳐내기 목표와 훈련 투척수를 준비한다. 이전 단계의 집중·잔여 입력은 기존 정리 경로로 해제한다.
2. 훈련 투척수의 실제 공격 ID에 대한 `PerfectParry`만 인정한다. 일반 막기·일반 패링·회피·다른 공격원으로는 목표를 넘기지 않는다.
3. 쳐내기 성공 시 일섬 목표로 이동하고 표적을 준비한다. 첫 설명 카드를 여는 동안 기존 `PauseTutorial`로 실제 패링 집중을 보존한다. 이벤트 순서상 집중 준비 전에 카드 전환을 처리하지 않도록 확인한다.
4. 설명을 닫는 좌클릭/RB는 안내 확인에만 사용한다. `ConsumeOnboardingAttackUntilRelease`로 소비하고, 버튼을 떼었다 다시 누른 실제 공격 입력으로 일섬을 사용하게 한다. 안내 클릭이 의도치 않게 일섬을 소비하지 않아야 한다.
5. 연습을 재개하면 본편의 남은 패링 집중 시간이 진행된다. `HoldOnboardingReady`로 무한 집중을 만들거나 `EnsureOnboardingSwordWaveReady`로 가짜 준비·게이지를 지급하지 않는다.
6. 집중이 만료되거나 시전 전에 취소되면 일섬 목표를 유지하고 훈련 투척을 재개한다. 3.1절의 집중 만료 보조 안내를 비정지 상태로 표시한다. 이미 완료한 쳐내기 목표의 완료 로그를 다시 발행하지 않는다.
7. 재시도에서도 실제 쳐내기가 패링 집중을 만들고, 극한 회피 집중은 준비로 인정하지 않는다. 일섬 목표 중에도 훈련 방어 결과를 관찰하도록 현재 목표 제한 분기를 수정한다.
8. 실제 `SwordWaveLaunched`를 일섬 성공 기준으로 유지한다. 키 입력·설명 카드 닫기·집중 진입만으로 완료하지 않는다. 실제 발사가 없으면 목표가 계속 열려 있어야 한다.
9. `UpdateRangedThrower`의 후속 목표 투척 중단 조건을 재시도 상태와 함께 수정한다. 유효한 패링 집중/시전 중에는 불필요한 발사를 막고, 집중 만료 시 다시 공급한다. 표적 재생성은 기존 공격 종료 대기를 따른다.

### 목표 인덱스·로그

- 4단계 목표는 0=수리검 쳐내기, 1=일섬 발동으로 변경한다. `RANGED_SWORD_WAVE_OBJECTIVE`, `GetParryObjective`, `IsFollowUpObjective`, 방어 판정의 기존 막기 건너뛰기 분기를 함께 수정한다.
- HUD 기본값·씬·Builder의 목표 배열 및 후속 안내 시작 인덱스를 동시에 바꾼다. 이전 세 목표 배열과 새 두 목표 상수를 섞지 않는다.
- 단계 식별자 `0-1~0-5`는 유지한다. 4단계 목표 인덱스 의미 변경은 온보딩/텔레메트리 명세에 기록해 이전 빌드와 분석할 때 구분한다. 과거 기록을 덮어쓰지 않는다.
- 집중 만료는 같은 목표 내 재시도로 다룬다. 단계 재시도/다시 연습과 혼동해 `StageCompleted`나 단계 재시도 횟수를 중복 발행하지 않는다.

## 5. 거합 홀드와 HUD 연결

- 완충 설명은 기존 거합 자원 HUD를 가리키고, 실제 홀드 중에는 기존 중앙 원형 진행 바가 진행도를 보여 준다. 자원 게이지와 홀드 진행도의 의미를 구분한다.
- 진행 바는 `Assets/Scenes/Defense/UI/BambooDefenseHud.prefab`의 `ShurikenDirectionCanvas/UltimateHoldProgress`를 사용한다. 크기·색상·두께는 기존 컴포넌트 Inspector 값으로 관리한다.
- 온보딩의 수리검 표시 비활성 설정 때문에 캔버스 부모까지 꺼지지 않는지 확인한다. 설명 카드·중앙 안내·비네트와의 정렬도 실제 화면에서 확인한다. 공유 프리팹의 정렬을 본편에 영향 없이 무조건 바꾸지 않는다.
- 홀드 전에 안내 카드를 닫고 입력을 해제한다. 진행을 보이기 위해 홀드 도중 별도의 설명 정지를 끼워 넣지 않는다.
- 일찍 떼면 본편 `Cancelled`를 따르고, 게이지와 8명 표적을 유지한 채 같은 목표에서 다시 홀드한다. 취소만으로 `RecoverFailedUltimate`나 단계 완료를 실행하지 않는다.
- 끝까지 누른 실제 시전 뒤에만 기존 시전 종료·표적 처치 판정을 수행한다. 시전했지만 표적 8명을 모두 처치하지 못한 경우에는 기존 게이지 재충전 연습 흐름을 유지한다.
- 메뉴 일시정지·재개 후 버튼 해제, 사망·비활성화·씬 전환 시 진행 바와 차징 상태가 남지 않는지 확인한다.

## 7. 구현 순서

1. **현재 기준 고정**: 적용된 revert 이후 입력/프리팹/씬을 재확인한다. 본편이 이미 제공하는 기능을 다시 구현하지 않는다. 사용자 변경·현재 브랜치 규칙을 확인한다.
2. **4단계 흐름 수정**: 막기 목표 삭제, 두 목표 인덱스 동기화, 실제 패링 준비와 일섬 성공 판정, 만료 시 재투척을 먼저 연결한다.
3. **1~3단계 안내 정리**: 실 연결 발도 경로와 일섬 게이지 설명을 제거한다. 3단계 방어 성공 조건과 2단계 수리검 정리를 보존한다.
4. **5단계 홀드 안내/HUD**: Q/Y 홀드 문구와 중앙 진행 바 연결을 확인하고 취소·재시도 흐름을 점검한다.
5. **저장 데이터/Builder 정합성**: 실제 씬·HUD 기본값·Builder를 맞추고 Inspector 문구가 재생성 때 보존되는지 확인한다.
6. **검증·명세 갱신**: 아래 수동 검증, 가능한 Unity 컴파일을 수행한다. 미확인 항목은 남겨 두고 완료한 것으로 표시하지 않는다.

## 8. 수동 검증 및 완료 기준

- [ ] 런타임·Editor 어셈블리 컴파일 성공, 씬/프리팹 참조 누락 없음. 테스트 코드 추가 없음.
- [ ] Intro → 5단계 → BambooStage1 전체 진행과 중간 사망 재시작 가능.
- [ ] 1단계에서 실 연결/발도 안내를 기다리지 않고 일반 공격으로 3명 처치 가능.
- [ ] 2단계 극한 회피 후 수리검 정리, 파동 설명과 완료 처리 유지. 일섬 게이지 설명이 나오지 않음.
- [ ] 3단계 막기와 쳐내기 목표 유지. 패링 뒤 실제 일섬을 사용해도 다음 단계가 막히지 않음.
- [ ] 4단계 첫 목표는 쳐내기이며 일반 막기는 진행시키지 않음. 쳐내기 한 번 후 바로 일섬 목표로 이동.
- [ ] 설명을 읽는 시간은 집중을 소모하지 않음. 설명 닫는 클릭이 일섬으로 새지 않고 다음 클릭으로 실제 시전.
- [ ] 집중을 놓치거나 극한 회피한 뒤에도 다시 수리검을 쳐내 일섬 가능. 가짜 집중/무한 집중/게이지 지급 없음.
- [ ] Shift/RT·일반 공격·설명 클릭으로 일섬 목표가 완료되지 않고 실제 발사 한 번에만 완료.
- [ ] 5단계 Q/Y 홀드 중 중앙 진행 바 증가, 조기 해제 시 취소·진행 바 제거·자원 미소비·같은 목표에서 재시도.
- [ ] 홀드 완료 시 실제 거합 한 번 발동·게이지 한 번 소비, 표적 처치 확인 뒤 정상 완료.
- [ ] 메뉴 일시정지/재개, 홀드 중 사망·단계 재시작에서 입력·차징·집중·진행 바 잔류 없음.
- [ ] 다음 단계/다시 연습 시 기존 거합 자원 복원, 완료 전 실제 시간 1초 동안 씬 진행 유지.
- [ ] 키보드/패드 전환과 1920×1080·1280×720에서 설명·진행 바·비네트·게이지 가독성 확인.
- [ ] 기존 안내의 서술형 말투, 목표/조작/설명/완료 카드별 형식, 계속 진행 마지막 줄을 유지하고 글자 넘침·잘림이 없음. 폰트·색상·크기·배치의 불필요한 변경 없음.
- [ ] Inspector에서 바꾼 시작/완료/조작/설명 문구가 재시작 및 Builder 재생성 후 유지됨. 폐기 문구가 복원되지 않음.
- [ ] 4단계 두 목표 로그, 집중 만료 재시도, 단계 완료 로그 중복 없음. 과거 빌드와 목표 의미 차이를 명세에 기록.
- [ ] 본편 패링 일섬·극한 회피 일반 공격·Q 홀드 및 멀티킬 출처/집계 동작 유지.
