# 전투 텔레메트리 0.1.3 업데이트 계획

## 1. 목적과 범위

- 기준 버전 `0.1.2`와 후보 버전 `0.1.3`의 플레이 결과를 같은 로그 체계에서 비교한다.
- 새 구간 `2-1`, `2-2`, 일반 Beast 적, Twin Boss의 공격과 연계 패턴을 기록한다.
- 게임이 Google Sheets로 보내는 원본 행은 분석에 필요한 상태 변화만 추가한다.
- 로그 수집기, Apps Script, CSV 전처리기, 분석 웹사이트를 호환 가능한 순서로 갱신한다.
- 이 문서는 구현 순서, 완료 조건, 후속 검증 결과를 함께 관리한다.

## 2. 버전 정책

| 구분 | 0.1.2 기준 | 0.1.3 목표 |
| --- | --- | --- |
| 게임 빌드 버전 | 비교 기준 | `Application.version = 0.1.3` |
| 텔레메트리 스키마 | `0.3.0` | `0.4.0` |
| 분석 설정 ID | 기존 값 | `combat-analysis-0.1.3` |
| 수집 구간 | 온보딩, `1-1`, `1-2` | 기존 구간 + `2-1`, `2-2` |

## 3. 코드 조사로 확인된 누락

### 3.1 2막 시작 구간 유실

`RainyStageController`가 `Start`에서 `2-1` 또는 `2-2` 신호를 보내지만, `CombatTelemetryRecorder`의 실행 순서가 더 늦어 구독 전 신호가 사라질 수 있다. Recorder는 BambooStage1 외 씬을 `unassigned`로 시작한다. Recorder가 시작할 때 Stage Controller의 현재 구간을 직접 조회하도록 계약을 추가한다.

### 3.2 Twin Boss의 AttackId 누락

현재 `TwinBossRanged`, `TwinHumanSlash`, `TwinHumanCounterSlash`, `TwinHumanIai`, `TwinBeastBite`의 `DamageContext`에는 유효한 `AttackId`가 없다. 각 공격의 전조, 확정, 접촉, 종료에 동일한 ID를 전달해야 공격 결과와 반응 시간을 연결할 수 있다.

### 3.3 연계 패턴과 개별 공격의 혼합

한 번의 `Cooperation`에는 여러 수리검이 있고, `IaiCharge`에는 인간 거합과 Beast 방해 공격이 함께 들어간다. 부모 패턴 인스턴스와 실제 피해를 만드는 자식 공격을 별도로 기록한다.

### 3.4 Beast 출현 가중치 검증 불가

근접 적과 Beast 선택 가중치는 누적 스폰 수로 보간되지만 로그에 선택 당시 종류와 가중치가 없다. 적 종류, 스폰 순번, 적용 확률, 처치를 기록해 설계값과 실제 출현 비율을 비교한다.

### 3.5 진행 연결 정보 부족

`1-1 → 1-2 → 2-1 → 2-2 → 클리어`를 한 플레이로 연결할 지속 `runId`가 2막까지 보장되지 않는다. 새 게임, 이어 하기, 체크포인트 재도전, 에디터 즉시 보스 시작도 구분해야 한다.

### 3.6 Sheets 수신 제한

Apps Script의 구간 검증과 복원 정규식은 현재 `2-1`, `2-2`를 허용하지 않고 스키마도 `0.3.0` 기준이다. 게임 빌드 전에 수신기를 하위 호환 방식으로 배포한다.

## 4. 추가할 로그 계약

### 4.1 구간과 실행 흐름

| 필드 | 값 예시 | 목적 |
| --- | --- | --- |
| `stageId` | `1-1`, `1-2`, `2-1`, `2-2` | 구간별 난이도와 이탈 |
| `runId` | 게임 흐름 UUID | 여러 씬의 세션 연결 |
| `stageAttemptId` | 구간 시도 UUID | 재도전 구분 |
| `entryMode` | `fresh`, `checkpoint_retry`, `continue`, `editor_skip` | 정상 진행과 직접 진입 분리 |
| `buildVersion` | `0.1.2`, `0.1.3` | 버전 비교 |
| `schemaVersion` | `0.3.0`, `0.4.0` | 행 해석 방식 선택 |

### 4.2 일반 적 생명주기

기존 무인자 `EnemyKilled` 이벤트는 유지하고 상세 이벤트를 추가한다. 기존 Stage Controller의 처치 진행에는 영향을 주지 않는다.

| 이벤트 | 필수 필드 | 빈도 |
| --- | --- | --- |
| `enemy_spawned` | `enemyId`, `enemyArchetype`, `spawnOrdinal`, `position`, `meleeWeight`, `beastWeight` | 적 1개당 1회 |
| `enemy_defeated` | `enemyId`, `enemyArchetype`, `lifetimeSeconds`, `position` | 처치된 적 1개당 1회 |

`enemyArchetype`은 최소 `Melee`, `Beast`, `Thrower`를 지원한다.

### 4.3 일반 Beast 공격

현재 ID `DefenseBeastLeap`을 유지하고 사이트에는 `Beast 물기 돌진`으로 표시한다.

- 전조: `enemy_attack_started`
- 돌진 확정: `enemy_attack_committed`
- 피해, 방어, 패링, 퍼펙트 패링: `enemy_attack_contact`
- 회피 또는 빗나감: `enemy_attack_resolved`의 `Miss`
- 사망, 씬 종료, 취소: `Cancelled` 또는 `Interrupted`
- 도약 높이, 이동 연출, 연기, 눈 트레일, 발소리는 반복 로그로 남기지 않는다.

### 4.4 Twin Boss 부모 패턴

| 이벤트 | 필수 필드 |
| --- | --- |
| `boss_pattern_started` | `patternInstanceId`, `parentPatternId`, `humanHealthStart`, `beastHealthStart` |
| `boss_pattern_ended` | `patternInstanceId`, `parentPatternId`, `durationSeconds`, `patternOutcome`, `humanHealthEnd`, `beastHealthEnd` |

부모 패턴 ID:

- `Cooperation`: Beast 외곽 이동과 인간 수리검 난사
- `IaiCharge`: 인간 거합 충전과 Beast 방해 공격
- `AlternatingMelee`: 인간 돌진 베기와 Beast 물기 교대
- `Countering`: 인간 반격 베기

`Idle`, `Finished`, `Evading`은 직접 공격 통계에서 제외한다. 종료 결과는 `Completed`, `InterruptedByPlayerHit`, `CancelledOnBossDeath`, `CancelledOnPlayerDeath`, `CancelledOnStageExit`로 제한한다.

### 4.5 Twin Boss 개별 공격

| 로그 ID | 사이트 한글 표기 | 부모 패턴 | 단위 |
| --- | --- | --- | --- |
| `TwinBossRanged` | 쌍둥이 인간 수리검 | `Cooperation` | 투사체 1개 |
| `TwinHumanSlash` | 쌍둥이 인간 돌진 베기 | `AlternatingMelee` | 베기 1회 |
| `TwinHumanCounterSlash` | 쌍둥이 인간 반격 베기 | `Countering` | 반격 1회 |
| `TwinHumanIai` | 쌍둥이 인간 거합 | `IaiCharge` | 거합 방출 1회 |
| `TwinBeastBite` | 쌍둥이 짐승 잠수 물기 | `IaiCharge`, `AlternatingMelee` | 물기 1회 |

공통 필드는 `attackId`, `patternId`, `patternInstanceId`, `parentPatternId`, `attackerActor`, `origin`, `target`, `contactPosition`, `outcome`, `resolution`, `appliedDamage`, `reactionSeconds`, `inputToContactSeconds`다. 수리검은 발사체마다 AttackId 하나를 사용하고, 반사 시 원래 공격 결과를 두 번 종료하지 않는다.

### 4.6 Twin Boss 피격과 처치

| 이벤트 | 필수 필드 |
| --- | --- |
| `boss_damage_received` | `bossActor`, `playerAttackPattern`, `appliedDamage`, `healthAfter`, `parentPatternId`, `position` |
| `boss_actor_defeated` | `bossActor`, `timeSinceStageStart`, `position` |
| `boss_pair_defeated` | `humanDefeatTime`, `beastDefeatTime`, `stageClearTime` |

보스 방어 결과를 현재 계약에서 확실히 알 수 있을 때만 `boss_defense_resolved`에 `Blocked` 또는 `Countered`를 기록한다. 알 수 없는 상태를 추정해 만들지 않는다.

### 4.7 구간 설정 스냅샷

구간 시작에 `stage_config`를 한 번 기록한다.

- `requiredKills`, `startBossImmediately`
- 근접/Beast 가중치 시작값과 종료값
- 가중치 보간 시작/종료 스폰 수
- 투척/근접 시작 시간과 분당 스폰 수
- 일반 구간 소리 인지 거리 사용 여부와 거리
- 전장 중심과 분석 반경

오디오 클립 이름, 볼륨, 시각 효과 파라미터는 넣지 않는다.

## 5. Sessions 집계

### 5.1 2-1

- 총 스폰과 처치
- `Melee`, `Beast`, `Thrower`별 스폰과 처치
- Beast 실제 출현 비율과 설정상 기대 비율
- Beast 공격 시도, 적중, 피해, 회피, 방어, 패링, 퍼펙트 패링
- 사망, 구간 완료, 활성 시간

### 5.2 2-2

- 부모 패턴별 시작, 완료, 중단 횟수와 평균 지속 시간
- 다섯 개 개별 공격별 시도와 결과
- Human과 Beast가 받은 피해 합계
- Human과 Beast의 처치 시각 및 처치 순서
- 2-2 진입부터 전체 처치까지 걸린 시간

성공률은 세션별 비율의 평균 대신 전체 분자 합계 ÷ 전체 분모 합계로 계산한다. `Cancelled`, `Interrupted`는 별도 표시한다. 0.1.2에 없는 지표는 `0` 대신 `수집 안 됨`으로 표시한다.

## 6. 전송량 원칙

- 플레이어 이동 위치와 15초 요약 주기는 유지한다.
- 일반 적은 스폰 1행, 처치 시 종료 1행만 추가한다.
- Twin Boss 부모 패턴은 시작 1행과 종료 1행만 추가한다.
- 보스 피해는 실제 체력이 줄어든 타격당 1행만 추가한다.
- 구간 설정은 시도당 1행이다.
- 프레임, 애니메이션, 발자국, 사운드, NavMesh 이동은 보내지 않는다.

2-1에서 50마리를 처치해도 적 생명주기 추가량은 약 100행이다. 기존 배치 업로드와 ACK 후 즉시 삭제 정책은 유지한다.

## 7. 구현 순서

### S0. 식별자 고정 — 완료

대상: `ProjectSettings.asset`, `TelemetryJson.cs`, `CombatTelemetryRecorder.cs`

1. 게임 버전 `0.1.3`, 스키마 `0.4.0`, 설정 ID `combat-analysis-0.1.3`, source ID `combat.telemetry`를 적용한다.
2. 이 문서의 이벤트, 패턴, 결과 ID를 고정한다.

완료 조건: 새 JSON 행에서 게임, 스키마, 설정 버전을 구분할 수 있다.

### S1. 2막 구간과 run 연결 — 완료

1. `RainyStageController`가 현재 로그 구간을 공개한다.
2. Recorder 시작 시 현재 구간을 직접 읽고 이후 전환 신호를 구독한다.
3. 게임 시작부터 타이틀 복귀 또는 클리어까지 runId를 유지한다.
4. `entryMode`를 기록한다.

완료 조건: 새 2-1, 2-2 재도전, 2-1→2-2 전환이 `unassigned` 없이 기록된다.

### S2. 일반 적 종류와 생명주기 — 완료

1. `DefenseEnemySpawner`에 기존 계약을 보존한 상세 스폰/처치 이벤트를 추가한다.
2. `MeleeUnit.IsBeast`와 Thrower 경로로 종류를 정한다.
3. 선택 당시 가중치, 스폰 순번, 고유 적 ID를 전달한다.
4. Recorder에 종류별 집계를 추가한다.

완료 조건: 스폰 총계가 종류별 합계와 같고 처치 목표 동작은 유지된다.

### S3. Beast 공격 생명주기 — 완료

1. `DefenseBeastLeapAttack`과 공통 공격 계약의 AttackId 전달을 확인한다.
2. 적중, 방어, 패링, 퍼펙트 패링, 회피, 빗나감 중 결과 하나만 생성되게 한다.
3. 공격 동작, 피해량, 이동 결과는 바꾸지 않는다.

### S4. Twin Boss 개별 공격 — 완료

대상: `HumanBossAttack`, `TwinBossProjectile`, Beast 보스 공격, 거합 공격, 공통 텔레메트리 컨텍스트.

1. 다섯 공격에 AttackId를 발급한다.
2. 발사체마다 고유 ID를 쓴다.
3. 전조, 확정, 접촉, 수명 만료/장애물/취소를 구분한다.
4. 부모 패턴 ID와 인스턴스 ID를 전달한다.
5. 전투 로직 자체는 리팩터링하지 않는다.

### S5. 부모 패턴과 보스 피격 — 완료

1. 공격 가능한 부모 패턴에 인스턴스 ID를 발급한다.
2. 시작/종료, 종료 사유, 시작/종료 체력을 기록한다.
3. Human/Beast의 실제 피격과 개체별 처치를 기록한다.
4. 쌍둥이 전체 처치를 기록한다.
5. 플레이어 사망이나 씬 종료 시 열린 패턴과 공격을 취소로 닫는다.

### S6. Google Sheets와 CSV — 완료

대상: `tools/combat_telemetry/google_apps_script/Code.gs`, `Export-Telemetry.cjs`, `README.md`.

1. `2-1`, `2-2`, `0.4.0`, 새 이벤트와 열을 허용한다.
