# 멀티킬 처치 표시 구현 계획

- 작성일: 2026-10-24
- 상태: 코드·HUD 프리팹·온보딩 이외 방어 씬 연결 구현 완료. Unity Editor 미설치로 컴파일·Play 검증 미확인.
- 목적: 일반 스테이지에서 공격 한 번으로 많은 적을 처치한 성과를 처치 목표 아래의 `+N`으로 즉시 전달한다.
- 예상 규모: 보통 10~20명, 큰 성공은 30명 이상.
- 보상음: 사용자 선택 대기. 이번 구현 범위는 시각 표시이며 사운드 자산·재생 정책은 추후 결정한다.

## 1. 적용 범위와 집계 규칙

- 정식 일반 웨이브 구간에 적용한다. 온보딩과 보스전에서는 새 멀티킬을 만들지 않는다.
- 일반 공격 한 번, 일섬 한 번, 거합 한 번을 각각 독립적인 공격 실행으로 집계한다.
- 일반 공격의 연속 입력은 각각 별개다. 한 번의 일섬에서 발생한 검기·돌진 피해와 한 번의 거합에서 발생한 여러 타격은 같은 실행에 묶는다.
- 같은 실행에서 다섯 번째 적이 실제 사망하면 표시를 시작한다. 이후 같은 실행의 처치가 늘면 해당 숫자만 갱신한다.
- 공격 종류나 짧은 시간 간격만으로 묶지 않는다. 공격 실행 ID와 처치 출처를 사용한다.
- 누적 처치 목표에 실제로 포함되는 적을 대상으로 하며, 같은 적의 같은 생존 주기는 한 번만 센다. 재사용된 적은 새 생존 주기로 구별한다.
- 피해 없는 강제 제거·디스폰과 출처가 없는 사망은 멀티킬에서 제외한다. 반사 수리검 등 요청된 세 공격 이외의 처치는 합산하지 않는다.
- 처치 목표를 초과한 실제 처치도 같은 공격의 결과라면 N에 포함한다. 기존 스테이지 종료 시점과 처치 목표 계산은 변경하지 않는다.

## 2. 표시와 연속 발생 처리

- 처치 목표 바로 아래에 최신 결과 한 줄과 직전 결과 한 줄을 위한 고정 영역을 둔다. 목표 텍스트의 위치는 움직이지 않는다.
- 새 공격이 5명 기준을 충족하면 최신 결과 자리를 차지한다. 이전 결과는 아래로 이동하며 원래 등급 크기의 75%, 불투명도 50%로 축소한다.
- 서로 다른 공격의 숫자는 합치지 않는다. 예: `+18`과 `+12`를 `+30`으로 바꾸지 않는다.
- 아래 줄의 공격이 늦게 추가 처치를 만들면 아래 줄 숫자만 갱신한다. 최신 자리로 다시 올리거나 큰 등장 연출을 반복하지 않는다.
- 이미 퇴장한 공격은 늦은 처치로 다시 등장하지 않는다. 집계는 실행 종료까지 유지해 중복 알림을 방지한다.
- 직전 결과는 기본 0.4초에 걸쳐 퇴장한다. 가능하면 첫 등장부터 최소 0.8초의 가독 시간을 보장한다.
- 세 번째 멀티킬이 들어오면 가장 오래된 결과를 즉시 비운다. 이 경우 최대 두 줄 유지가 최소 가독 시간보다 우선한다. 표시 대기열은 만들지 않는다.
- 4명 이하의 별도 공격은 현재 표시나 타이머에 영향을 주지 않는다.

## 3. 애니메이션과 초기 설정값

| 항목 | 초기값 |
| --- | --- |
| 등장 | 0.15초, 즉시 가시화 후 정착 크기의 120%에서 정착 크기로 수렴 |
| 최신 결과 유지 | 마지막 처치 갱신부터 1.5초 |
| 30명 이상 유지 | 마지막 처치 갱신부터 2초 |
| 자연 퇴장 | 0.35초, 아래로 8px 이동하며 투명도 감소 |
| 숫자 갱신 묶음 | 최대 0.08초 간격으로 최신 누적값 반영 |
| 직전 결과 축소 | 크기 75%, 불투명도 50% |
| 최소 가독 시간 | 0.8초, 세 번째 결과 발생 시 예외 |
| 더하기 기호 | 숫자 크기의 70% |

- 다섯 번째 처치에서는 즉시 표시한다. 같은 프레임의 여러 처치는 해당 프레임의 최신 합계를 사용한다.
- 큰 확대는 첫 등장과 10·20·30명 등급 상승 때만 실행한다. 한 번에 여러 등급을 넘으면 도달한 최종 등급 연출 한 번만 실행한다.
- 숫자 갱신만 발생한 경우 전체 등장 연출을 재시작하지 않는다.
- 자연 퇴장 중 같은 공격의 추가 처치가 발생하고 아직 슬롯이 남아 있으면 퇴장을 취소하고 유지 시간을 갱신한다.
- 유지 시간은 실제 시간을 사용하고, 일시정지 메뉴가 열린 동안은 모든 표시 타이머와 애니메이션을 멈춘다.
- 1.5초가 넘는 처치 공백 후에도 피해가 이어질 수 있는 공격이 있는지 확인한다. 그런 경로는 공격의 피해 발생 가능 기간을 표시 수명에 반영해 최종 숫자가 생략되지 않게 한다.

| 처치 수 | 기본 크기 대비 | 색상 방향 | 장식 |
| --- | --- | --- | --- |
| 5~9 | 1.0배 | 밝은 상아색 | 짧은 확대 |
| 10~19 | 1.15배 | 옅은 금색 | 확대 강도 증가 |
| 20~29 | 1.3배 | 선명한 금색 | 확대 강도 증가 |
| 30 이상 | 1.5배 | 밝은 금색·상아색 | 짧은 붓질 또는 베기 흔적 한 번 |

- 기본 크기는 32를 시작값으로 삼아 기존 목표 텍스트와 실제 해상도에서 조정한다. 30명 이후에도 크기는 1.5배로 제한한다.
- 동일한 글꼴과 어두운 외곽선 또는 그림자를 사용한다. 숫자 중심을 기준으로 확대하며 두 자리·세 자리 전환 시 기준 위치를 유지한다.
- 색상·크기·시간·간격·임계값은 Inspector에서 조정한다. UI 계층과 두 TMP 슬롯은 HUD 프리팹에 저장한다.

## 5. 구현 순서

1. **공격 출처와 사망 경로 확인·보완 — 구현 완료**
   - 일반 공격·일섬·거합의 시작, 피해, 마지막 타격, 종료 경로를 연결해 조사한다.
   - 기존 실행 ID를 우선 재사용한다. 서로 다른 ID 체계가 섞인 경우에만 명시적인 연결 정보를 추가한다.
   - 적 사망 시 공격 실행과 종류가 보존되도록 한다. 현재 플레이어 행동을 사망 시점에 조회하는 방식은 사용하지 않는다.
   - 기존 피해량·타격 중복 방지·게이지 보상·텔레메트리 의미가 달라지지 않는지 확인한다.
   - 결과: `LethalDamageContext`가 치명 피해를 보존하며, 일반 공격은 기존 행동 ID, 일섬·거합은 별도 음수 실행 ID를 사용한다.
2. **멀티킬 집계 컴포넌트 구현 — 구현 완료**
   - 실행별 처치 수와 적 생존 주기 중복 방지 상태를 관리한다.
   - 5명 도달, 수치 갱신, 실행 종료를 표시 컴포넌트에 전달한다.
   - 공격 애니메이션 종료 뒤에도 남아 있는 검기·지연 타격의 수명까지 고려해 기록을 정리한다.
   - 일반 웨이브 종료 후에는 새 집계를 열지 않고 이미 열린 실행의 유효한 후속 처치를 마무리한다. 씬 이동·재시작 때 기록을 비운다.
   - 결과: 정식 처치 대상과 네 공격 패턴을 실행 ID로 집계하고, 퇴장 후 재등장 없이 비행 검기 종료까지 상태를 유지한다.
3. **HUD 프리팹과 표시 컴포넌트 구현 — 구현 완료**
   - 최신·직전 결과 슬롯, 등급, 숫자 갱신, 교체·퇴장 상태를 구현한다.
   - 보스 등장으로 기존 목표가 숨겨져도 이미 표시된 결과는 수명이 끝날 때까지 유지한다.
   - 보스 경고 UI와 위치·정렬 순서를 맞추며 스테이지 전환을 멀티킬 때문에 지연하지 않는다.
   - 결과: 0.08초 숫자 갱신 묶음, 일시정지 일시중지, 독립 표시 수명, 최대 두 줄 슬롯을 코드에 연결했다.
4. **시각 튜닝과 씬 연결 — 씬 연결 완료, Play 튜닝 미확인**
   - 정식 일반 웨이브 구간에 연결한다. 5·10·20·30명과 연속 멀티킬을 보며 강도를 조정한다.
   - 30명 이상 장식은 기존 프로젝트 자산을 먼저 확인한 뒤 결정한다. 보상음은 미정으로 둔다.
   - 결과: BambooStage1, BambooDefense, RainyStage_JH, RainyTwinBoss, TestStage, (Legacy) RainyStage의 BambooDefenseHud prefab instance에 HUD 표시 컴포넌트를 연결했다. 온보딩은 프리팹 인스턴스에서 표시 컴포넌트를 비활성화한다. 공통 크기·색상·시간은 BambooDefenseHud.prefab 루트의 DefenseMultiKillHud Inspector에서 한 번 조절하며, 씬별로는 Director 참조만 저장한다. TMP 슬롯은 Bold를 끈 일반 글자 두께(400)를 사용하고 전용 SDF 머티리얼의 검은 Underlay로 바깥 테두리를 그린다. 머티리얼의 Underlay Color·Dilate에서 테두리 색·두께를 조절한다. 화면에서의 위치·가독성 조정은 Unity Editor 미설치로 미확인이다.
5. **검증 및 명세 반영 — 명세 반영 완료, 실행 검증 미확인**
   - `docs/features/멀티킬_처치_표시.md`를 작성하고 기능 목록에 등록했다. 테스트 코드는 추가하지 않았다.
   - Unity CLI로 빌드를 시도했지만 프로젝트 버전 6000.3.22f1 Editor가 설치되어 있지 않아 컴파일 단계에 도달하지 못했다. 자동 설치는 수행하지 않았다.
   - Unity Editor를 실행할 수 없어 아래 수동 Play 항목은 전부 미확인이다.

## 6. 수동 검증 및 완료 기준

- [ ] 세 공격 각각에서 4명은 미표시, 5명은 표시, 10·20·30명 경계에서 강조가 한 번만 상승한다. (미확인)
- [ ] 한 번의 일섬의 돌진·검기와 거합의 여러 타격이 한 결과로 합쳐지고, 별도 일반 공격과 섞이지 않는다. (미확인)
- [ ] 일섬 뒤 일반 공격처럼 실행이 겹쳐도 늦은 처치는 원래 결과에 반영된다. (미확인)
- [ ] `+35` 직후 `+5`, 짧은 간격의 세 멀티킬, 자연 퇴장 중 추가 처치를 확인한다. (미확인)
- [ ] 사망 중복 알림·적 재사용·강제 제거가 숫자를 잘못 올리지 않는다. (미확인)
- [ ] 감속 중 표시 시간이 늘어나지 않고, 메뉴 일시정지 동안 표시가 사라지지 않는다. (미확인)
- [ ] 목표 달성 마지막 멀티킬이 보스 등장 중 유지되며 경고 텍스트와 겹치지 않는다. (미확인)
- [ ] 재시작·씬 이동 후 이전 숫자가 남거나 재등장하지 않는다. (미확인)
- [ ] 16:9 및 지원하는 좁은 화면에서 목표·두 줄 표시·다른 HUD가 겹치지 않는다. (미확인)
- [ ] 처치 목표의 총합, 스킬 게이지 보상, 기존 전투 로그에 회귀가 없는지 확인한다. (미확인)

## 7. 결정이 남은 부분

- 보상음의 자산·발생 등급·중복 재생 정책: 사용자 추후 결정.
- 색상 정확한 값, 기본 크기와 여백: Inspector 초기값을 정했으며 실제 게임 화면 튜닝은 미확인이다.
- 30명 이상 장식: HUD에 적합한 기존 자산을 확인하지 못해 별도 붓질 요소는 넣지 않았다. 현재는 밝은 색상과 1.5배 크기만 적용했다.
- 이번 계획은 멀티킬 표시에 한정한다. 앞서 언급한 온보딩 수치 표현 수정은 별도 작업으로 관리한다.
