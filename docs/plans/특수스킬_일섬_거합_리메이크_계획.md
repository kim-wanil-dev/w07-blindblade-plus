# 특수 스킬·일섬게이지·거합게이지 리메이크 계획

- 작성일: 2026-10-23
- 상태: M1·M2 완료. M3에서 거합 HUD 컴포넌트를 프리팹 루트에 두고 `UltimateGaugeCanvas` UI 계층을 자식으로 직렬화했다. 런타임 UI 생성은 제거했다. HUD 통합 화면과 검 구슬 검증은 미완료이며 온보딩 UI 개편은 제외한다.
- 실행 모델: 사용자 지시에 따라 Orca 오케스트레이션을 취소하고 남은 구현은 luna-max 단독으로 진행한다.
- 현재 브랜치: `.git/HEAD` 기준 `feature/skill`. AGENTS.md에 따라 이 브랜치에서는 Git CLI를 사용하지 않으며 커밋 메시지만 제안한다.

## 1. 확정 요구사항

| 항목 | 일섬 | 거합 |
| --- | --- | --- |
| 자원 | 기존 3칸 거합게이지를 일섬게이지로 변경 | 독립된 새 게이지 |
| 범위 | float 0~3칸 | 0~100% |
| 발동 입력 | Shift 누름 | Q 누름 |
| 자원 조건 | 1칸 이상 | 100% |
| 사용 비용 | 1칸 | 100% 소모를 기본안으로 제안 |
| 극한회피 성공 | +0.5칸 | +15%p |
| 패링 성공 | +1칸 | 최대 게이지의 정확히 1/3 |
| 몬스터 처치 | +0.1칸 | +1%p |
| 보스 몬스터에게 일반 공격 유효 적중 | 증가 없음 | +3%p |
| 기존 집중 상태 필요 | 제거 | 제거 |
| 기존 좌클릭 홀드 필요 | 해당 없음 | 제거 |

- 패링·극한회피·처치는 두 게이지를 각각 적립한다. 보스 일반 공격 적중은 거합게이지만 적립한다. 일반 막기와 일반 회피는 적립하지 않는다.
- 패링 보상은 반올림한 33%가 아닌 정확한 1/3이며, 0에서 패링 3회면 100%가 되어야 한다.
- 온보딩 개편은 사용자 요청으로 이번 구현 범위에서 제외한다. 온보딩 전용 코드·씬·설명·목표·입력 인계·명세는 수정하지 않는다. 공용 API 변경 시 기존 호출이 컴파일되도록 호환성을 고려하되 온보딩 재설계는 후속 작업으로 둔다.
- 각 게이지는 상한에서 멈추며 초과분은 저장하지 않는다. 한 스킬의 소비는 다른 게이지에 영향을 주지 않는다.
- 일섬 시전에는 0.2초 집중 연출을 넣는다. 시간 기준은 일시정지를 제외한 실시간을 기본안으로 한다.
- 일섬의 각 칸은 부분 충전 시 아래에서 위로 채우고, 완전히 찬 칸만 기존 실 구체가 일렁이는 표현을 사용한다.
- 새 거합게이지는 화면 중하단 원형이며 아래에서 위로 차오른다. 가운데 백분율, 아래 `Q:거합`을 표시한다.

## 2. 사용자 답변으로 확정한 연출

2026-10-23 사용자 답변을 다음과 같이 반영한다.

1. 패링·극한회피 성공 시 기존 자동 집중을 유지한다. 스킬 발동에 집중이 필요하다는 조건만 제거한다. 현재 Player 프리팹의 패링 준비 5초·극한회피 준비 1초를 기준으로 유지한다.
2. 거합은 Q 한 번으로 자동 차징한다. 현재 `Player.prefab._ultimateChargeDuration`은 1.5초이므로 **0.75초**로 줄인다. Q를 놓아도 차징을 계속하고, 완료되면 거합 시전 연출로 넘어간다.
3. 일섬은 **Shift와 동시에 시작하며 첫 0.2초간 집중**한다. 시전 앞에 0.2초 대기를 추가하지 않는다. 돌진·검기의 상대적 발사 시점은 기존 일섬 순서를 사용한다.

- 패링 판정·패링 순간 무적·성공 효과음·인지 파동과 성공 시 집중은 유지한다. 집중 중에도 좌클릭은 일반 공격이고, 일섬/거합은 각각 Shift/Q로 요청한다.
- 자동 차징 0.75초는 일시정지를 제외한 실시간이다. 차징 중 감속 목표에 도달하는 별도 `_chargeSlowDuration`은 현재 0.7초이며, 차징 총시간을 절반으로 줄이는 것과 구별하여 기본적으로 유지한다. 보스 자동 반격이 같은 duration 프로퍼티를 읽는지 구현 시 확인하여 반격 시간까지 함께 줄어들지 않도록 한다.
- 쌍둥이 거합 회피의 기존 별도 불릿 타임 예외는 유지한다. 일반 극한회피 보상을 주는 사건으로 자동 변경하지 않는다.

## 3. 미지정 세부사항에 대한 기본안

- 두 게이지는 새 플레이어/재도전에서 0으로 시작한다. 같은 플레이어 인스턴스 내 일반전→보스전 전환은 유지하고, 영구 저장·이어하기 복원 기능은 새로 추가하지 않는다.
- 수동 거합은 발동 확정 시 100%를 소비한다. 일섬도 발동 확정 시에만 1칸을 소비한다. 자원 부족·입력 불가로 거부된 요청은 소비하지 않는다.
- 거합 자동 차징 동안 비용은 예약하고 실제 발동 시 확정한다. 차징 중 사망·씬 종료 등으로 취소되면 예약만 해제한다. 일섬은 수락과 실제 시작을 같은 흐름으로 처리해 1칸을 소비한다. 실제 돌진·공격이 시작된 뒤 빗나가거나 벽에 막혀도 환불하지 않는다.
- 스킬로 처치한 적도 적립한다. 비용 확정 후 처치 보상을 처리하므로 거합으로 8명을 처치하면 거합 8%·일섬 0.8칸이 다시 쌓일 수 있다.
- 몬스터 처치는 플레이어의 유효한 처치로 제한한다. 일반 적·Beast·보스를 포함하고, 투사체 제거·풀 반환·웨이브 정리·씬 종료는 제외한다. 공유 체력 보스 한 묶음은 한 번 적립하는 안으로 둔다.
- 보스 일반 공격 적중은 플레이어의 일반 공격으로 실제 피해가 수락된 경우에만 +3%p를 준다. 빗나감·무적/방어로 막힌 접촉·일섬 몸 판정/검기·거합·자동 반격은 제외한다. 일섬이 내부적으로 일반 공격 동작을 사용하므로 공격 종류뿐 아니라 스킬 출처도 구분한다.
- 동일 타격의 복수 콜라이더/콜백과 공유 체력 보스 양쪽 접촉은 중복 적립하지 않는다. 일반 공격 1타·2타처럼 별도 유효 타격은 각각 적립한다. 일반 공격으로 보스를 처치하면 적중 +3%p와 처치 +1%p를 함께 적립하고, 처치에 따른 일섬 +0.1칸도 적용하는 것을 기본안으로 한다.
- HUD의 3칸과 검에 매달린 3구슬은 모두 일섬게이지를 읽는다. 월드 구슬은 완충 칸에 기존 실 구체를 표시한다. 부분 충전의 `fillAmount` 요구는 우선 HUD Image에 적용한다. 3D 구슬까지 수면처럼 채우는 셰이더 확장은 별도 결정 사항이다.
- 패드 기본안은 일반 공격 RB·막기 LB·회피 A를 유지하고 일섬 RT·거합 Y를 추가한다. 키보드는 Shift/Q를 사용하며 Inspector/입력 설정에서 구분한다. 패드 배치는 사용자 미지정 제안이다.
- 보스 거합 받아치기 `BeginCounterStrike`는 기존 자동 반격으로 유지한다. 수동 Q 거합 비용과 사용 횟수 집계에 합치지 않는다.
- 일반 공격 중 스킬 캔슬을 새로 허용하지 않는다. 기존 허용 상태를 확인하여 입력 가능 조건표를 만들고, 거합의 기존 강제 행동 종료가 있는 부분은 별도 기록한다. 동시에 여러 스킬을 수락하거나 일반 공격 예약이 스킬로 바뀌지 않도록 한다.

## 5. 구현 순서와 단계별 완료 기준

### S1. 자원 소유자와 보상 계약

- 단일 자원 관리 컴포넌트(가칭 `PlayerSkillGauge`)에 일섬 float 0~3과 거합 0~100을 저장한다. PlayerEmpower는 시전/시간 연출을 담당하며 자원을 중복 저장하지 않는다.
- Inspector에서 최대값·스킬 비용·성공별 증가량을 한 곳에서 편집한다. 현재 요구값을 프리팹에 직접 직렬화한다.
- 공개 상태는 읽기 전용 프로퍼티와 변경 이벤트로 제공한다. 새 HUD·구슬은 같은 값을 읽고, 온보딩의 기존 API 호출은 컴파일 호환성을 고려한다.
- 누적 오차를 처리한다. 0.1×10이 정확히 사용 가능한 1칸으로 인정되도록 작은 경계 오차를 정규화하고, 임의의 0.99를 1로 판정하지 않는다. 예약 비용까지 고려한 사용 가능 잔량을 검사한다.
- 패링은 실제 성공 사건, 극한회피는 기존 DodgeId당 한 번 확정 보상에 연결한다. 기존 성공 판정과 보상을 양쪽에서 중복 지급하지 않는다.
- 거합 패링 보상은 최대값/3으로 계산하고 경계 오차를 정규화한다. 33 또는 33.3으로 잘라 저장하지 않으며 패링 3회로 정확히 완충된다. 극한회피·처치·일반 공격 적중이 섞여도 합산 후 상한을 적용한다.
- 보스 일반 공격 보상은 보스 식별과 피해가 수락된 실제 공격 출처를 확인한다. 타격 ID·대상 스폰 세대·공유 체력 키를 이용해 동일 타격당 +3%p만 지급하고 별도 콤보 타격은 구분한다. 적중과 처치 보상은 서로 다른 보상이므로 막타에서 둘 다 적용한다.
- 처치는 실제 사망 전환에서 세대/공유 체력 묶음을 기준으로 한 번만 적립한다. 풀 재사용으로 같은 GameObject가 다시 죽는 경우는 새 처치로 인정한다. 사망 처리 후 비활성화되므로 콜백에서 IsAlive로 보상을 다시 거부하지 않는다.
- 완료 기준: 보상표에 따라 두 자원이 정확히 증가하고 최대값을 넘지 않으며, 보스 일반 공격은 거합에만 적립되고 한쪽 소비가 다른 쪽을 바꾸지 않는다.

### S2. 입력과 시전 흐름

- Shift와 Q는 누른 프레임에 한 번 요청하며 길게 눌러도 반복 소비하지 않는다. InputManager의 초기화·Enable/Disable·Dispose·일시정지 입력 정리를 함께 연결한다.
- 좌클릭의 `BeginCharge`, 집중 중 자동 일섬, 홀드 해제 시 일반 공격 전환을 정식 전투의 수동 스킬 경로에서 제거한다. 온보딩 전용 홀드 인계는 이번 개편 대상에서 제외하고 기존 호출 메서드를 무작정 삭제하지 않는다.
- 일섬: 입력 허용/잔량 검사 → 실제 시전 수락·중복 실행 잠금·1칸 소비 → 즉시 기존 일섬 시작과 0.2초 집중 → 돌진·검기 순서 진행. 일반 공격 버퍼에 들어가 한참 뒤 발동하는 흐름을 만들지 않는다.
- 거합: 입력 허용/100% 검사 → 비용 예약과 0.75초 자동 차징 → 실제 시전 확정과 100% 소비 → 기존 거합 연출/판정. Q 해제로 취소되지 않는다.
- 단일 시전 ID로 입력·예약·취소·실제 발동을 연결한다. 실패한 입력은 일반 공격으로 자동 변환하지 않는다. 동시 Shift/Q의 기본 우선순위는 Q이며 한 프레임에 하나만 수락한다.
- 0.2초는 전용 시간 요청 수명으로 관리한다. 일섬을 쓰기 전의 성공 집중은 기존 일섬처럼 종료하고 일섬 연출로 넘긴다. 기존 패링 준비 타이머와 런처 감속 때문에 일섬 집중만 0.2초를 초과하지 않도록 한다. 일섬 이후 새로 성공한 패링/극한회피의 집중은 별도 정상 보상이다. FOV·돌진 이동과 집중 감속의 수명은 별개로 관리한다.
- 사망·씬 종료·컴포넌트 Disable에서 예약/시간 요청을 정리한다. 일시정지는 차징/집중 진행 시간을 동결하고 해제 후 남은 시간부터 계속한다. 일시정지 메뉴 입력이 추가 시전으로 넘어가지 않도록 입력 상태를 정리한다.
- 완료 기준: 집중 없이 Shift/Q로 사용 가능하고, 좌클릭이 스킬을 쓰지 않으며, 거부·연타·동시 입력으로 자원이 중복 소모되지 않는다.

### S3. HUD와 검 구슬

- 일섬 슬롯 i(0~2)의 충전량은 `Clamp01(일섬 잔량 - i)`다. 예: 1.6칸이면 첫째 완충 구슬, 둘째 60% 아래→위 채움, 셋째 빈 슬롯이다.
- 빈 배경 Image와 부분 Fill Image를 분리한다. Fill은 `Image.Type.Filled`, `FillMethod.Vertical`, `Origin.Bottom`을 사용한다. 완충 칸은 기존 실 구체가 표시된다.
- 완충 판정은 실제 정규화된 자원 값으로 계산한다. 화면 보간이 실제 사용 가능 시점을 바꾸지 않는다.
- 거합 HUD는 `BambooDefenseHud.prefab` 루트의 `PlayerUltimateHint`가 제어하며, `UltimateGaugeCanvas/UltimateGauge/GaugeCircle` 아래에 배경·세로 Fill·가운데 TMP 퍼센트·아래 `Q:거합`을 프리팹 자식으로 직렬화한다. 런타임 UI 생성은 하지 않으며, 원형 Sprite 안을 세로로 채우고 Radial360은 쓰지 않는다.
- 0%부터 표시하며, 정수 퍼센트는 내림을 기본으로 하고 실제 완충 때만 100%를 보인다. 99.9%가 반올림되어 100%로 보이는 문제를 막는다.
- 100% 준비 표시는 텍스트/색으로 구별하고 입력 가능 여부와 일치시킨다. 새 레이아웃의 정확한 크기·오프셋은 기존 HP/스태미너 및 안내 겹침을 확인하여 결정한다.
- 정식 전투에서 `PlayerUltimateHint`를 Player 프리팹에서 HUD 프리팹으로 옮기고, 게이지 UI 오브젝트를 `BambooDefenseHud.prefab`에 저장한다. 런타임 컴포넌트는 직렬화된 CanvasGroup·Image·TMP 참조만 갱신한다. 기존 Canvas 정렬과 Q/Y 안내는 유지한다. 온보딩 화면 개편은 보류하고 기존 안내 숨김 연결만 새 컴포넌트 위치로 갱신한다.
- 검 구슬은 일섬게이지의 완충 칸에 연결하며 물리·끈·껍질 표현은 이번 변경에 맞춰 필요한 참조만 조정한다.
- 완료 기준: 0/0.1/0.5/0.9/1/1.6/2.9/3칸과 거합 0/3/15/33⅓/66⅔/99/100%가 올바르게 표시된다. 내림 표시 기준 패링 1·2·3회는 33%·66%·100%다.

### S4. 사운드·기록 연동과 온보딩 범위 제외

- 온보딩의 새 입력 학습·게이지 목표·집중 고정·실 구슬 강조·설명 버튼 인계·실패 복구·문구 개편은 이번에 수행하지 않는다. 공용 스킬/HUD 변경이 온보딩에 미치는 영향은 기록하되 이번 완료 기준에 온보딩 리메이크를 포함하지 않는다.
- 정식 전투의 스크립트 기본 문자열과 씬/프리팹에 저장된 스킬 안내만 갱신한다.
- 거합 완충음은 거합게이지가 100%가 되는 전이에 연결하여 처치나 보스 일반 공격 적중으로 가득 차도 재생된다. 같은 완충 상태에서 패링/회피할 때 반복 재생 여부는 기존 소리를 확인한 뒤 일관되게 정리한다.
- 실제 일섬/수동 거합 집계는 기존 `SwordWave`/`Empower`, `manual`을 유지한다. 반격 `counter`는 계속 구분한다. 키 입력만으로 발동 횟수를 올리지 않는다.
- 입력 종류 추가 시 정식 전투의 입력 기록·로그 소비자의 허용 값/표시를 확인한다. 새 게이지 획득/소비 로그가 필요하면 원인·전후 값·시전 ID를 별도 필드로 추가하고 기존 집계 의미를 바꾸지 않는다. Sites/Apps Script 배포는 이번 계획의 자동 수행 범위에 포함하지 않는다.
- 완료 기준: 정식 전투에서 완충음과 실제 스킬 발동 기록이 새 규칙에 맞고 온보딩 전용 파일은 변경하지 않는다.

### S5. 검증·기능명세 갱신

- 테스트 코드는 작성하지 않는다. 컴파일과 Unity Editor/Play 수동 시나리오로 확인한다. 런타임 확인용 조작이 실제 수집 시트에 전송되지 않는 환경을 사용한다.
- 수치: 처치 10회→일섬 1칸·거합 10%, 극한회피 2회→1칸·30%, 패링 3회→3칸·100%. 보스 일반 공격 1회→거합 3%·일섬 증가 없음, 별도 1타/2타 유효 적중→6%. 패링 2회+보스 일반 공격 11회→99⅔%로 사용 불가, 추가 적중→100%로 사용 가능.
- 보스 적중: 일반 몬스터 타격·일섬·거합·자동 반격·무적/방어·빗나감은 +3%p 제외, 공유 체력/다중 콜라이더 중복 제외, 일반 공격 막타는 적중 3%p+처치 1%p 합산.
- 소비: 일섬 1.6→0.6, 거합100→0; 두 스킬의 자원 독립, 발동 후 같은 스킬의 처치 보상 정상 적립.
- 중복: 동일 성공의 다중 콜백, 한 회피에 여러 접촉, 한 적 다중 히트, 공유 체력 보스, 풀 재활성 후 새 사망, 단순 비활성화/씬 정리.
- 입력: 자원 부족, 일반 공격 중, 막기 중, 회피 중, 일섬 시전 중, 거합 자동 차징/공격 중, 사망/일시정지, Shift/Q 동시 누름, 길게 누름, 장치 전환. Q를 즉시 놓아도 거합은 0.75초 차징 뒤 한 번만 실행된다.
- 연출: Shift 즉시 일섬 시작·첫 0.2초 집중, Q 자동 차징 0.75초 실시간 측정, 일시정지 포함 시 정지, 종료/취소 후 시간 배율과 FOV 복구, 기존 성공 시 집중 유지, 보스 자동 반격.
- HUD: 여러 화면 비율, 부분 충전→완충→소비 전환, 100% 숫자와 사용 가능 판정 일치, 정식 전투 하단 안내 겹침, 검 구슬 동기화.
- 정상 플레이 경로: BambooStage1→RainyTwinBoss, 사망 재도전, 일반전→보스전 전환, 게임 클리어. 온보딩 개편 검증은 후속 작업이며 기존 API의 컴파일 참조와 공용 변경 영향을 확인한다.
- 관련 명세: `퍼펙트_패링_토큰.md`, `칼_구슬_토큰_표시.md`, `전투_HUD.md`, `패드_입력_안내.md`, `전투_판정_계약.md`, `전투_로컬로그_자동전송.md` 및 `FEATURE_SPEC.md`의 해당 항목. 실제 변경한 계약만 갱신하고 `온보딩.md`는 이번에 수정하지 않는다.
- 완료 보고: 변경 내용·Inspector 위치·최종 수치·수행한 검증과 미확인 항목·커밋 메시지 제안. 현재 브랜치에서는 Git 명령/커밋/푸시를 하지 않는다.

## 6. luna-max 실행 인계

### 마일스톤 진행 규칙 (2026-10-23 사용자 추가 지시)

- 한 마일스톤을 완료하면 변경 내용·검증 결과·남은 문제를 보고하고 사용자가 다음 진행을 지시할 때까지 멈춘다.
- M1 독립 자원 모델: 완료. luna-max 작성, 조정자 경계 오차 보완. Unity 임시 오브젝트에서 처치 10회=일섬 1칸/거합 10%, 패링 3회=3칸/100%, 거합 소비 후 일섬 유지, 패링 2회+보스 적중 11회=99.666664% 사용 불가/추가 적중=100%를 확인했다.
- M2 입력·전투·보상 통합: 완료. InputManager의 Shift/Q/RT/Y 경로, 좌클릭 일반 공격 분리, 일섬 0.2초 집중, 거합 0.75초 자동 차징과 실제 시전 시 소비를 연결했다. EnemyHealth의 수락된 실제 피해를 통해 보스 일반 공격 적중과 처치 보상을 지급하고 공유 체력·ActionId 중복을 제한한다.
- M2 검증: Unity 재컴파일 오류 0. Play 수동 평가에서 일섬 1.6→0.6 및 약 0.21초 집중, 거합 차징·일시정지 중 진행 정지·재개 후 1회 소비, 자원 부족 거부, 중복 Q 거부, 좌클릭 일반 공격 유지, 컴포넌트 비활성화와 PlayerHealth.Died 콜백의 시간 요청 해제·미소비 게이지 유지를 확인했다. 실제 키 이벤트는 Editor 포커스가 없어 확인하지 못했고, 차징 중 강제 피해는 별도 무적 판정에 막혀 실제 체력 사망 대신 Died 콜백을 직접 실행해 정리만 확인했다. 실제 키 입력과 치명타 통합은 미확인이다.
- M3 HUD·검 구슬: 3칸 부분 Fill·거합 원형/퍼센트/하단 문구를 구현했다. `BambooDefenseHud.prefab`에 거합 HUD Canvas와 자식 UI를 직렬화하고 런타임 생성 코드를 제거했다. 통합 화면 렌더링과 검 구슬 동기화 검증은 완료되지 않았다.
- M4 회귀 확인·기능명세 마감: 미완료. 각 단계가 완료될 때 실제 검증 결과로 문서를 갱신한다.
- 사용자 지시에 따라 오케스트레이션 실행은 취소했고 이후 luna-max만 사용한다. 검증용 Play mode와 임시 기록·스테이지 설정은 종료·복구했으며 원래 RainyTwinBoss 씬을 다시 열었다.

1. 1·2절은 사용자 확정 요구사항으로 적용한다. 3절 기본안에 후속 수정 요청이 있다면 반영한다.
   - 최신 범위: 온보딩 수정 제외, 거합 패링 보상은 정확히 1/3, 보스 일반 공격 유효 적중은 거합 +3%p.
2. 작업 당시 AGENTS.md·현재 소스·열린 씬의 미저장 변경과 해당 기능명세를 다시 확인한다. 이미 다른 작업이 진행된 구간과 충돌하면 해당 부분의 선택을 확인한다.
3. S1→S2→S3→S4→S5 순서로 구현한다. 기존 PlayerEmpower의 모든 IsReady 사용자를 자원 준비/성공 연출/시전 상태로 분류한 뒤 바꾼다.
4. UI 에셋은 연결된 Unity Editor와 unity-cli/ui-ugui 지침에 따라 변경한다. 관련 없는 dirty 씬까지 일괄 저장하지 않는다.
5. 기능 단계가 끝날 때 컴파일과 해당 시나리오를 확인하고 다음 단계로 진행한다. 단순 컴파일 성공을 플레이 검증 완료로 보고하지 않는다.

M2 제안 커밋 메시지: `feat: Shift·Q 입력과 전투 게이지 보상 연결`
